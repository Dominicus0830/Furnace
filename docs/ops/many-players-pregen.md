# 다인원 탐험 서버: 월드 경계 + 미리 생성

여러 사람이 동시에 새 땅을 걸어 다니는 서버(탐험·생존 서버 개장 첫날 등)는 청크 생성이 가장 큰 일이다. 생성은 새 땅을 처음 밟을 때만 드는 일이므로,
**걸어 다닐 땅을 경계로 정하고 사람이 들어오기 전에 미리 만들어 두면** 그 일이 사라진다. 같은 길을 미리 만든 땅에서 걸으면 서버 CPU 가 절반쯤
(60명 측정 278% → 136%)이고 발밑 청크가 늦게 오는 사람도 없어진다(`furnace/reviews/w60-explore/W60-explore.md` 3장).

## 1. 경계를 정한다

```
/worldborder center 0 0
/worldborder set 10000          # 한 변 10000 블록(±5000)
```

경계 밖으로는 걸어갈 수 없으므로 만들 땅이 정해진다. 플레이어는 경계 가장자리에서도 시야(서버 `view-distance`)만큼 바깥 청크를 받으므로,
가장자리까지 미리 만들고 싶으면 반경을 `경계 반 변 + 시야 × 16` 블록으로 준다(아래 2번의 반경 형태).

## 2. 미리 만든다 — `/furnace pregen`

| 명령 | 하는 일 |
|---|---|
| `/furnace pregen start border` | 그 차원의 월드 경계 안(경계에 걸치는 청크까지)을 만든다. 경계가 기본값(사실상 없음)이면 거절한다 |
| `/furnace pregen start <반경> [가운데 x z]` | 가운데(기본: 월드 경계 가운데) 둘레 정사각형 `[가운데 − 반경, 가운데 + 반경)` 블록에 걸치는 청크를 만든다 |
| `/furnace pregen status` (또는 `/furnace pregen`) | 진행률·속도·남은 시간 |
| `/furnace pregen stop` | 멈춘다. 진행 위치는 남는다 |
| `/furnace pregen resume` | 남은 진행 위치부터 이어 한다(서버를 다시 켠 뒤에도) |
| `/furnace pregen cancel` | 멈추고 진행 위치를 지운다. 이미 만든 청크는 그대로 |

- 권한 4(콘솔·`/save-all` 과 같은 수준). 명령을 친 차원에서 돈다 — 네더·엔드는 `/execute in minecraft:the_nether run furnace pregen start 2000`.
- 한 차원에 하나만 돈다. 돌고 있는데 `start` 하면 거절하고, 멈춰 둔 진행이 있는데 `start` 하면 `resume` 이나 `cancel` 을 먼저 하라고 거절한다(모르고 덮지 않게).
- 진행률은 10초마다 콘솔 로그에, 명령을 친 플레이어에게도 보낸다(`-Dfurnace.pregen.reportSeconds=<초>`, 0 이면 끔).
  예: `[미리 생성] minecraft:overworld 반경 2000 (가운데 0, 0): 18432/62001 청크 (29.73%), 새로 만든 18000 · 건너뛴 432, 41.3 청크/초, 남은 시간 0:17:35`
- 진행 위치는 차원 폴더 `data/furnace_pregen.properties` 에 10초마다·멈출 때 쓴다. 서버를 끄면(`/stop`) 멈춘 것으로 남고, 다시 켠 뒤 저절로 이어 하지는 않는다 — `resume` 을 친다.

### 플레이어가 있어도 돌려도 되나

된다. 미리 생성 요청은 생성 대기열(T-170)의 **맨 뒤**에 선다. 플레이어·플러그인·스폰 청크 요청이 하나라도 기다리면 그것이 먼저 시작되고,
미리 생성은 생성 스레드가 놀 때만 쓴다. 플레이어가 미리 생성이 걸어 둔 청크를 원하면 그 요청은 맨 뒤에서 바로 내려온다.
다만 생성 스레드가 미리 생성으로 바쁘면 CPU 는 그만큼 쓴다 — 틱이 빠듯한 서버는 사람이 적은 시간에 돌린다.

### 무엇이 만들어지나

플레이어가 걸어가 만드는 것과 같은 생성 경로(같은 생성기·같은 저장)로 만든다. 청크는 티켓 없이 올라왔다가 유예(`chunk-eviction-grace`) 뒤
평소처럼 저장되고 내려간다(엔티티 틱·무작위 틱은 받지 않는다 — 플레이어 근처가 아니므로). 이미 디스크에 있는 청크는 읽지 않고 건너뛴다.
저장이 밀리면(IO 레인 역압) 새 요청을 멈췄다가 다시 한다.

겹치는 장식(광석 덩어리·이끼·스컬크 무리처럼 청크 경계를 넘는 것)은 바닐라처럼 생성 순서에 따라 결과가 조금 다를 수 있다 — 같은 시드라도
플레이어가 걸어간 순서에 따라 달라지는 것과 같다. 같은 순서(`-Dfurnace.pregen.window=1`)로 두 번 만들면 블록이 모두 같다.

### 손잡이(시스템 속성)

| 키 | 기본 | 뜻 |
|---|---|---|
| `furnace.pregen.window` | 생성 스레드 × 2 | 동시에 걸어 두는 청크 수 |
| `furnace.pregen.maxResident` | 1024 | 만들어 놓고 아직 안 내려간 청크가 이만큼이면 새 요청을 멈춘다 |
| `furnace.pregen.reportSeconds` | 10 | 진행률 보고 간격(0 = 끔) |

## 3. 속도 짐작

클라우드 4코어(생성 스레드 4), 접속자 없을 때 새 땅 약 80 청크/초(반경 640 = 6561 청크 1분 18초). 반경 5000 블록(약 39만 청크)이면
1시간 20분쯤이다. 노트북 10코어처럼 생성 스레드가 많으면 그만큼 빠르다. 사람들이 새 땅을 걷는 동안에는 그쪽이 먼저라 미리 생성은 남는 틈만 쓴다
(봇 16명이 걷는 동안 1.3 청크/초 — 그동안 봇들의 발밑 채움·받은 청크 수는 미리 생성이 없을 때와 같았다).
