# M-22 스폰 청크 규칙 0 대 2 측정 (노트북)

## 장비·조건
- 노트북 DominicusLaptop: Intel i5-1235U(P코어 2개=논리 4, E코어 8개), RAM 16GB, Windows 11, Temurin 21.0.13. 데스크탑은 쓰지 않았다(도미니코 지시).
- 서버 jar: 기준 브랜치 `claude/quirky-wright-lra834` 의 f0a6bffaa 빌드. `-Xmx6G`, JFR, `-XX:ActiveProcessorCount=8`, 서버 java 는 E코어 8개(0xFF0), 봇 node 는 P코어(0x00F)에 묶음. 콘솔·로그 UTF-8.
- 진행기 `tools/r0-laptop/m22.py`(데스크탑 스레드가 만든 것에 코어 묶기만 추가). 결과 원본 `tools/r0-laptop/m22-laptop/`.
- 규칙 0 = `spawnChunkRadius 0`, 규칙 2 = 기본값(스폰 청크 유지). 월드 시드·설정은 둘 다 같고 level.dat 만 다름. 판 3번씩, 판 안에서 규칙 순서를 바꿔 가며 돌림.
- 한계: 노트북(하이브리드 코어, 발열·전원 영향 가능), 표본 3판, 클라우드 판과 절대값 비교 불가. 걷기 봇은 1명, 속도 10, 60초.

## 읽는 법
- 접속자가 없을 때: 규칙 2 는 청크 49개를 계속 들고 있어 CPU 약 0.23코어, 힙 +64MB, RSS +100MB. 규칙 0 은 거의 0(0.025코어). 이 차이는 세 판 모두에서 일관됐다(확정).
- 걷기 중: 규칙 2 가 시야16 에서 CPU 약 +31%p 더 높게 나왔으나 시야10 에서는 +15%p 이고, 판 간 퍼짐이 커서(시야10 규칙 2: 169~190) 크기를 단정하기 어렵다. 로드 청크는 규칙 2 가 약 50개 많다(스폰 청크 49개와 일치).
- 기동 시간: 유휴 판의 규칙 2 기동이 26.6초, 58.1초로 튀었지만, 걷기 판의 규칙 2 기동은 모두 15~16초라 규칙 탓으로 보기 어렵다. 원인 미확인(노트북 잡음 추정, 확인 안 함).
- 표의 mspt(지역 틱 평균)는 걷기에서 규칙 0 이 약 5.0ms, 규칙 2 가 약 2.5ms 로 반대로 나왔다. 규칙 0 쪽이 더 느리다는 뜻으로 보기엔 CPU 와 어긋난다. 이 지표가 무엇을 평균하는지(지역 수에 따라 달라질 수 있음) 아직 확인하지 않았으므로 해석하지 않는다.
- 이전 데스크탑 중간 값(유휴 규칙 2 약 0.30코어, 규칙 0 약 0.06코어)과 방향이 같다. 데스크탑 값은 IDE·음악 앱이 켜진 상태라 참고용.

## 하지 않은 것
코드 변경 없음, 규칙 1·3 이상, 접속자 여러 명은 측정하지 않았다.
