## 3. R0 — 1차 병합분 실측 비교 방법

목적은 두 가지다. 1차 효과를 서버 전체 장면으로 확인하는 것, 그리고 2차 검토자가 쓸 새 핫스팟 지도를 만드는 것이다.

### 3.1 무엇과 무엇을 비교하나

- A = `07dec3da`(O00 기준선), B = `a242b1af`(2차 기준). 둘 다 fatJar 로 만들어 **같은 컨테이너에서 A/B 교대로** 돌린다. O00 은 장면마다 1회였으므로 잡음 폭을 모른다. 이번에는 장면마다 A·B 를 2회 이상 교대로 돌려 범위를 적는다.
- B 는 기본값이 바뀐 것이 있다. 같은 조건 비교를 위해 B 를 두 번 잰다.
  - **B-바닐라**: D11 활성 범위 끔(바닐라와 결과가 같은 조건). A 와 비교하는 기준이다.
  - **B-기본**: D11 켬(배포 기본값). 활성 범위 효과를 따로 보인다.
  - `light.async` 는 기본 꺼짐으로 둔다. 빛 장면 하나만 켬도 잰다.
- 정확성 수정은 일을 늘렸을 수 있다(F6 스폰 청크 상시 로드, F2 `#tick` 20회, F5 길 다시 찾기, F1 원형 시야는 청크 수 −6%). 그래서 ① 유휴 장면의 차이는 따로 설명하고, 청크 수가 다른 장면은 **청크당** 값으로도 적는다.

### 3.2 장면 (O00 과 같은 조건)

O00 보고서 1장 그대로다. 시드 20261112, `simulation-distance=10`, `-Xmx6G`, G1 기본, JFR `settings=profile`, `-Dfurnace.tickstats=true`, `metrics.prometheus.enabled=true`. 도구는 `O00-repro/` 의 `srv.sh`·`o00walk.js`·`o00hold.js`·`sampler.py`·`JfrAgg.java`·`csvsum.py` 를 그대로 쓴다. 봇 이름 접두사는 실행마다 바꾼다(저장된 위치에서 접속하는 함정).

| 장면 | 조건 | 주요 지표 |
|---|---|---|
| ① 유휴 | 접속 0, 120초 | CPU, RSS, 로드된 청크 |
| ② 새 땅 이동 | 1·8·32명 × 시야 10·16, 초당 10블록 | 첫 시야 시간, 받은 청크/초, region MSPT 평균/p95, 가장 느린 TPS, CPU, 할당 GB/분, GC 최장 정지 |
| ③ 만든 땅 접속 | 8×16 냉·온, 1×16 | 시야 다 받기 중앙/최대, 직렬화 횟수/청크, region MSPT, 가장 느린 TPS |
| ④ 몹 농장 | 소 1000·3000 | region MSPT, TPS |
| ⑤ 레드스톤·호퍼 | O00 과 같은 장치 | region MSPT, 이벤트 확인 몫 |
| ⑥ 기동 | 새 월드·다시 켜기 | Done 까지 시간, 요새 고리 몫 |

B 에서만 덧붙이는 것: `SceneLibraryBench`(장면 9개), T-075 호환 장면 10종. 2차 회귀 감시의 새 기준선이 된다.

### 3.3 결과 형식

- 장면마다 전/후 표: A, B-바닐라, B-기본, 차이(%), 잡음 범위.

## 5. 검토자 규칙 (1차 1장에 더하는 것)

1. **1차 기각 후보는 새 근거 없이 되살리지 않는다.** 기각 목록은 `optimization-tasks.md` 1장·3.5 절 끝·6.1 절이다(방송 패킷 한 번 인코딩 공유, Deflater 재사용, O07-11 변경 방송 비트맵, O08-12 호퍼 쉬기·피스톤 기억, 빛 풀 안 A·B·D, region 구역 s2r1, O14-23 등). 되살리려면 "무엇이 바뀌어 전제가 달라졌나"와 새 측정이 있어야 한다.
2. **안 한 1차 TASK 는 새 번호로 다시 내지 않는다.** 유지·올림·내림·폐기와 그 근거(새 숫자)만 적는다.
3. **병합된 TASK 의 남은 몫**을 본다: 기대한 만큼 나왔는지, 다음 병목이 무엇인지, 기대에 못 미치면 원인.
4. 2차 TASK 번호는 `T-1xx`(측정은 `M-1xx`)로 시작해 1차와 겹치지 않게 한다. 묶음마다 B1 = T-100~, B2 = T-110~, … B7 = T-160~.
5. 결과 동일 증명은 IdentityKit(T-001)·장면 라이브러리(T-003)·호환 장면(T-075) 위에서 한다. 금 파일을 바꾸는 제안은 독립 검토 승인과 PR 사유가 필요하다(O15 결정).
6. 도미니코 결정이 필요한 것은 `docs/user-todo/entries/<날짜>-opt-review-r2-<묶음>.md` 에 쓰고 코디네이터에 알린다.
