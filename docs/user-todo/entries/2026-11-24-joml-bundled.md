# JOML 1.10.5 를 서버 실행 파일에 늘 싣기 (2026-11-24)

**코디네이터 확정(도미니코 위임).**

- 무엇: 서버 실행 파일에 JOML 1.10.5 를 Guava·SnakeYAML 처럼 그대로 싣는다(Paper 1.21.1 과 같은 판). 호환 계층이 이미 JOML 을 늘 기대하므로(`compatCore`) 자동 내려받기가 꺼져 있어도 동작한다.
- 왜: `Mth.X_AXIS` 같은 JOML 정적 필드와 엔티티 데이터의 JOML 칸을 채우려면 JOML 이 항상 있어야 한다.
- 안 하면: JOML 을 내려받지 못하는 서버(자동 내려받기 꺼짐)에서 그 필드가 클래스 초기화를 죽인다.
- 추천: 함(확정).
- 주의: 호환 라이브러리 방식이 OFF 면(`plugins.compat.libraries` 끄기) 호환 계층이 기대는 묶음도 붙이지 않으므로 JOML 도 안 붙는다. 그 서버에서는 JOML 을 쓰는 NMS 멤버가 클래스 못 찾음으로 실패한다(Paper 와 같은 동작은 아님, 끈 쪽의 선택).
