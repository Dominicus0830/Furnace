# 결과 동일 금 파일 갱신 절차 (IdentityKit, T-O15-02) — 2026-11-12

## 알림 (바뀐 것)

- 최적화 PR 이 "옛 구현과 결과가 같다"를 증명할 공용 시험 도구(IdentityKit)가 생겼다. 운영 코드는 바뀌지 않았다. 설명: `docs/testing/identitykit.md`.
- 월드젠 노이즈 결과를 **금 파일**(`furnace-server/src/test/resources/identity/*.txt`, 기대 해시 목록)과 비교하는 시험이 평소 시험에 들어갔다(`NoiseIdentityGoldenTest`). 노이즈·표면·카버를 고치는 최적화가 결과를 바꾸면 CI 가 빨개진다.

## 결정 필요

| # | 질문 | 추천 | 이유 |
|---|---|---|---|
| 1 | 금 파일이 바뀌는 PR(= 결과가 달라지는 PR)을 병합하려면 무엇이 필요할까? **A** PR 본문에 사유(어느 파일·왜·바닐라 근거) + 독립 검토자 스레드가 바뀐 줄을 확인·승인. **B** A 에 더해 도미니코 직접 승인(user-todo 에 올리고 대기). **C** 사유만 적으면 스레드가 병합. | **A** | 지금 병합 규칙(CI `test` + 독립 검토)과 같은 틀이라 일이 멈추지 않는다. 금 파일 갱신은 의도한 바닐라 정확성 수정이나 장면 변경일 때만 허용하고, 최적화와 한 PR 에 섞지 않는다. 검토자가 바뀐 줄과 바닐라 근거를 직접 본다. B 는 안전하지만 정확성 수정마다 도미니코를 기다려 멈춘다. C 는 최적화가 결과를 바꾸고 금 파일만 고쳐 통과하는 것을 막지 못한다. |

추천안 A 를 이미 문서(`docs/testing/identitykit.md` "금 파일 갱신")에 적어 두었다. 다른 안을 고르면 그 절만 고친다.
