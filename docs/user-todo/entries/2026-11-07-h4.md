# 호환 계층 실제 플러그인 시험 (H4) — 2026-11-07

서버 쪽 측정은 끝났다(`docs/feature-parity/compat-h4-2026-11-07.md`, 생성 대조표 `compat-h4-coverage-2026-11-07.md`). 이 컨테이너는 Maven Central 만 닿아 Vault·PlaceholderAPI·EssentialsX 등 인기 플러그인 jar 는 받지 못했다. 직접 확인·결정할 것:

- **직접 확인(권장, 표본 늘리기):** 쓰고 계신 실제 Bukkit·Paper 플러그인 jar(서버에 올릴 것들, 예: Vault·PlaceholderAPI·EssentialsX·LuckPerms·WorldEdit·ProtocolLib)를 한 폴더에 모아 아래를 한 번 돌려 주세요. 저장소 문서·기준표는 건드리지 않고 `furnace-compat-paper/build/compat-h4-extra-report.md` 만 만들어집니다. 그 파일(또는 jar 자체를 프로젝트 파일 `furnace/real-plugins/` 에)을 올려 주시면 다음 스레드가 같은 도구로 순위를 다시 매깁니다. jar 는 저장소에 커밋하지 않습니다(라이선스·크기).
  `./gradlew -PskipOracle=true :furnace-compat-paper:compatReport -PextraJars=<jar 가 든 폴더>`
  한 플러그인만 올려 보려면 `./gradlew -PskipOracle=true :furnace-compat-paper:liveProbe -Pjar=<jar 이름 앞부분> -PextraJars=<폴더>`.
- **결정:** 서버가 줘야 하는 라이브러리를 Furnace 서버 jar 에 넣을지. Paper 는 Adventure·Guava·Brigadier·SnakeYAML·log4j 를 싣고 있어 Paper 용 플러그인은 `libraries:` 선언 없이 그것들에 기댄다. 실측(실제 jar 13개): Adventure 80개 클래스·Guava 67개·Brigadier 30개·SnakeYAML 4개를 요구하는데 지금 서버 클래스패스에는 모두 없다(Gson 만 있음). 대략 크기(Central 기억 기준 jar): Guava 3.1 MB, Adventure(api·key·minimessage·gson/legacy/plain 직렬화) 약 0.7 MB, SnakeYAML 0.33 MB. **Brigadier 는 Maven Central 에 없고 Mojang 저장소(`libraries.minecraft.net`)에만 있으며 이 컨테이너에서는 그 호스트에 못 닿는다**(내려받기 접근을 우회하지 않는다). 후보: ① 모두 서버 jar 에 포함(추천, 약 4 MB 증가, Brigadier 는 빌드 환경에서 받을 수 있어야 함), ② 플러그인이 선언한 것만 자동 내려받기(R1, 기본 꺼짐)로 해결(Paper 플러그인은 선언이 없어 실패), ③ 호환 계층이 필요한 부분만 새로 작성(저작권·유지 부담). 답이 없으면 다음 묶음은 Brigadier 를 뺀 ①을 조사만 합니다.
- **결정:** 다음 묶음 순서. 측정이 제안한 순서는 A(명령·스케줄러·서비스를 `JavaPlugin` 에 연결: `getCommand`·`BukkitScheduler`·`ServicesManager` — 가장 많은 jar 가 막힘) → B(라이브러리, 위 결정 필요) → C(`Registry`·`Sound`·`Particle`·`PotionEffectType` 등 값 타입) → D(인벤토리 이벤트·메뉴) → E(BossBar·Scoreboard·플러그인 메시징) → F(Spigot·BungeeChat) → G(이벤트 확장) → H(Paper 스케줄러). 답이 없으면 이 순서대로 열자고 코디네이터에게 제안합니다.
