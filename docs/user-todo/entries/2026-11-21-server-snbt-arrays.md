# 서버 SNBT 읽기를 바닐라와 맞춤 (2026-11-21)

급하지 않다. 결정할 것 없음. 확인용 기록이다.

## 무엇이 바뀌었나
플러그인이 아이템 구성요소 글을 읽을 때 쓰는 서버 안쪽 SNBT 읽기가 배열에 느슨해서, 바닐라가 거절하는 글을 받아들였다. 이제 바닐라 1.21.1 서버로 같은 입력 206개를 돌린 결과와 똑같이 받아들이거나 거절한다(오류 문구 포함).

| 입력 | 전에는 | 지금(바닐라와 같음) |
|---|---|---|
| `[B;1,2]` (접미사 없는 수를 바이트 배열에) | 받아들임 | 거절: `Can't insert TAG_Int into TAG_Byte_Array` |
| `[I;1b]`, `[L;1]` | 받아들임(수를 넓혀 넣음) | 거절(배열 원소 종류가 정확히 같아야 함) |
| `[i;1]`, `[b;1b]` (소문자 종류 글자) | 받아들임 | 거절: `Invalid array type 'i'` |
| `['B';1]` (작은따옴표) | 배열로 읽으려 함 | 목록으로 읽음 |
| `{a:1,` 처럼 쉼표 뒤에서 끝남 | `Expected '}'` | `Expected key` (바닐라와 같음) |
| 오류 문구의 앞 문맥 | 35글자 | 10글자(바닐라와 같음) |
| 목록 섞임 오류 | 종류를 숫자로 표시 | `TAG_Int` 같은 이름(바닐라와 같음) |

## 안 고치면 / 영향
Paper 도 같은 바닐라 읽기를 쓰므로 호환 면도 Paper 와 같아진다. 예전에 `[B;1,2]` 같은 글을 쓰던 플러그인은 이제 바닐라·Paper 서버에서와 똑같이 오류를 받는다(그 글은 원래 바닐라에서 동작하지 않았다).
