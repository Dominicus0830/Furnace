전문: `docs/ops/version-tags.md`. 아래는 코디네이터 위임으로 먼저 정한 것이고, 마음에 안 들면 바꾸면 된다(태그를 아직 릴리스로 쓰지 않았으므로 바꾸는 비용이 작다).

| # | 물음 | 상태 | 내용 |
|---|---|---|---|
| G1 | Furnace 버전 숫자를 마크 판마다 새로 셀까, 이어서 셀까 | 위임 결정(추천대로) | 이어서 센다. `v1.21.1-0.4.0` 다음 1.21.2 첫 출시가 `v1.21.2-0.5.0`. 안 하고 판마다 `0.1.0` 부터 다시 세면 "Furnace 가 얼마나 자랐는지"가 안 읽힌다. 마크 판은 이름 앞쪽이 말해 준다. |
| G2 | 첫 `1.0.0`(실서비스 선언) 시점 | **도미니코 결정 필요** | 그 전까지는 `0.x.y`. 코디네이터가 추천하는 기준: FAWE 호환 병합 + 플러그인 여러 개 실서버 시험 통과 + main 반영. 안 정하면 계속 `0.x` 로 남을 뿐 해로운 일은 없다. |
| G3 | 릴리스 태그(`v…`)를 누가 언제 찍나 | 위임 결정(추천대로) | 도미니코가 "출시"라고 지시할 때만. base·ms·port 태그는 스레드가 알아서(기준 브랜치 전체 시험 초록일 때). |
