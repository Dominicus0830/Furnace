보고서: 공유 폴더 `furnace/reviews/opt-review-r2/shift3-assessment.md`(재현 `shift3-repro/`). B1 결정 항목(`2026-11-14-opt-review-r2-b1.md` 1번)에서 "득과 실을 확실히 조사" 하라고 한 뒤속이다. 클라우드(4코어)와 노트북(i5-1235U 10코어)을 따로 쟀고 숫자를 섞지 않았다.

1. **`region-section-shift` 기본값을 4 에서 3 으로 바꿀지(r1 그대로).** 지금은 바꾸지 않았다.
   - 득(측정): 32명이 흩어진 서버에서 가장 느린 region TPS 가 클라우드 8.2~8.8 → 18.7~19.6, 노트북 8.3~8.4 → 19.9. 코어가 많을수록 이득이 크다.
   - 같음(측정): 한곳에 몰린 32명, 소 3000마리 농장, CPU 여유가 있는 상태에서 플레이어가 다가갔다 멀어지는 장면, 스레드 수·힙.
   - 실(측정): CPU 가 이미 꽉 찬 상태(새 땅 초당 690청크)에서 32명이 동시에 엇갈리는 장면은 TPS 평균 11.4 → 10.7(−6%), 하위 10% 7.8 → 6.7(−13%). region 표 조회 한 번 +9~14ns(T-019 키 섞기로 없어짐).
   - 위험(코드 확인): region 사이 띠가 257 → 129블록. 바닐라 기본 생존 플레이는 안전(피뢰침·지옥문 128 이 1블록 여유). NBT 로 키운 폭발(ExplosionPower 65 이상)과 플러그인의 `getNearbyEntities` 같은 region 한정 조회는 129블록부터 남의 region 을 못 본다(지금은 257).
   - **(a) 조건부 적용 — 추천.** 바꾸는 PR(T-101)에 ① 기본값 단언 시험 2개·설정 키 표 고치기와 경계 시험 shift 3·4 둘 다 돌리기(T-004) ② 반경 목록(M-07 K3)에 "띠 129" 줄 ③ 플러그인 문서에 region 한정 조회 안내 ④ PR 본문에 과부하 장면 −6% 명시. T-019 키 섞기는 같이 하면 좋다.
   - (b) 지금 그대로(s4) — 흩어진 다인원 서버 TPS 가 절반인 채로 둔다. 운영자는 `furnace.properties` 로 3 을 고를 수 있다.
   - (c) 보류 — 과부하 장면의 −6% 원인을 먼저 나눠 본 뒤 결정.
