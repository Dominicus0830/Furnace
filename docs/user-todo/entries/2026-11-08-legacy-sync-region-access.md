# 옛 동기 작업이 월드를 만지게 하기(만진 region 만 빌려 오기) — 2026-11-08

11-08 결정 6("성능·호환성 둘 다")에 따라 구현했다. 서버 쪽은 시험으로 확인(헤드리스 서버에서 옛 동기 작업이 블록·엔티티를 읽고 쓰는 시험, 실제 region 스레드로 빌림·병합·교착을 보는 시험). 설계·한계: `docs/feature-parity/compat-legacy-sync-region-access-2026-11-08.md`.

- **고른 설계(설계가 갈린 곳):** 옛 동기 작업·옛 명령이 블록·엔티티를 만지면, 전역 스레드가 **그 region 만** 틱이 끝난 자리에서 잠깐 빌려 와 곧바로 읽고 쓴 뒤 박동이 끝나면 돌려준다. 만지지 않은 region 은 계속 병렬로 돈다. 이전 선택지 ②(접근마다 넘기고 기다리기)는 읽기마다 수 ms 를 기다려 느리고 교착 위험이 커서, ④(박동마다 온 서버 멈추기)는 옛 반복 작업 하나만 있어도 매 틱 병렬성이 0 이 되어 고르지 않았다. 대가: Bukkit 처럼 "온 월드가 한순간"은 아니다(region 마다 빌린 순간이 다를 수 있다). 바꾸고 싶으시면 알려 주세요.
- **결정(기본값 정함, 답이 없으면 그대로):** Paper `GlobalRegionScheduler` 로 건 작업도 월드를 만지면 빌려 올지. 지금은 **빌리지 않는다**(Folia 규칙 그대로 — Folia 를 아는 플러그인은 원래 거기서 월드를 만지지 않는다). Paper 전용 플러그인이 그 스케줄러로 월드를 만지는 경우가 보이면 켜는 것이 한 줄입니다.
- **결정(기본값 정함):** 빌리러 기다리는 한도 5초(`-Dfurnace.regionBorrowWaitMillis=5000`). 넘으면 예전처럼 `ThreadOwnershipException` 과 경고 한 줄. 값을 바꾸고 싶으시면 알려 주세요.
- **직접 확인(실제 플러그인, 권장):** 동기 작업에서 블록을 바꾸는 플러그인(예: 일정 시간마다 블록을 되살리는 재생 광산류, 홀로그램·간판 갱신류)을 실제 서버에 올려, 예외 없이 돌고 다른 지역의 TPS 가 떨어지지 않는지 `/tps` 로 봐 주세요. 결정 8 의 실제 플러그인 jar 를 받으면 그것으로도 돌려 보겠습니다.
