# 엔티티 id 역조회·머리 yaw (PR #248 검토 후속) — 2026-11-12

## 알림 (바뀐 것)

- `Entity#getLocation()` 의 yaw 가 살아 있는 엔티티에서 **머리 방향**이 됐다(Paper 와 같다). 몸과 머리가 다른 몹(좀비·주민이 플레이어를 바라볼 때 등)에서 값이 달라진다. 플레이어·몸=머리인 엔티티는 그대로. 나중에 `teleport(getLocation())` 로 되돌려 놓는 플러그인은 몹의 몸·머리를 같은 값으로 맞추게 된다(바닐라 `moveTo` 와 같다).
- NMS `ServerLevel#getEntity(int)` 가 생겼다(ProtocolLib 의 엔티티 id → 엔티티 역조회). 네트워크·비동기 스레드에서 부르면 소유 region 이 읽어 줄 때까지 최대 1초 기다린다.

## 결정 필요 (급하지 않음)

| # | 질문 | 추천 | 이유 |
|---|---|---|---|
| 1 | 차원·엔드 관문 이동 뒤 **옛 Bukkit 객체가 옛 엔티티 id 를 계속 주는 것**(Paper 는 같은 Bukkit 객체가 새 엔티티를 따라가 새 id) 을 지금 고칠까? 고치려면 서버가 엔티티를 새로 만들어 넣을 때마다(모든 스폰) 호환 계층이 UUID 로 갈아 낄 스냅샷을 만들어야 해 스폰마다 비용이 든다. | 보류 | 새 스냅샷이 오면(이벤트·`refresh`) 그때 맞는 id 가 된다. 패킷 리스너가 저장한 Bukkit 객체의 id 를 차원 이동 뒤 비교하는 경우에만 어긋나고, `ServerLevel#getEntity(int)`·`Entity#getEntityId()` 를 새로 얻은 객체로 부르면 맞다. 실제 플러그인에서 어긋남이 보고되면 그때 UUID → 현재 id 조회를 더한다. |
