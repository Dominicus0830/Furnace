# 전 모듈 최적화 검토 2차(O13 호환 계층) 결정 (opt-review-wave2) — 2026-11-13

O13 호환 계층 검토(보고서·반론)에서는 **새로 정할 것이 없다.** 근거와 TASK 는 `docs/roadmap/optimization-tasks.md` 6장에 있다. 1차 결정 중 추천이 바뀐 것 하나만 적는다.

- **결정 D17(1차) 빠진 이벤트 범위 — 추천 갱신:**
  - 지금 어댑터에는 Bukkit 이벤트 클래스가 92개뿐이다. 플러그인 리스너가 없는 클래스를 하나만 써도 그 리스너 전체가 등록되지 않는다. 예를 들어 보호 플러그인의 `BlockBreakEvent` 처리기까지 사라진다.
  - 추천은 세 단계다.
    1. **먼저 (T-040a):** 없는 클래스가 있어도 나머지 처리기는 등록되게 하고, 보호 이벤트 6종(폭발·피스톤 2종·퍼짐·형성·투사체 맞음)을 잇는다.
    2. **다음 (T-040b):** 플러그인 jar 를 훑어 실제로 쓰이는 이벤트부터 잇는다.
    3. **마지막 (T-040c):** 남은 것은 껍데기 클래스로 둔다.
  - 이 순서로 하면 1차 추천(H1 6종 → 많이 쓰는 10개 → 나머지)을 대신한다.
- 참고: 1차 TASK 표의 결정 번호 오기(T-038·040·041·044·045·M-10)를 고쳤다. 결정 내용은 바뀌지 않았다.
