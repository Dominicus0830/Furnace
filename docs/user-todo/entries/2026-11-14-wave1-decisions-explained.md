## A. 판단이 필요한 4건

### D2 채팅 이벤트를 어디서 실행할지
- **무엇**: 플레이어가 채팅하면 플러그인 이벤트가 서버 전체 공용 스레드에서 돕니다. 어떤 플러그인이 여기서 오래 멈추면 시간, 명령, RCON, #tick이 같이 멈춥니다.
- **선택지**: (가) 지금처럼 전역 스레드 / (나) Paper처럼 접속자별 순서 줄로 옮김.
- **추천**: (나).
- **이유**: Paper 플러그인은 이미 그렇게 도는 걸 전제로 만들어졌고, 한 플러그인 때문에 서버 전체가 서는 일을 막습니다. 다만 채팅과 서명 명령이 같은 순서 상태를 쓰기 때문에 옮길 때 신경 쓸 점이 있어 구현이 단순하지는 않습니다(T-035).
- **당신이 할 일**: "추천대로"면 답 없이 두셔도 됩니다. 단 채팅 쪽 구조가 바뀌니 알고만 계세요.

### D3 백업 zip 안의 지역 파일을 다시 압축할지
- **무엇**: 지역 파일(mca)은 이미 압축되어 있는데 백업 때 또 압축하고 있습니다.
- **선택지**: 다시 압축(지금, 용량 작음, CPU 많이 씀) / 압축 안 함(CPU 99% 절약, 백업 크기 40~55% 커짐).
- **추천**: 압축 안 함을 기본으로 하고 `backup.compression` 옵션을 둡니다(T-036).
- **이유**: 백업 중 서버가 버벅이는 쪽이 디스크를 더 쓰는 쪽보다 대체로 더 나쁩니다. 옵션이 있어 디스크가 모자란 서버는 되돌릴 수 있습니다.
- **당신이 할 일**: 디스크가 빠듯한 환경이라면 알려 주세요. 아니면 추천대로 하시면 됩니다.

### D11 Spigot·Paper의 엔티티 설정(활성 범위 등)
- **무엇**: 먼 몹을 덜 움직이게 하는 설정들입니다. 속도는 빨라지지만 **바닐라와 결과가 달라집니다.**
- **추천**: 기본은 꺼 두고, 활성 범위부터 옵션으로만 넣습니다.
- **이유**: "결과물은 바닐라와 같아야 한다"는 원칙을 기본값에서는 지키고, 원하는 서버만 켤 수 있게 합니다.
- **당신이 할 일**: 추천은 원칙과 맞습니다. 옵션도 아예 넣지 말자는 의견이면 알려 주세요.

### D14 바닐라 데이터를 못 구했을 때
- **무엇**: 바닐라 데이터(레시피·전리품 등)를 못 얻으면 지금은 그냥 뜹니다. 그러면 레시피와 전리품이 빈 서버가 됩니다.
- **선택지**: 그대로 기동 / 기동 중단.
- **추천**: 기동을 멈추고, 알고 쓰는 경우를 위해 우회 옵션 `-Dfurnace.allowNoVanillaData`를 둡니다.
- **이유**: 망가진 서버가 조용히 돌며 월드를 망치는 것보다 시작 단계에서 분명히 실패하는 편이 안전합니다. 테스트나 오프라인 환경은 옵션으로 해결됩니다.
- **당신이 할 일**: 테스트 서버나 CI가 데이터 없이 뜨는 경우가 있는지만 확인해 주세요. 없으면 추천대로.
