# NMS 어댑터 N2b(필드 수준 청크 쓰기) 설계 — 결정 3건 (2026-11-14)

설계안: `docs/feature-parity/compat-nms-n2b-design-2026-11-14.md`. 셋 다 "바닐라·Paper 와 같게"(추천)와 "Furnace 가 더 친절하게" 사이의 선택이다.
결정 전까지 구현은 추천안 기준으로 설계·준비한다(N2b-0·1 은 결정과 무관).

## 도미니코가 결정할 것

| # | 질문 | 선택지 | 추천 |
|---|---|---|---|
| D1 | 플러그인이 **비동기 스레드**에서 청크 섹션에 블록을 직접 쓰면(`section.setBlockState` 등) | **A** 플러그인이 보는 사본에 바로 쓰고 서버 청크에는 주인 스레드가 1틱 안에 들여온다(Paper 에서처럼 "그냥 된다") / **B** 오류를 던진다(엄격, 그런 플러그인은 안 돈다) | **A** — Paper 에서 되는 플러그인이 Furnace 에서도 되게. 결과는 Paper 와 같고 반영만 최대 1틱 늦다 |
| D2 | 플러그인이 섹션을 통째로 바꾼 뒤 **빛을 다시 계산하지 않으면** | **A** 바닐라·Paper 처럼 낡은 빛 그대로(밝기가 틀린 칸이 남을 수 있음) / **B** Furnace 가 바뀐 섹션의 빛을 자동으로 다시 계산(끄는 설정 키 둠) | **A** — 바닐라와 같은 결과가 원칙. FAWE 는 기본 설정에서 스스로 빛을 다시 계산하므로 차이가 없다 |
| D3 | 섹션을 통째로 바꾼 뒤 플러그인이 **저장 표시(`setUnsaved`)를 안 하면** | **A** 바닐라처럼 저장되지 않는다(청크가 내려가면 그 편집은 사라짐) / **B** Furnace 가 들여올 때 자동으로 저장 표시 | **A** — 바닐라·Paper 와 같은 결과. FAWE 는 늘 저장 표시를 한다 |

## 알아 둘 것 (결정 아님)
- 설계 원칙: 바닐라에 있는 후처리(빛·하이트맵·저장 표시·클라이언트 알림)는 바닐라처럼 플러그인 몫으로 두고, Furnace 에만 있는 캐시는 Furnace 가 책임진다.
- FAWE 로 실제 편집이 되려면 N2b 외에 N3a(청크 보내기·ChunkMap)와 FAWE 어댑터 초기화 기호(`SharedConstants`·`DataComponentPatch` 등)가 더 필요하다. 마지막 단계(N2b-6)에서 **테스트 노트북에 Paper 1.21.1 + FAWE 2.16.2 와 Furnace + FAWE 2.16.2 를 같은 월드로 띄워 같은 명령 결과를 비교**할 예정이다 — 그때 Paper jar 준비가 필요하다(이 클라우드에서는 papermc 에 못 닿는다).
