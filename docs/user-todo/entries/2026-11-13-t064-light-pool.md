# 빛 계산 풀 옵션(T-064, `light.async`) — 확인 (2026-11-13)

빛 계산을 region 스레드 대신 따로 도는 빛 스레드에 맡기는 옵션을 넣었다(바닐라 `ThreadedLevelLightEngine` 방식). **기본은 꺼짐**이고, 끈 동안은 지금과 똑같다.
켜는 법: `furnace.properties` 에 `light.async=true`(빛 스레드 수 `light.async-threads`, 기본 1).

측정(시험 `AsyncLightRegionTest.lamps400Bench`, 발광석 400개를 4틱마다 켜고 끄는 장치): region 틱 평균 **15.2ms → 1.3ms**, p95 **72ms → 2.3ms**. 빛을 다 기다린 뒤의 빛 값은 끔과 같다(해시 같음).

## 켜면 바닐라·지금과 달라지는 점 (결정 불필요 — 옵션이라 알고만 계시면 됨)
- 빛 스레드가 밀리면(큰 빛 장치) 빛이 한두 틱 늦게 보인다: 그 사이 작물·몹 스폰·잔디·얼음이 옛 빛을 본다. 바닐라 서버가 과부하일 때와 같은 성질이다. 평소(빛 일이 작음)에는 다음 틱에 보이므로 지금과 같다.
- 빛 갱신 패킷도 한두 틱 늦게 갈 수 있다(클라이언트 화면이 잠깐 어두웠다 밝아질 수 있음 — 바닐라도 같다).
- 새로 올라온 청크의 빛은 지금처럼 올라오는 자리에서 끝낸다(틱·스폰·전송 전에 빛이 맞다 — 바닐라와 같음). 그때 빛 스레드가 돌고 있으면 그 묶음을 기다리므로, 빛 스레드가 크게 밀리면 청크 로딩 틱이 그만큼 길어질 수 있다.
- 저장은 밀린 빛을 기다린 뒤 한다 — 바닐라처럼 옛 빛이 디스크에 굳는 일은 없다(바닐라보다 정확한 쪽).

## 직접 확인하면 좋은 것
- `light.async=true` 로 켜고 접속해, 레드스톤 램프 시계·횃불 놓기·부수기·동굴 걷기를 했을 때 화면 빛이 어긋나거나 남는 칸이 없는지. 청크가 늦게 뜨거나 빠지는 일이 없는지.
