# N2b-2 남은 바닐라 차이 — 빈 섹션에 NMS 로 넣은 블록을 Furnace 는 보이게 한다 (PR #373 검토, 2026-11-14)

**결정할 것**: 아래 차이를 그대로 둘지.

- **무엇이 다른가**: 플러그인이 NMS 컨테이너 쓰기(`section.getStates().set(...)`)로 **블록이 하나도 없던 섹션**에 블록을 넣고 `recalcBlockCounts()` 를 부르지 않으면,
  - Paper·바닐라: 섹션 개수가 0 이라 그 블록이 서버(충돌·`getBlock`)에서도, 클라이언트(그리지 않음)에서도 **공기**다 — 즉 Paper 에서는 이 플러그인이 고장 나 있다.
  - Furnace: NMS 읽기(`LevelChunk.getBlockState`)만 공기이고, Bukkit `getBlock`·충돌·빛·청크 패킷에서는 **블록으로 보인다**.
- **언제 생기나**: Paper 에서 이미 고장 난 플러그인만. 그렇게 쓰는 플러그인은 아직 모른다. 보통 플레이·`setBlockState`·FAWE 처럼 개수를 맞추는 플러그인에는 차이가 없다.

| 선택 | 결과 |
|---|---|
| **A (추천) 그대로 둔다** | 가장 자주 쓰는 블록 읽기에 개수 검사를 넣지 않는다(성능 유지). 문제 플러그인이 나오면 그때 맞춘다. |
| B 바닐라처럼 맞춘다 | Furnace 블록 읽기·충돌·청크 패킷이 바닐라 개수를 보게 한다(N2b-4 뒤, 읽기 성능 비용). |
