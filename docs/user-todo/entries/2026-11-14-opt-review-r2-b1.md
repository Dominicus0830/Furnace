# 2차 CSP B1(스케줄러·청크 저장·네트워크) 결정 (2026-11-14)

보고서: 공유 폴더 `furnace/reviews/opt-review-r2/B1-core.md`(원자료 `B1-repro/`). 측정은 클라우드 4코어 컨테이너에서 했고 노트북은 쓰지 않았다.

1. **C1(region 구역 크기 기본값) — 1차에 "실측 뒤 결정"으로 남긴 것. 측정 M-01 이 끝났다.**
   32명을 5000×5000 블록 안에 흩어 세운 만든 땅 장면(시야 10)에서, 지금 기본값 `region-section-shift=4`(r1)는 이웃끼리 시야가 닿는 플레이어들이 사슬처럼 한 region 으로 합쳐져(청크 6076개, 틱 67~77ms) **가장 느린 region TPS 가 8.1~8.4** 다. 구역을 줄이면 그 region 이 갈라져 **shift 3(r1) 18.4~19.1, shift 2(r2) 18.7~19.0** 이 된다(판 2개씩). 청크당 틱 비용은 어느 설정이든 같았다.
   - (a) s4r1 유지 — 지금 그대로. 흩어진 다인원 서버에서 TPS 가 절반.
   - **(b) s3r1 — 추천.** region 사이 띠가 128블록이라 1차에 확인한 "결과 동일" 조건(피뢰침 128블록 등)을 그대로 지킨다. s2r2 와 TPS 가 같고 구역 수는 ¼ 이라 관리 비용이 적다.
   - (c) s2r2 — 띠는 (b)와 같고 구역이 4배. 이번 장면에서 (b)보다 나은 점이 없었다.
   (b)·(c)를 고르면 기본값을 바꾸는 PR(T-101)은 ① 시험이 shift 3 을 쓸 수 있게(T-004) ② 플레이어가 다가갔다 멀어지는 움직이는 장면에서 합치기·나누기 비용 확인 ③ 8코어 장면(R0 측정이 끝난 뒤 노트북이나 도미니코 PC) ④ 128블록 넘는 월드 읽기가 새로 없는지 확인을 조건으로 연다. 운영자는 지금도 `furnace.properties` 의 `region-section-shift` 로 바꿀 수 있다.
2. (알림, 결정 아님) R0 의 "32명 새 땅 시야 채움 85 → 27%"(F-R0-01)는 회귀가 아니라 측정 봇의 함정이었다. 옛 버전은 콘솔 명령이 밀려 봇이 덜 걸었다. 같은 속도로 걸으면 옛·새 버전이 같고, 받은 청크/초는 새 버전이 19% 많다.
