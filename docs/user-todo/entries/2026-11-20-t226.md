# 확인 요청 — T-226 1단계(직렬화 풀 대기 계측) 병합 뒤 PC 측정 (2026-11-20)

**결정할 것은 없습니다.** 계측만 넣었고 서버 동작·청크 내용은 그대로입니다(`-Dfurnace.chunktrace=true` 를 켰을 때만 기록, 꺼져 있으면 비용 없음).

**쉬운 말:** 청크를 보내기 전 압축하는 줄에서 "지금 보낼 청크"와 "미리 만드는 청크"가 얼마나 기다리는지 따로 적게 했습니다. 이 숫자를 보고 줄 순서를 바꾸는 개선(2단계)을 할지 정합니다.

**측정 요청(코디네이터가 PC 스레드로):** R0 ③ 냉 8×16, `-Dfurnace.chunktrace=true`, 노트북·데스크탑 각 3판. 볼 값은 로그 `[CHUNKTRACE]` 의
- `hop.serpool.req`(지금 보낼 일) / `hop.serpool.spec`(미리 일) / `hop.serpool.pf`(주인 스레드 밖 길로 건 미리 일) 의 avg·max
- `batch.serpool.depth`(줄 길이), `batch.serpool.req.over100ms`(요청 일이 100ms 넘게 기다린 횟수)
- 2단계 진행 기준: 요청 일 평균이 미리 일의 2배 이상이거나 100ms 초과가 뚜렷할 때. 아니면 폐기.
