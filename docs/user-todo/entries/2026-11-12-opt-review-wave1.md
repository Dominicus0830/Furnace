# 전 모듈 최적화 검토 1차 결정 (opt-review-wave1) — 2026-11-12

최적화·기능 검토(보고서 15개, 반론 3개, 답변 토론)에서 도미니코가 정할 것만 모았다. 각 줄 끝의 추천대로 두면 TASK 목록(`docs/roadmap/optimization-tasks.md`)이 그대로 진행된다. 이미 정한 것(O11 명령 홉·#tick, O01 구역 = 실측 뒤·워치독 경고 켬, O15 난수 이음매·금 파일 절차, O07 폭발 가림 옵션 진행·빛 풀 분리는 해결 방법 조사)은 뺐다.

- **결정 D1 플러그인 비동기 실행기 기본값:** 지금은 가상 스레드라서, 옛 JDBC처럼 synchronized 안에서 블로킹하면 운반 스레드를 붙잡습니다. 추천: Paper와 같은 플랫폼 풀을 기본으로 하고 `virtual`은 옵션으로 둡니다. (T-034)
- **결정 D2 채팅 이벤트 실행 위치:** 지금은 전역 스레드에서 발화해서, 처리기가 블로킹하면 시간·명령·RCON·#tick이 함께 멈춥니다. 추천: Paper처럼 연결별 순서 사슬로 옮깁니다. (T-035)
- **결정 D3 백업 zip 안의 지역 파일:** 다시 압축하지 않으면 CPU가 99% 줄고 크기는 40~55% 늘어납니다. 지금은 압축합니다. 추천: 압축 안 함을 기본으로 하고 `backup.compression` 옵션을 둡니다. (T-036)
- **결정 D4 첫 응답 전 청크 배치:** 바닐라는 9개짜리 배치 하나를 보내고 응답을 기다립니다. 지금 Furnace는 틱마다 64개를 보냅니다. 추천: 바닐라와 같게 합니다.
- **결정 D5 청크 프레임 압축 레벨과 libdeflate:** 레벨 4로 내리면 청크 풀 CPU가 38~48% 줄고 바이트는 4% 늘어납니다. 이득은 풀이 꽉 찰 때만 납니다. 추천: 측정(M-05)이 끝날 때까지 바닐라 값 6을 유지하고 키만 공개합니다.
- **결정 D6 패킷 종류별 한도와 같은 주소 재접속 제한 기본값:** 추천: 새 서버는 꺼 두고, Paper 설정을 가져온 서버는 그 값을 따릅니다.
- **결정 D7 밀도 함수 코드 생성 다시 열기:** 노이즈가 아직 오버월드 CPU의 38~45%입니다. 추천: 월드젠 작은 항목들을 먼저 하고, 다시 재서 판단합니다.
- **결정 D8 생성 스레드 수 기본값(차원 공유 풀):** 선택지는 코어−1, 코어÷2, 설정입니다. 추천: 측정 M-02 뒤에 정합니다.
- **결정 D9 미리 생성(pregen):** 내장 명령을 만들지, Chunky 호환으로 충분한지입니다. 추천: Chunky가 되는지 먼저 확인합니다.
- **결정 D10 생성 저장소의 메모리와 CPU 중 무엇을 우선할지:** 추천: 측정 뒤에 정합니다.
- **결정 D11 Spigot·Paper 엔티티 손잡이(활성 범위 등):** 바닐라 결과를 바꾸므로 기본은 꺼 둡니다. 추천: 활성 범위부터 옵션으로 넣습니다.
