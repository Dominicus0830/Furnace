# squaremap 흉내 클래스 구멍 채우기 (nms-squaremap) — 2026-11-20

지도 그리기 플러그인 squaremap 이 부르는데 Furnace 에 없던 것 39개를 채웠다(설명서 `docs/feature-parity/compat-nms-squaremap-2026-11-20.md`). 결정할 것은 없고, 확인만 부탁한다.

| # | 무엇 | 이렇게 했고, 그래서 어떻게 되나 | 안 바꾸면 |
|---|---|---|---|
| S5-1 | **실제 squaremap 으로 접속 시험** | 코드로는 "squaremap 이 부르는 이름이 하나도 빠지지 않았다"(감사 0개)와 각 부분의 단위 시험까지 확인했다. 실제 플러그인을 올려 지도가 그려지는지는 보지 못했다. 예: 지도 그림에서 풀 색이 바이옴대로 나오는지, 색유리가 투명하게 그려지는지. 서버에 squaremap 을 넣고 `/map` 처럼 지도 화면이 도는지 봐 주면 된다. | 지도가 이상하게 그려져도 단위 시험으로는 못 잡는다(원인 후보: 바이옴 색, 하이트맵). |
| S5-2 | 명령 라이브러리의 "차원" 인자 | squaremap 이 Brigadier(Minecraft 명령 문장 해석기)용 차원 인자를 등록하려 할 때 이름은 있지만 실제로 문장을 읽지는 못한다(Furnace 는 그 분배기가 없다). 예: Paper 에서 Brigadier 로 `/squaremap fullrender <차원>` 의 차원 자동 완성이 되는데 Furnace 에서는 평소 Bukkit 식 명령이라 해당 없다. | Brigadier 를 쓰는 길이 필요해지면 그때 따로 설계(추천: 지금대로). |
| S5-3 | 바이옴 색은 서버가 켜질 때 한 번 읽는다 | 플러그인이 같은 이름으로 바이옴 색을 나중에 바꿔도 지도는 서버를 다시 켜야 새 색을 쓴다. 예: 바이옴 플러그인을 켠 채 풀 색을 바꿔도 지도는 이전 색. 데이터 팩이 바닐라 바이옴 색을 덮어쓴 경우도 지도는 내장 바닐라 색을 쓴다. | 그런 일이 드물다 — 추천: 지금대로 두고 문제가 보이면 고친다. |
