# FAWE 통합·Paper 대조 (N2b-6) — 2026-11-16

설명: `docs/feature-parity/compat-nms-n2b6-2026-11-16.md`. 노트북에서 실제 FAWE 2.16.2 를 Furnace 에 올려 Paper 1.21.1 과 같은 편집 7가지를 대조했다 — 블록·바이옴·하이트맵 0칸 차이, 빛만 다름(D2).
이 작업에서 범위 밖 동작 두 가지를 스레드가 먼저 바꿨다. 되돌릴 수 있으니 확인만 해 주면 된다.

## 결정할 것(사후 확인)

- **결정:** 플러그인 onLoad·onEnable 을 Furnace 전역 스레드에서 부르기(지금 PR). Paper 처럼 "켜는 스레드 = 동기 작업 스레드"가 되어 켤 때 주 스레드를 적어 두는 플러그인(FAWE 등)이 돌고, onEnable 안의 `Bukkit.isPrimaryThread()` 도 Paper 처럼 참이 된다. 위험: onEnable 안에서 전역 스레드 작업의 끝을 동기로 기다리면 멈춘다(개발 모드 다시 읽기는 이미 이렇게 켠다).
  - A. 유지(추천) / B. 되돌리고 FAWE 는 못 쓴다
- **결정:** NMS 클래스를 상속한 플러그인 클래스를 "정의 거부"에서 "껍데기로 정의, 만들 때 같은 문구로 거부"로(설계 H7 5.4 의 정책 바꿈). 그 클래스를 가리키기만 하는 코드(람다·메서드 참조·instanceof)가 돈다 — FAWE 어댑터 생성자에 필요.
  - A. 유지(추천) / B. 되돌리고 FAWE 만 따로 다룬다(특정 플러그인 저격이라 비추천)

## 직접 확인하면 좋은 것

- 실제 클라이언트로 접속해 `//set`·`//paste` 뒤 바뀐 청크가 화면에 바로 보이는지(FAWE 청크 패킷 → Furnace 가 그 청크를 다시 보낸다). 빛은 편집 전 값 그대로라 어둡거나 밝게 남을 수 있다(T-197 전까지).
- 상자·화로가 있는 곳을 `//set` 하면 지금은 그 청크 편집이 실패한다(T-198). 서버 로그에 `LevelChunk#removeBlockEntity` 오류가 나오면 이 경우다.
