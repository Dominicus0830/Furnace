# T-235 2단계: 게임 값 대조에서 나온 확인 거리 (2026-11-23)

바닐라 값 자동 대조에 채팅 글·레지스트리 키·블록 상태·아이템 8클래스를 넣었다. 그러다 고친 것과 남은 것 중 도미니코가 알아 두면 좋은 것만 적는다. 추천을 이미 적용했고 급하지 않다.

## 1. 글의 "키 이름" 부분을 평문으로 바꿀 때 바닐라처럼 키 글자 그대로 (적용함)
- 무엇: 채팅 글에는 "점프 키" 같은 키 이름 칸(`key.jump`)이 있다. 평문으로 바꾸면 Furnace 는 그동안 "Jump" 로 번역했는데, 바닐라 서버는 `key.jump` 를 그대로 쓴다(실제로 키를 바꿔 보여 주는 건 클라이언트).
- 바꾼 곳: Furnace API `Text.plainText()`/`getString()` 과 `PlainTextSerializer` 기본값. 번역해서 보고 싶으면 `PlainTextSerializer.builder().keybinds(KeybindMode.TRANSLATE)` 를 쓰면 된다.
- 안 하면: 플러그인이 `getString()` 결과를 비교·저장할 때 바닐라·Paper 와 글자가 달라진다.
- 추천: 지금처럼 바닐라와 같게. (공개 API 의 기본 동작이 바뀌는 것이라 적어 둔다.)

## 2. Paper 와 같게 둔 차이: 부술 수 없는 블록의 피스톤 반응 (적용함)
- 명령 블록·끝 차원문 틀 등 10개 블록은 Paper 에서 피스톤 반응이 늘 "막음"이다(바닐라는 블록 값). 호환 원칙대로 Paper 와 같게 두고, 대조 시험에 Paper 근거로 적었다.

## 3. 남은 작은 차이 하나 (기록만, 고칠 일감)
- `글.withStyle()` 을 서식 없이 부르면 바닐라는 JSON 이 `{"text":""}` 꼴, Furnace 는 `""` 꼴이다. 화면에는 같게 보인다. Furnace 글 직렬화가 "값이 빈 스타일" 과 "스타일 없음" 을 구별하지 않아서다. 대조 시험에서는 이 한 멤버만 이유를 적고 뺐다.
- 추천: 급하지 않음. 글 직렬화를 손볼 때 같이.

## 4. 대조 시험이 아직 못 보는 것 (다음 단계 할 일)
- 태그(예: "곡괭이로 캐는 블록")에 기대는 질문 — 대조용 바닐라 실행기에 데이터 팩 태그를 아직 싣지 않았다.
- 아이템 컴포넌트 값 넣기·마법 부여 — 값 씨앗과 레지스트리가 필요하다.
- 월드가 필요한 블록·아이템 동작 — 장면 차분기(T-253 후보) 몫.

## 알림: 개수 0 아이템의 최대 겹침 수(확인만, 결정 불필요)
- 예전 손 시험(#382)은 "개수 0 이 된 엔더 진주의 getMaxStackSize 는 16" 이라고 적었는데, 바닐라·Paper 1.21.1 jar 를 직접 보니 빈 스택은 컴포넌트를 비운 채로 읽어 **1** 이다. 값 견주기가 이 차이를 잡아 shim 을 바닐라와 같게 고쳤고 손 시험도 1 로 바로잡았다.
- 안 고치면: 개수 0 아이템을 다루는 플러그인이 바닐라 서버와 다른 숫자를 본다.
