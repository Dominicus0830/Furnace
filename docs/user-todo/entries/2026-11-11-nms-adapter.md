## 결정할 것

- **패킷 클래스를 생성할 때 무엇을 커밋할까?** 플러그인이 쓰는 게임 패킷은 40종이고 그중 25종은 플러그인 하나만 쓴다. 손으로 다 쓰면 범용이 아니라서 생성 도구를 쓰려 한다. 절대 규칙 7(바닐라 jar·생성 결과물 커밋 금지)과 닿는 부분이라 정해 주셔야 한다.
  - 추천: 손으로 쓴 중립 스키마(패킷 이름과 필드 타입 목록)를 커밋하고, 그 스키마에서 shim 클래스(이름·생성자·필드만, 직렬화 본문은 Furnace 패킷 인코더)를 빌드 때 만든다. 바닐라 jar 와 맞는지는 커밋하지 않는 로컬 도구로 확인한다. 지금 커밋된 NMS shim 11개와 같은 성격이다.
  - 다른 길: 바닐라 jar 를 읽어 만든 shim 소스를 그대로 커밋(규칙 7 위반 소지), 또는 40종을 손으로 쓰기(느림).
