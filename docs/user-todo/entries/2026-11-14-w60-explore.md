# 60명 동시 새 땅 탐험 — TPS·청크 생성 결정 (2026-11-14)

보고서: 공유 폴더 `furnace/reviews/w60-explore/W60-explore.md`(원자료·시제품 diff `repro/`), 독립 검토 `W60-review.md`(같은 시제품으로 25판 다시 돌려 숫자 재현, 이견 해소). 클라우드 4코어, 서버는 일반 사용자 권한, 60명 봇이 직접 위치 패킷으로 초당 5.6블록(전력질주) 이동. 노트북 수치와 섞지 않는다.

요약: 흩어져 탐험하면 TPS 는 괜찮고(19.7+) **생성 처리량**이 문제다(지금은 발밑 청크를 아무도 못 받는다). 스폰에서 같이 퍼지면 생성은 따라가지만 60명이 region 하나로 묶여 **TPS 10 안팎**(땅 높이에서는 7.8)이다. 앞쪽은 생성 대기열 재설계(T-170)와 빛 계산 분리(T-170a)로, 뒤쪽은 틱 재스케줄 규칙(T-171: TPS 9.3~11.6 → 12.4~15.0, 땅 높이 7.8 → 11.1, 미리 만든 땅 17.2)으로 고친다. 4코어에서 흩어진 60명 전력질주의 발밑을 다 채우는 것은 어떤 방법으로도 안 된다(필요량이 처리량의 2배 이상) — 미리 생성(pregen)이 운영 쪽 답이다.

1. **W-1 region 틱이 50ms 를 넘겼을 때 다음 틱(T-171).** 지금은 50ms 를 조금만 넘겨도 다음 틱을 한 칸(50ms) 더 쉰다 — 틱 53ms 가 TPS 10 이 된다. 바닐라는 밀린 만큼 쉬지 않고 이어 돌며(2초까지 따라잡기), Folia 는 따라잡지는 않고 바로 다음 틱을 돈다.
   - ① 바로 다음 틱, 따라잡기 없음(Folia 와 같음) — **추천**(검토도 동의). 계속 밀리는 서버에서는 바닐라와 결과가 같고, 잠깐 튄 뒤 몰아치기로 같은 스레드 풀의 다른 region 을 굶기지 않는다.
   - ② 바닐라처럼 밀린 만큼 이어 돌기(2초 한도).
   - ③ 지금대로(한 칸 쉼).
2. **W-2 생성 조절기 기본값(T-172).** 가장 느린 region 의 TPS 가 19 아래로 내려가면 동시 생성 수를 줄이고 회복하면 늘린다. 실측(1판): TPS 최저 4~6 → 9.8, 대신 생성 −35%·시야 채움 −8%p(발밑 0~2칸은 99.8% 유지).
   - ① 기본 꺼짐, 설정 키로 켬 — **추천**(1판뿐이고 생성을 줄인다).
   - ② 기본 켜짐.
3. **W-3 미리 생성 명령(T-175)을 만들지.** 이미 있는 P-O04-15(D9)와 같은 것. 같은 길을 미리 만든 땅에서 걸으면 서버 CPU 가 절반(278 → 136%), TPS 평균 17.2. 생성은 같은 생성기로 하므로 결과는 그대로다.
   - ① 만든다(낮은 우선순위로 T-170 대기열 맨 뒤, 진행률·중지·재개) — **추천.**
   - ② 지금은 안 만들고 Chunky 같은 플러그인을 쓴다(호환 계층이 받쳐 주면).
4. **W-4 생성이 모자랄 때 누구 먼저(T-170 공정성).** 시제품 "거리 우선" 대기열은 생성이 45~56개/초(지금 27~33)로 가장 많았지만, 그 이득은 사고에서 나왔다: 플레이어가 지나친 땅의 요청이 영영 뽑히지 않으면서 그 사람의 동시 요청 자리(16)를 막아, 흩어진 60명 중 약 30명이 90초 내내 발밑 청크를 하나도 못 받았다. 지나친 요청을 취소하고 자리를 돌려주면 아무도 영영 굶지 않지만, 동시 요청 수를 그대로 두면 생성이 23~26개/초로 떨어지고, 동시 요청 수를 같이 줄이면 31~35개/초로 돌아온다. 어느 쪽이든 만들어지는 블록은 같고 "누가 먼저 받느냐"만 다르다.
   - ① 굶김 없음 — 지나친 요청은 취소·자리 반납 + 서버 전체 동시 생성 예산을 작게(4코어 8~24, 값은 구현 PR 에서 측정해 정함) — **추천**(검토 권고와 같음). 혼자 탐험할 때 첫 시야가 늦어지지 않게 플레이어당 고정 상한이 아니라 전체 예산으로 나눈다.
   - ② 몰아주기 — 지금 시제품 그대로(총량은 가장 많지만 절반은 발밑을 못 받고, 탐험이 멈추면 아무도 없는 뒤쪽 땅을 그제야 만든다).
   - ③ 지나친 요청 자리 반납만, 동시 요청 수는 그대로(바닐라에 가장 가깝지만 총량 23~26개/초 — 비교용).
5. (알림, 결정 아님) 반론 X 의 "플레이어당 동시 요청 상한 16 → 4" 를 지금 대기열(FIFO) 위에 혼자 넣으면 60명에서는 생성이 오히려 줄었다(작성 3판 17~23개/초, 검토 2판 11.7~13.4). 상한을 줄이는 것은 거리 순서·지나친 요청 취소와 **함께**일 때만 이득이라 T-170 하나로 합쳤다(B2 의 T-110 대체, 반론 X 의 상한 제안 흡수).
6. (알림, 결정 아님) 장면 R 은 봇이 y200 에 떠 있어 몹이 덜 붙는다. "자연 스폰 52%"·"시뮬레이션 거리 6 은 효과 없음"은 그 장면 한정이고 땅 높이 장면으로 다시 잰다. 시뮬레이션 거리가 자연 스폰 범위(플레이어 128블록)를 줄이지 않는 것은 바닐라 1.21.1 과 같은 동작이다.
