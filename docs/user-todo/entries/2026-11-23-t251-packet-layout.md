# 패킷 모양 기계 추출 (T-251) — 결정·확인 항목 (2026-11-23)

## D1. 다음 단계를 어디까지 할까 (코디네이터가 추천대로 진행해도 되는 항목)
**지금 된 것:** 바닐라 서버 파일에서 패킷 모양(어떤 값이 어떤 순서·크기로 오가는지)을 기계가 뽑습니다. 사람이 옮겨 적은 스키마와 자동으로 맞춰 보고, 서버 코덱이 같은 바이트를 내는지도 시험합니다. 이번에 손 스키마 오류 1건(로그인 거절 메시지 형식)을 찾아 고쳤습니다. 서버가 실제로 쓰는 코드는 바뀌지 않았습니다.

**고를 것:** 이 다음에 무엇을 먼저 할까요?
- A (추천): 새 판용 스키마 뼈대(자바 필드 이름·타입까지)를 기계가 만들게 하기. 지금의 대조 시험이 정답 확인용으로 이미 있어 안전하게 갈 수 있고, 버전을 올릴 때 패킷 쪽 손작업이 거의 사라집니다. 서버 속도에는 영향이 없습니다.
- B: 서버가 패킷을 읽고 쓰는 코드 자체를 기계가 만들게 하기. 가장 많이 줄이지만 패킷은 서버에서 제일 자주 도는 곳이라, 손으로 쓴 것보다 느려지지 않는다는 측정이 먼저 필요합니다.
- C: 여기서 멈추고 다른 일 먼저.

**안 하면:** 지금도 "무엇이 바뀌었나" 목록과 "스키마가 맞나" 대조는 자동으로 나옵니다. A 를 안 하면 새 판 스키마 뼈대를 사람이 쓰는 시간(연구 추정으로 패킷 쪽 약 9시간 중 일부)이 남습니다.

**추천 근거:** A 는 서버 속도를 건드리지 않고 버전 올리기 시간을 줄이는 가장 안전한 길입니다. B 는 A 가 끝나고 속도 측정 계획을 세운 뒤에 판단하는 편이 좋습니다.

## 알림 (결정 불필요)
- `protocol-767.schema` 의 `login_disconnect` 사유를 `string` 와이어로 고쳤습니다(바닐라는 JSON 글자 한 덩어리, 서버 손 코덱은 이미 그랬음). 스키마를 쓰는 곳(shim 생성기·범용 코덱)은 login 단계 이 필드의 와이어를 읽지 않아 동작 변화는 없습니다.
- CI 의 vanilla-gates 에 "바닐라에서 다시 뽑은 잠금이 커밋된 것과 같은지" 한 단계를 더했습니다(바닐라 내려받기가 안 되면 기존 단계처럼 실패합니다).
