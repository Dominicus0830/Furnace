# T-210 바이옴 공급자로 만드는 월드 — 결정·확인 두 가지 (2026-11-17)

근거: `docs/feature-parity/compat-t210-biome-provider-worlds-2026-11-17.md`

플러그인이 "이 좌표는 무슨 바이옴" 을 정해 주는 코드(바이옴 공급자)를 넘겨 월드를 만들 수 있게 했다(Paper 와 같은 방식). 평지 월드에서 FAWE `//regen <바이옴>` 이 오류 나던 것(T-203 결정 D3)도 같이 고쳤다. 아래 두 가지는 추천안으로 이미 적용했다. 바꾸고 싶으면 알려 주면 된다.

## E1. 서버가 스스로 다시 열 때(자동 불러오기·`/worlds load`) 공급자 월드를 어떻게 할까

- 쉬운 말: 공급자는 플러그인 안의 코드라 파일에 저장할 수 없다. 그래서 서버를 다시 켜면 그 월드는 "공급자가 필요하다"는 표시만 남는다. Paper 는 서버가 추가 월드를 스스로 열지 않고 플러그인이 다시 만들 때까지 기다린다. Furnace 는 `furnace.properties` 의 `worlds.autoload` 와 `/worlds load` 로 스스로 열 수 있다.
- 예: 바이옴 플러그인으로 만든 `fantasy` 월드를 `worlds.autoload=fantasy` 에 넣어 둔 경우. 자동 불러오기는 플러그인이 켜지기 전에 돈다.
- 추천(적용함): 표시가 있는 월드는 자동 불러오기·`/worlds load` 에서 열지 않고 콘솔에 "이 월드는 바이옴 공급자 ○○ 로 만든 월드라 건너뜁니다 — 그 플러그인이 다시 만들 때 열립니다" 한 줄을 남긴다. 플러그인이 켜지면서 공급자와 함께 다시 만들면 정상으로 열린다.
- 이렇게 안 하면(바닐라 바이옴으로 연다): 서버가 플러그인보다 먼저 그 월드를 바닐라 바이옴으로 열어 버린다. 그 뒤 플러그인이 공급자를 주며 다시 만들어도 Paper 규칙대로 "이미 열린 월드"가 돌아와 공급자가 영영 안 붙고, 새로 생기는 청크가 바닐라 바이옴이 되어 경계가 생긴다(되돌릴 수 없다).
- 플러그인이 Bukkit `createWorld` 로 공급자 없이 다시 열면 Paper 와 똑같이 그냥 연다(콘솔 경고 한 번만 더함). 이건 플러그인이 고른 것이라 따른다.

## E2. 추가 평지 월드를 바닐라 평지 생성기로 바꿈(확인만)

- 쉬운 말: 지금까지 플러그인이 만든 평지 월드(`createWorld` 의 FLAT)는 층만 쌓는 간단한 생성기여서 마을·요새가 안 생겼다. Paper 는 기본 평지에 마을·요새가 생기고, `generatorSettings` 의 features·lakes·구조물 목록도 따른다. 바이옴 공급자를 평지에 붙이려면(D3) 바닐라 평지 생성기가 필요해서 같이 바꿨다.
- 예: `new WorldCreator("lobby").type(WorldType.FLAT).createWorld()` → 이제 Paper 처럼 마을·요새가 생긴다. 구조물을 원하지 않으면 `generateStructures(false)`(Paper 와 같다).
- 이미 있는 평지 추가 월드: 그 월드 `level.dat` 에 적힌 설정(구조물 없음)을 그대로 따라서 바뀌는 블록이 없다.
- Furnace 자체 API·`/worlds create … flat` 으로 만드는 새 평지 월드는 지금처럼 구조물·지형지물 없음(층만). Paper 와 같은 평지를 원하면 새 API `flatGeneratorSettings("{}")` 를 쓴다.
- 높이가 다른 차원 타입의 평지·빈 월드(VOID)는 전과 같다(공급자는 받지 않는다).
- 추천: 이대로(Paper 와 같음).

## 남은 것

- Bukkit `ChunkGenerator`(`WorldCreator#generator`)로 만드는 월드는 아직 안 된다(오류 메시지로 알림) — 로드맵 T-211 로 나눴다.
