# 탭 목록 이름 갱신 시점 차이 (영역 8, 2026-11-27)

**무슨 일인가?** 플러그인이 `setPlayerListName` 을 부르면 Paper 는 부른 그 자리에서 모든 접속자에게 이름 갱신 패킷을 바로 보냅니다. Furnace 는 접속자마다 담당 스레드가 다르고, 그 접속자의 탭에 이 플레이어가 아직 안 올라갔을 때 갱신을 보내면 클라이언트가 어긋나서, 각 접속자의 다음 틱(최대 50ms 뒤)에 보냅니다. 패킷 내용·받는 사람·횟수는 Paper 와 같습니다.

**예:** 플러그인이 이름을 바꾸자마자 바로 이어서 다른 패킷을 보내면, Paper 에서는 이름 갱신이 먼저 가고 Furnace 에서는 나중에 갑니다. 플레이어 눈에는 보이지 않는 차이입니다.

**안 하면?** 지금 상태 그대로 둡니다(눈에 보이는 차이 없음).

**추천:** 그대로 둔다. 정확히 같게 하려면 접속자별 탭 기록을 모든 스레드에서 안전하게 읽게 고쳐야 해서 비용이 큽니다.
