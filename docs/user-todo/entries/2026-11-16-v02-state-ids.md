# V-02 블록 상태 번호 이름 붙이기 — 결정할 것 (2026-11-16)

이 작업은 "결과가 바뀌지 않는 정리"라 지금 동작을 그대로 두었다. 그 과정에서 **옛 코드가 바닐라와 어긋나 있는 곳 두 군데**가 보였다. 둘 다 숫자를 이름으로 바꿀 때 지금 값을 그대로 이름에 묶어 두었고(`gradle/state-ids.spec` 맨 아래 "알려진 어긋남"), 고칠지는 도미니코가 정한다.

## 결정 1. 해초 심을 자리의 "딱딱하지 않은 바닥" 범위 두 곳을 바닐라대로 고칠까?

| | 지금(어긋남) | 바닐라 |
|---|---|---|
| 해초류 범위 | 해초·키다리 해초 **뒤로 3칸이 더 늘어** 피스톤(`extended=true`, 북·동·남 방향) 위에는 해초를 안 심는다 | 피스톤은 윗면이 단단해서 심을 수 있다 |
| 켈프 범위 | 켈프 `age=22~25` + 켈프 줄기만 "딱딱하지 않음"이라 켈프 `age=0~21` 위는 "딱딱함"으로 본다 | 켈프는 모두 윗면이 단단하지 않아서 해초를 못 심는다 |

- 쉬운 예: 바다 바닥에 피스톤이 있는 일은 월드 생성에서는 없고(구조물에도 없다), 켈프 위에 해초가 겹치는 일도 지형 높이 기준이라 사실상 없다. 그래서 **지금 월드가 달라지는 일은 거의 없다**.
- 안 하면: 지금과 똑같이 동작한다. 나중에 플레이어가 지은 구조물 위에 `/place feature` 같은 명령으로 해초를 심을 때만 바닐라와 다를 수 있다.
- 추천: **고친다**(별도 작은 PR). 고치면 `gradle/state-ids.spec` 의 두 줄에서 `+3`·`+22` 가감만 지우고 켈프 범위를 `kelp` 첫 칸부터로 바꾸면 되고, 월드젠 정답표 대조(오라클) 한 번으로 "정답표가 안 바뀜"을 증명할 수 있다. `StateIdsTest.해초_바닥_어긋남은_지금_동작을_그대로_둔_것이다` 가 그때 같이 바뀐다.

## 메모 (결정 아님)
- `ChunkColumn`·`TreeFeature` 에는 `CAVE_AIR`/`VOID_AIR` 이름이 서로 바뀌어 있었다(12958 은 `void_air`, 12959 가 `cave_air`). 둘 다 "공기"로 같이 쓰는 자리라 동작은 같았고, 이제 이름이 맞는 `StateIds.VOID_AIR`/`CAVE_AIR` 로 통일했다.
- 계획 문서가 말한 "엔티티 5개"(`Enderman`·`Display`·`Sniffer`·`Pillager`·`Armadillo`)는 블록 상태 번호가 아니라 **엔티티 메타데이터 칸 번호**(`DATA_*`)여서 V-04 몫이다. V-02 에서는 건드리지 않았다.
