# 호환 계층 명령·스케줄러 (H2) — 2026-11-07

H2 는 Bukkit 타입 없는 "호환 코어"까지 끝났다(`docs/feature-parity/compat-h2-2026-11-07.md`). Bukkit 클래스에 거는 부분은 아래 결정이 있어야 H1 이 붙일 수 있다.

- **결정:** `org.bukkit.*`·Paper API 클래스를 어떻게 들일지(H1 의 선행). 이 컨테이너에서는 paper-api·spigot-api 를 못 받는다(`repo.papermc.io`·`hub.spigotmc.org` 403). 후보: ① Paper API jar 를 `compileOnly` 로 받아 쓴다(빌드 환경이 `repo.papermc.io` 에 닿아야 하고, 라이선스를 확인해야 한다 — CI 는 지금 `-PskipOracle=true` 로 Paper 저장소를 피한다), ② Bukkit API 호환 인터페이스를 직접 다시 쓴다(저작권·유지 부담이 크다), ③ 사용자가 jar 를 저장소 밖 폴더에 두고 `-Pbukkit.api=경로` 로 받는다. 추천은 ①이고 라이선스 확인 뒤 진행. 답이 없으면 ① 을 조사만 한다.
- **직접 확인:** 실제 Bukkit·Paper 서버에서 권한 없는 플레이어가 plugin.yml 에 `permission:` 이 있는 명령을 치면 어떤 문장이 나오는지(거절 문장 vs `Unknown command`). Furnace 는 현재 트리에서 숨겨 "알 수 없는 명령"이 나온다. 거절 문장이 맞으면 `BasicCommand` 에 "트리 표시"와 "실행 허용"을 나누는 항목을 추가한다.
- **직접 확인(접속 시험, 권장):** 실제 클라이언트로 옛 방식 명령 하나(별칭·`usage`·탭 완성) 확인 — 자동 시험은 가짜 플레이어까지만 봤다.
