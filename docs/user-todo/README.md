# user-todo 항목 쓰는 법 (병합 충돌 방지 규칙)

**한 줄 규칙: 사용자가 직접 확인·결정할 새 항목은 `docs/user-todo.md` 를 고치지 말고 `docs/user-todo/entries/<YYYY-MM-DD>-<묶음 id>.md` 새 파일로 쓴다.**

## 왜
`docs/user-todo.md` 맨 위에 절을 추가하는 PR 이 모두 같은 자리를 건드려, 기준 브랜치가 움직일 때마다 병합 충돌이 났다(2026-11-06~07 이틀에 이 파일을 고친 커밋 67개, 충돌 해결 병합 커밋 수십 개). 작업마다 새 파일이면 서로 겹치지 않는다.

## 파일 형식
- 이름: `2026-11-07-m21.md` 처럼 날짜 + 묶음 id(소문자). 같은 묶음의 후속은 `2026-11-08-m21-followup.md`.
- 내용: 첫 줄이 `# 제목 (묶음 id) — 날짜` 인 절 하나. 아래에 근거 한두 줄과 "직접 확인·결정할 것" 항목을 `-` 목록으로 쓴다. **결정**이 필요한 것은 항목 앞에 `**결정:**` 을 붙인다.
- 끝난(사용자가 확인했거나 결정한) 항목은 그 파일을 지우거나 줄여도 된다. 코디네이터가 `docs/user-todo.md` 의 "완료·결정 기록"으로 옮긴다.

## 한 번에 보기
`tools/user-todo-combined.sh > /tmp/user-todo-all.md` — `docs/user-todo.md` 와 모든 항목 파일을 파일 이름 역순(날짜가 최신인 것 먼저, 같은 날짜 안에서는 id 역순)으로 합쳐 출력한다(저장소 파일은 안 바뀐다). CI 의 기준 브랜치 실행은 같은 결과를 `user-todo-combined` 산출물로 올린다.

## `docs/user-todo.md` 본문은 언제 고치나
1~3장(직접 확인 표, 결정 표, 코디네이터 항목)과 "완료·결정 기록"은 코디네이터가 정리할 때만 고친다. 작업 스레드는 고치지 않는다(이미 있는 줄의 상태를 바꿔야 할 때만 그 줄만 최소한으로).
