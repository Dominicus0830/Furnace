# 플레이어 불·투명·발광·탑승 (M20) — 2026-11-07
바닐라 바이트코드 대조(`context-notes.md` "M20")와 서버 시험(`PlayerPoseFlagsM20Test`, `RegionPlayerFireTest`)으로 확인. 실제 클라이언트로 남은 것:
- 용암에 들어가면 몸에 불이 붙은 모습이 보이고, 나와도 약 15초 동안 계속 타며 1초마다 하트 반 칸씩 닳다가 물(또는 비)에 닿으면 치익 소리와 함께 꺼지는지. 두 사람이 접속해 한쪽이 타면 다른 쪽 화면에도 불 붙은 모습이 보이는지.
- 불 블록 안에 가만히 서 있으면 약 1초(20틱) 뒤에, 걸어서 지나가면 약 0.5초 뒤에 불이 붙고, 영혼 불은 피해가 두 배인지. 불 보호 IV 방어구를 입으면 불이 붙은 시간이 눈에 띄게 짧아지는지(0.4배).
- 투명 물약을 마시면 다른 사람 화면에서 몸이 사라지고 방어구만 보이는지, 발광 효과(또는 발광 화살)를 맞으면 다른 사람 화면에서 외곽선이 보이는지.
- 좀비 머리를 쓰고 좀비 가까이 걸어가면 일반 상태보다 가까이 가야 좀비가 알아채는지(해골 머리는 해골에게만). 웅크리면 더 가까이 가야 알아채는지.
- 말을 타고 3칸 넘게 뛰어내려 착지하면 말과 함께 플레이어도 낙하 피해를 입는지(말 안전 거리 6·피해 ½배라 말은 덜 입고 플레이어는 말이 입은 만큼 입는다), 배를 타고 높은 곳에서 떨어져 땅에 닿을 때도 플레이어가 피해를 입는지.
- 두 사람이 접속해 한 사람이 배를 타고 좌우로 돌 때 다른 사람 화면에서 그 사람의 몸·머리 방향이 배를 따라 돌고 배 기준 ±105도를 넘지 않는지.

# 블록 잔여 (M17) — 2026-11-07
서버 시험(`BlockRemainderM17Test`·`BlockEntityLootTest`)으로 규칙은 확인(`context-notes.md` "묶음 M17"). 실제 클라이언트로 남은 것:
- 비교기 앞에 단단한 블록을 두고 그 뒤 칸에 아이템 액자(아이템 넣음)를 비교기 쪽으로 걸었을 때, 액자를 우클릭해 돌릴 때마다 비교기 출력이 1~8 로 바뀌는지(빈 액자는 0).
- 노트 블록 위에 `note_block_sound` 가 있는 머리(`/setblock ~ ~1 ~ player_head{note_block_sound:"minecraft:entity.creeper.hurt"}` 나 `/give @s player_head[note_block_sound="minecraft:entity.creeper.hurt"]`)를 올리고 두드리면 그 소리가 나는지, 소리 없는 머리는 조용한지.
- 꾸며진 항아리를 곡괭이로 캐면 금 가며 조각 4개(벽돌 포함)가 나오고, 섬세한 손길 곡괭이로 캐면 장식이 붙은 항아리 통째로 나오는지.
- 책이 놓인 연단을 부수면 책이 연단 앞쪽(바라보는 방향)에서 튀어 나오는지. 양조대에서 용의 숨결로 양조하면 남는 유리병이 양조대 칸 안에서 튀는지.
- 부싯돌로 TNT 에 불을 붙이면 부싯돌 내구도가 1 닳고(화염구는 1개 줄고, 크리에이티브는 둘 다 그대로), 가위로 호박을 깎으면 가위 내구도가 닳는지(통계 화면의 "사용함" 에도 올라가는지).
- 토끼가 가루눈 위를 걸어 다니고(가죽 장화를 신은 좀비도; 가죽 장화를 신은 본인이 걸어 봤을 때 바닐라와 같은지도), 일반 몹은 가루눈에 빠지는지. 모래를 2칸 안쪽 높이에서 떨구면 가루눈 위에 얹히지만 높은 곳에서 떨구면 부서져 아이템으로 떨어지는 것이 바닐라와 같은지.
- `/summon falling_block ~ ~5 ~ {BlockState:{Name:"minecraft:barrel"},TileEntityData:{Items:[{Slot:0b,id:"minecraft:diamond",count:3}]}}` 로 떨군 통이 내려앉은 뒤 다이아 3개를 담고 있는지.

- 스컬크(M2): 데이터 팩이 만든 `minecraft:mob_experience` 인챈트(처치자 보정 경험치)는 반영하지 않는다 — 1.21.1 기본 데이터에는 쓰는 인챈트가 없다

### 알려진 차이
- 다차원(M10 에서 고침, 2026-11-07): 보더는 차원별(네더 중심 1/8), 좀비 피글린 생성은 있다. 남은 차이: 목적 청크를 디스크에서 읽거나 새로 만들어야 하면(엔티티가 처음 가는 곳 — 플레이어는 포털 대기 중 미리 올린다) 그동안 도착이 늦다. 바닐라는 그 틱에 서버 전체를 멈추고 만든다
- 수면·리스폰: 밤 건너뛰기 후 깨우기는 플레이어가 속한 region 의 다음 작업 때 한다(전역 스레드가 region 의 플레이어를 직접 만지지 못해서 — 결과는 같고 최대 한 틱 차이). 추가 월드(W1)는 바닐라 DerivedLevelData 처럼 그 월드 접속자만 세어 충분히 자면 깨우기만 한다(시간·날씨는 오버월드 것이라 그대로) **(M10)**
- 명령: `/give` 이후 여러 명령(`/data`, `/execute`(일부), `/clone`, `/fillbiome` 등)은 실접속 미확인. `/execute store` 는 S3~S4 에서 **(M11)**
- 구조물 블록은 그 region 에서 로드된 청크만 다룸(범위 밖이면 저장/불러오기가 아무 일도 안 함). 직소 "생성"은 노이즈 월드(내장 풀)에서만 된다. **(W4)**

### 서버 성능 관찰
- ~~플레이어 2명부터 청크 전송이 1명일 때보다 약간 느림~~ → **M12(2026-11-07)에서 원인 두 가지를 고침**: ① 여럿이 새 땅을 돌면 서버 종료 때 IO 대기열이 밀려 생성 청크의 약 42%가 저장되지 않고 사라져, 재시작 뒤 그 땅을 다시 생성했다(이미 가 본 곳이 1.5초 → 11초). 이제 종료·`save-all` 은 대기열이 빌 때까지 나눠 저장한다. ② 디스크에서 읽은 청크의 빛 다시 계산이 CPU 의 약 40% — 결과가 같은 빠른 경로로 청크당 1.09 → 0.35ms. 남은 차이는 CPU 몫(4코어에서 서로 떨어진 4명이 동시에 새 시야를 받으면 1명보다 약 1.3배). 측정 `docs/feature-parity/perf-multiplayer-chunks-2026-11-07.md` **보완(압축 중복, 같은 날):** 같은 청크를 여럿에게 보낼 때 이벤트 루프마다 중복 압축하던 것을 청크 풀에서 한 번만 하도록 고침 — `docs/feature-parity/perf-m12-2026-11-07.md`, 실접속 확인은 맨 위 "여러 명 청크 전송 — 압축 중복 제거"

### region 정보 API · zstd 압축 (W5, 2026-11-06)
- `World.regionAt(청크)`·`regions()` → `RegionInfo`(청크 수·범위·소유 워커 스레드·최근 5초 TPS·직전/최장 틱). 플러그인은 `Furnace.server().world(...)` 로 읽는다.
- `region-file-compression=zstd` 는 **기본 꺼짐**이며 바닐라·Paper 가 그 월드를 못 연다(종류 바이트 5, 서버 시작 때 경고). 되돌리기·변환: `java -cp furnace-server.jar org.domi.furnace.server.world.anvil.RegionConvert <월드 폴더> <deflate|zstd|…>` (서버를 끈 채). 순수 자바(aircompressor 0.27).

### 생성 청크 저장 (F-14) 주의
- 생성만 한 청크도 디스크에 남아 탐험한 만큼 월드 폴더가 커짐(크기 제한 없음). 디스크 여유 확인
- 한 번 저장된 청크는 이후 월드젠 수정이 반영되지 않음. 월드젠 parity 를 실제 서버로 볼 땐 새 월드로 또는 `region/` 삭제 (`docs/feature-parity/f14-generated-chunk-save-2026-10-27.md`)
