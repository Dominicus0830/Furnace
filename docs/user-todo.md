# 플러그인 API 3단계 셋째 묶음 — 번짐·마법부여·탈것·낚시·스폰 (2026-11-06)

봇(`tools/bot-test/round5/ev.js` + 시험 플러그인 `round5/probe`)으로 31개 항목 통과. 실제 클라이언트로 남은 것:
- 플러그인이 피스톤·물 흐름·성장·불·화로·깔때기를 취소했을 때 화면이 서버 상태와 어긋나지 않는지(끈끈이 피스톤 줄이기 취소는 봇에서 머리가 남아 보이던 것을 고쳤다).

봇·오프라인 서버·바닐라 바이트코드 대조로 확인할 수 있는 것은 이미 돌려 지웠다(`docs/feature-parity/bot-connection-test-2026-11-06.md`). 이전 시험 상세는 `docs/feature-parity/user-test-bugs-2026-10-27.md`.

## 1. 직접 확인할 것 (실제 클라이언트에서만 볼 수 있음)

봇(mineflayer)은 화면·소리를 보지 못하고 이동도 바닐라 클라이언트가 아니라 mineflayer 물리로 계산한다. 아래는 실제 클라이언트로 한 번씩 봐 주시면 된다. 서버 쪽 동작은 모두 봇·서버 시험으로 이미 확인했다.

| 묶음 | 볼 것 | 기대 결과 / 문제 있으면 알릴 것 |
|---|---|---|
| 이동 자세 | 웅크림(몸통 1.5칸), 수영·기어가기, 높이 1칸 물 터널, 트랩도어 아래 기어가기, 다락문+사다리 칸 오르내리기, 급류 삼지창, 겉날개 | 이유 없이 뒤로 끌려가지 않음. 끌려가면 서버 로그의 `moved wrongly` / `moved too quickly` 줄과 상황을 알려 주세요 |
| 탈것 조종 | 돼지(당근 낚싯대)·스트라이더(뒤틀린 균류 막대)를 타고 걷기, 차가운 땅에서 떠는 스트라이더 탄 채 | 막대 방향으로 감. 떨 때 느려짐 |
| 손맛 | 성급함·채굴 피로 상태의 채굴 속도, 영혼 가속·민첩한 웅크리기 체감 속도 | 바닐라와 같은 느낌 |
| 화면 | 체력바 위 방어구 아이콘, 피격 방향 기울기, 체력 강화·속도 효과의 체력바·이동 속도 반영, 엔더의 눈 비행, 철퇴 충격파, 엔드 관문 빔, 전달체(2026-11-06 새로 구현) 회전·눈이 공격 대상을 바라봄 | 바로 보이고 바닐라와 같음 |
| 렌더 거리 | 옵션에서 렌더 거리를 줄였다 늘리기(움직이지 말 것), 플러그인 `setViewDistance` 로 줄였다 늘리기 | 먼 청크가 바로 다시 보임 |
| 큰 리소스팩 | `resource-pack=<큰 팩 URL>` + `require-resource-pack=true` | 30초 넘게 걸려도 끊기지 않고 입장 |
| 운영 옵션(O1) | `furnace.properties` 에 `server-brand=내서버` → F3 의 서버 브랜드, `confirm-interrupt=true` → 콘솔 Ctrl+C 한 번은 안내만·5초 안에 두 번째에 종료, `announce-sleep-status=false` → 침대에서 "x/y 명 자는 중" 액션바 없음 | 설정대로 동작. 꺼 두면(기본) 바닐라와 같음 |
| 소리 (귀로) | 털 깎기·안장·삼지창 등 움직이는 몹에서 난 소리가 몹을 따라가는지, 염소 뿔 소리가 "음반/소리 블록" 음량 설정을 따르는지, 종·자수정·첨벙 소리 | 바닐라와 같음 |
| 플러그인 취소 화면 | 플러그인이 웅크림·칸 변경·비행·피스톤·물 흐름·성장·불·화로·깔때기를 취소했을 때 | 화면이 서버 상태와 어긋나지 않음. 끈끈이 피스톤 줄이기는 봇에서 고쳤으니 다시 확인 |
| 플러그인 레시피 (D1) | 플러그인이 `Furnace.recipes()` 로 레시피를 등록·제거한 뒤 접속 중인 클라이언트의 제작대·2×2·레시피 북, 레시피를 내린 뒤 레시피 북 목록 | 등록한 레시피가 바로 맞고 내리면 사라짐. 서버는 `update_recipes` 를 다시 보내고 `recipe` REMOVE 로 잊게 함 — 클라이언트가 목록 갱신을 그대로 받아들이는지 화면에서만 확인 가능 |
| F 키 손 바꾸기 | 두 손이 바뀌고 다른 사람에게도 보이는지, 먹는 중에 바꾸면 멈추는지 | 바닐라와 같음 (2026-11-04 새로 구현) |
| 주민 문 (U3) | 문 앞 주민이 다시 안 열리는 상황을 보시면 가까운 주민에게 `/data get entity @e[type=villager,limit=1,sort=nearest] Brain.memories` 결과를 알려 주세요 | 코드는 바닐라와 줄 단위로 같음. 재현될 때만 필요 |
| 구조물 블록 편집 화면 | 구조물 블록(창조 모드·OP)을 우클릭 → 저장/불러오기/모서리/데이터 모드 전환, 이름·오프셋·크기·"크기 감지"·무결성·시드. 모서리 블록 두 개를 놓고 저장 블록에서 "감지"를 눌러 상자가 잡히는지 | 화면이 열리고 값이 저장됨 (봇 9차 `round9/structure.js` 로 패킷·저장·불러오기는 통과) |
| 구조물 경계 표시 | 구조물 블록을 켜고 보면 경계 상자·모서리 표시, 불러온 구조물이 눈으로 바닐라와 같은지(계단 방향·문·침대·상자 내용) | 바닐라와 같음 |
| 직소 블록 화면 | 직소 블록 우클릭 화면(풀·이름·대상·최종 상태·결합 종류·우선순위)과 "생성" 버튼이 마을 같은 조각을 펼치는지(노이즈 월드) | 바닐라와 같음 |
| 외부 프로그램 | 바닐라 1.21.1 `region-file-compression=lz4` 월드 ↔ Furnace, 실제 Paper/Spigot 월드 폴더로 첫 기동, 실제 BungeeCord(`ip_forward: true`) 뒤 접속, Fabric 클라이언트 접속 | 이 환경은 Mojang·papermc·md-5 호스트가 막혀 못 돌림. lz4 형식은 바닐라 바이트코드와 대조해 같음 |
| PROXY 프로토콜 (N2) | `furnace.properties` 에 `proxy-protocol=true` (+ `proxy-protocol.trusted=<HAProxy 주소>`) 를 두고 실제 HAProxy(`send-proxy-v2`)나 nginx stream(`proxy_protocol on`) 뒤로 접속 | 접속은 되고 서버 로그·`/ban-ip`·플러그인이 프록시가 아니라 실제 클라이언트 IP 로 봄. 헤더 없는 직접 접속은 거부됨. 이 환경에는 앞단 프로그램이 없어 EmbeddedChannel·소켓 시험까지만 함 (`docs/feature-parity/connection-defenses-2026-11-06.md`) |
| 구성 단계 리소스 팩·쿠키 (N1) | 플러그인이 `AsyncPlayerConfigureEvent` 에서 `connection().sendResourcePack(...)`·`requestCookie`·`storeCookie`·`transfer` 를 부르게 해 실제 클라이언트로 접속 | 팩 받기 화면이 뜨고 끝나면 입장, 필수 팩 거절 시 "서버 리소스 팩 필요" 로 끊김, 쿠키를 다시 접속해도(전송 뒤에도) 읽힘. 구성 패킷 번호(0x00·0x08·0x0A·0x0B)는 문서·기억 기준이라 이 확인이 실제 클라이언트로 처음 보는 것 |

## 2. 내가 결정할 것

| 항목 | 지금 상태 | 정하면 되는 것 |
|---|---|---|
| **RCON IP당 연결 상한 4** | 같은 기계에서 RCON 도구(패널·봇 등)를 4개보다 많이 동시에 쓰면 막힘 | 4개보다 많이 쓰는지 알려 주면 상한 조정. RCON 은 평문이라 공개 포트에 열지 말고 방화벽·loopback 권장. 인증 실패 제한(연결당 5회, IP당 60초 10회)과 연결 상한 16 때문에 NAT 뒤 관리자도 막힐 수 있음 |
| **BungeeCord 레거시 포워딩** | 구현됨, 기본 꺼짐 (`bungeecord=false`). 사용자가 지원을 정한 것이 아니라 미구현 목록에서 고른 후보 | 지원할지. 서명이 없어 포트가 열려 있으면 누구나 아무 UUID 로 들어올 수 있음 → 켠다면 방화벽으로 프록시만 허용. 새 프록시는 Velocity 모던 포워딩(`velocity-secret`) 권장. 두 설정은 함께 켤 수 없음(기동 실패) |

| **공유 스케줄러 S4 기본값** | 병합됨, 기본 꺼짐. 켜는 법 `-Dfurnace.sharedRegionPool=true` | 기본값을 켤지. 부하 5ms 에서 지연은 줄었으나 간헐적 40~60ms 튐 원인 미확인 (`docs/feature-parity/shared-scheduler-s4-2026-10-28.md`) |

## 3. 코디네이터가 이 파일에 필요하다고 보는 항목

### 미구현
- 영혼 가속의 입자·소리, 몹 착지 블록 입자
- 게임 이벤트: 낙타 돌진, 스폰 알 물에 쓰기 (`entity-game-events-2026-11-03.md`)
- 전체 미구현 목록: `docs/feature-parity/unimplemented-survey-2026-10-31.md`, `mob-ability-audit-2026-10-31.md`
- 마인카트: 상자/깔때기 수레·상자 배 창, 스포너·명령 블록 수레 동작, 디스펜서 설치, 몹이 수레를 미는 처리
- 약탈자·습격: 습격자 목표 AI(깃발·마을 이동·축하). 습격은 "나쁜 징조" 상태로 마을에 들어가야 시작. 테스트는 `/effect give @s bad_omen`. 차이: 내려간 청크의 POI 는 조회 안 됨, 같은 거리 POI 선택 순서
- 플레이어 전투: 쓸기/피해 파티클(level_particles 패킷 없음), 힘·나약함 효과 반영, 철퇴, 살충 느림
- 엔티티 창: 깔때기 수레 빨아들임, 라마 카펫 칸, 이름표 창 제목
- 지도 깃발: 무늬 컴포넌트→블록 엔티티 변환, 깃발 부술 때 이름·무늬 드롭, 네더 지도
- 워든·진동: 진동·음파 파티클, 걸음 소리, 알레이 진동 수신
- 깔때기·용기: 용기 엔티티 전리품 표 풀기, VindicatorBreakDoorGoal
- 스컬크: 스컬크 영혼 파티클, 발전 과제, 플레이어 사망 경험치 흡수
- 주민: 밭 수확·뼛가루, 거래 보여주기, 영웅 선물, 생성 이유별 종류/직업 설정, 철 골렘 평판 -100 플레이어 공격, 발전 과제, 스포너 경로 finalizeSpawn
- 주민 소문·평판·특별 가격(거래 평판, 좀비 주민 치료 할인, 마을의 영웅): 나중에 확인하기로 함
- 엔더 드래곤: 활성 출구 포털 판정(관문 블록 엔티티는 생겼으나 hasActiveExitPortal 은 받침대 블록으로 판정), 공격 후 마법 부여 효과, 사용자 이름 보스 바
- 블록 엔티티: 스포너 승객/장비, 벌집, 표지판 텍스트 선택자/점수 해석
- 수면: 자는 중 텔레포트·차원 이동 시 깨우기
- 명령: 명령 블록 등 (`/tick sprint` 는 구현됨). 순서는 `docs/feature-parity/roadmap-2026-10-09.md`

### 가정 (바닐라 jar 대조 필요)
- 약탈자 순찰: 저장 키 `patrol_target`, 마녀 지도자 불가, 불길한 깃발 이름 스타일
- 깔때기·용기: 양조기 연료 칸은 블레이즈 가루만
- 스컬크: SculkBehaviour 구현 블록은 스컬크·맥뿐, 경험치 보정(처치자·마법 부여) 없음
- 주민: 심을 씨앗 태그 `villager_plantable_seeds` 를 바닐라 기본값으로 고정(데이터팩 변경 미반영)

### 알려진 차이
- 다차원: 차원 이동이 비동기라 몇 틱 늦게 도착, 보더 차원 공유, 네더 포탈에서 좀비 피글린 미구현
- 수면·리스폰: 밤 건너뛰기 후 깨우기가 다음 region 틱, 자는 중 접속 종료 시 침대 위 위치 저장(바닐라는 일어선 자리), 네더·엔드 기본 스폰 (0,64,0) 전송
- 표지판: JSON 직렬화가 바닐라와 바이트 동일한지 확인 못 함 (클라가 파싱하면 문제 없음)
- 명령: `/give` 이후 여러 명령(`/data`, `/execute`(일부), `/clone`, `/fillbiome` 등)은 실접속 미확인. `/execute store` 는 S3~S4 에서
- 구조물 블록은 그 region 에서 로드된 청크만 다룸(범위 밖이면 저장/불러오기가 아무 일도 안 함). 직소 "생성"은 노이즈 월드(내장 풀)에서만 된다.

### 서버 성능 관찰
- 플레이어 2명부터 청크 전송이 1명일 때보다 약간 느림(N-05 청크 스냅샷 보관 제거 이후). 측정 항목으로 남김

### 생성 청크 저장 (F-14) 주의
- 생성만 한 청크도 디스크에 남아 탐험한 만큼 월드 폴더가 커짐(크기 제한 없음). 디스크 여유 확인
- 한 번 저장된 청크는 이후 월드젠 수정이 반영되지 않음. 월드젠 parity 를 실제 서버로 볼 땐 새 월드로 또는 `region/` 삭제 (`docs/feature-parity/f14-generated-chunk-save-2026-10-27.md`)
