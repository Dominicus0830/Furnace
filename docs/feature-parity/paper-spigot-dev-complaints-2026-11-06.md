# Paper·Spigot 개발자·운영자 불만과 요청 — Furnace 에서 풀 수 있는 것 (2026-11-06)

플러그인 개발자와 서버 운영자가 Paper·Spigot(Bukkit)을 쓰면서 하는 말을 모았다.
"왜 이 기능이 없지?", "왜 이걸 막아 놨지?", "이걸 쉽게 쓰게 해 주면 좋겠다", "이걸 고치고 싶은데 안 된다" 같은 것들이다.
그 가운데 Furnace 구조로 풀 수 있는 것을 3장 표에 모두 정리했다.

- 이어받은 문서: `docs/furnace-community-wishlist.md`(2026-10-26 기획 노트, 이 문서에서는 `[W번호]`로 부른다). 그 문서는 Furnace 가 크리에이티브 전용이던 시기에 썼다. 이번 문서는 지금 코드를 기준으로 하고, **GitHub 이슈의 실제 반응 수**를 새로 붙였다.
- Paper·Spigot 대비 미구현 목록은 `paper-spigot-gap-2026-11-03.md` 에 따로 있다. 이 문서는 "따라잡기"가 아니라 **Paper·Spigot 이 해 주지 않아서 사람들이 불편해하는 것**을 다룬다.
- 이 표를 스레드 단위 작업 묶음 37개로 나눈 문서: `work-packages-2026-11-06.md`(모델·노력치·순서·선행 포함).
- 결정이 필요했던 5개(D1~D5)는 5장에 있다. 2026-11-06 사용자가 모두 제안대로 수용했고, 1.21.1 이후 버전도 지원할 계획이라 API 는 버전 중립으로 설계한다(5장 추가 방침).

## 2. Furnace 의 출발점 (지금 코드 기준) [F]

3장 표의 "Furnace 방식"이 왜 가능한지의 근거다.
- **서버 코드를 처음부터 직접 썼다.** 바닐라 패치가 아니라서 이벤트·훅을 원하는 지점에 바로 넣을 수 있다. 1.21.1 고정이라 프로토콜·데이터 형식이 바뀌지 않는다.
- **region 멀티스레드가 기본**이고, API 는 처음부터 `CompletableFuture`·소유 스레드(`Owned`/`ThreadOwner`)·`EntityScheduler`·region 스케줄러 전제다(`furnace-api/.../sched`, `entity/EntityScheduler.java`). `Entity.teleport` 는 비동기다.
- 이벤트 버스는 `GameEvents.has(type)` 로 **구독자가 없으면 객체 생성·스레드 이동을 생략**한다(`plugin/GameEvents`, `PluginGameEvents`). 이벤트를 많이 넣어도 안 쓰면 비용이 없다.
- 이벤트 85종 안팎(플레이어 30·블록 14·엔티티 11·인벤토리 9·서버 5·월드 3 등), PDC(엔티티·청크·플레이어, Paper 와 같은 저장 키), 텍스트(Adventure 비슷한 `Text`, MiniMessage 비슷한 `TextMarkup`, 번역 `TranslationStore`), 설정 파서(YAML·TOML·JSON), 권한, 명령 레지스트리, 메뉴 프레임워크(서버 내부).
- 플러그인 로더: `depend`/`softdepend`/`loadbefore` 위상 정렬, 플러그인 예외 격리(`EventBusImpl`·`PluginManagerImpl` 의 catch), `FurnacePlugin` 은 인터페이스라 기반 클래스 강제가 없다.
- 운영: 단일 `furnace.properties`, `/tps`·`/mspt`, lz4 지역 파일, BungeeCord·Velocity 포워딩, Paper/Spigot 월드 폴더 가져오기, RCON·Query·워치독·크래시 리포트, `/furnace profile`·`/jfr`.
- **아직 없는 것**: Bukkit/Paper 플러그인 실행 어댑터(5단계 `furnace-compat-paper`), 스코어보드·보스바·월드보더 API, 아이템 컴포넌트·아이템 PDC, 패킷 API, 다중 월드(차원 외 추가 레벨) 등(`paper-spigot-gap-2026-11-03.md`).
- **원칙**: 결과물(관측 동작)은 바닐라와 같아야 하고, 내부 구현·성능은 자유다(`AGENTS.md`, 프로젝트 지시). 바닐라 결과를 바꾸는 기능은 **기본 꺼짐 옵션**으로만 둔다.

## 5. 사용자 결정 (2026-11-06 결정 완료 — 다섯 개 모두 아래 제안대로 수용)

**추가 방침(2026-11-06 사용자)**: 1.21.1 이후 마인크래프트 버전도 지원할 계획이다. 그래서 이 문서에서 "1.21.1 고정이라 안정"이라고 쓴 부분(28·48·89·107번, D2·D5)은 이렇게 읽는다.
- 플러그인 API 는 마인크래프트 버전에 묶이지 않는 타입으로 만든다(아이템 컴포넌트는 버전별 열거형이 아니라 레지스트리 키로, 버전에만 있는 키는 "이 버전에 없음"을 돌려준다).
- 패킷 API(D2)는 서버 내부 패킷 레코드를 그대로 내보내지 않고, 버전 중립 패킷 타입 + 버전별 변환 계층으로 둔다. 원시 패킷 접근이 필요하면 프로토콜 버전을 함께 받는 별도 저수준 API 로 분리하고 "버전마다 깨질 수 있음"을 명시한다.
- API 버전(D5)은 마인크래프트 버전과 따로 매긴다. 새 마인크래프트 버전 지원은 API 마이너 올림으로 처리하고, 없어진 게임 기능은 폐기 기간을 거친다.
