### 2단계 — 서버 뼈대 (월드젠 직후, 온라인 모드 포함)
이 순서는 앞 단계가 뒤 단계의 전제이기 때문이다.
1. ✅ **설정·파일**: `server.properties` 전체 키셋, `eula.txt`, `ops/whitelist/banned-*.json`, `usercache.json`, 로그 파일, 시작 스크립트. 시드 빈 값=무작위.
2. ✅ (구조물 시작점 직렬화 제외) **`level.dat` + 월드 형식**: 시드·스폰·시간·게임룰·DataVersion, `session.lock`, 청크 NBT에 바이옴·구조물 시작/참조·InhabitedTime 저장, 모르는 NBT 보존(새 블록을 공기로 지우는 영구 손실 방지).
3. ✅ **온라인 모드**: 암호화(RSA-1024 서버키, 검증 토큰, AES/CFB8 스트림) → `sessionserver.mojang.com/hasJoined` 호출(비동기, 타임아웃·재시도) → 프로필 속성 → UUID. 로그인 게이트(밴·화이트리스트·가득 참·중복 접속), 상태 JSON(online/max/sample/favicon). 프록시 전달(Velocity modern forwarding)은 이 단계에 옵션으로 포함.
4. ✅ (기본 명령 일부) **명령 프레임워크**: Brigadier, `commands` 패킷, 자동완성, 권한 레벨(0~4), 콘솔 stdin. 기본 명령(`stop op deop whitelist ban kick say list tp gamemode time weather give seed locate …`)을 데이터 주도로.
5. ✅ **서명된 채팅**: 채팅 세션 공개키 검증(Mojang 공개키 서명), `player_chat` 서명 검증·메시지 체인·last-seen 윈도우, `system_chat`·`disguised_chat`, 서명 없는 명령 인자(`chat_command_signed`), 신고용 서명 보관.
6. ✅ **시간·날씨·난이도·월드 보더·게임룰**: 전역 틱 배리어(지금 없음)와 함께.
7. ✅ **게임모드·체력·허기·피해·사망·리스폰·경험치.** (드롭·블록 피해·방어구는 3단계)
8. **플러그인 API v0** (아래): 명령 등록·이벤트 버스·권한·스케줄러·설정이 2~5단계와 같은 지점이므로 같이 노출한다.

### 3단계 — 게임플레이 코어 (작은 세로 조각으로)
데이터 주도 기반부터: 데이터 팩 로더 → 전리품 표(1,178)·레시피(1,290)·발전 과제(1,399) → 아이템 컴포넌트 → 블록 상태 설치/파괴/이웃 업데이트·틱·유체 → 아이템 엔티티·컨테이너 → 빛 엔진 → 엔티티(몹·동물·투사체·전투) → 차원·포털 → 진행 시스템(발전·통계·점수판·보스바·포션/속성). 월드젠 시점 몹 스폰·스포너·구조물 상자 내용물은 전리품 표 이후에 연결.

### 4단계 — Paper 동작·운영·성능
Paper 설정 파일 키(`paper-*.yml`, `spigot.yml`, `bukkit.yml`)와 기본 동작 차이 목록 작성 → 구현, `/tps /mspt /version /plugins /timings`, 안티 엑스레이, 스폰 한도·엔티티 활성 범위, RCON/Query/메트릭, 크래시 리포트·워치독, CI·배포(Docker/fat jar). 성능 작업(청크 생성 병목, 네트워크 flush 합치기, 적응형 청크 전송, 리전 파일)은 1~3단계 사이사이에 출력 불변을 확인하며 병행.

### 5단계 — 플러그인 호환 어댑터 (별도 모듈 `furnace-compat-paper`)
`furnace-api` 위에 Bukkit/Paper API 구현체를 얹어 `plugin.yml` 기반 jar를 로드. NMS/CraftBukkit 내부를 건드리는 플러그인은 범위 밖으로 명시. 5단계에서 새로 만들어야 하는 것은 "API 이름 매핑·이벤트 변환·스레드 모델 에뮬레이션"뿐이 되도록 1~2단계에서 아래 원칙을 지킨다.

## 어댑터 대비 설계 원칙 (`furnace-api`를 지금부터 이렇게 만든다)
1. **이벤트 모델을 Bukkit 호환 의미로**: 우선순위(LOWEST~MONITOR), `ignoreCancelled`, 취소 가능, 동기/비동기 구분, 핸들러 등록은 리플렉션 없이도 가능하되 어노테이션 방식도 지원. 이벤트 이름·필드는 Bukkit과 1:1 변환이 쉽게 (`PlayerJoinEvent`, `BlockBreakEvent` …).
2. **스레드 모델 명시**: Furnace는 지역(region) 스레딩. Bukkit 플러그인은 "메인 스레드 한 개"를 가정하므로, 어댑터가 쓸 **전역 직렬 실행기(global region)**를 API에 일급으로 둔다. 모든 API 호출에 "어느 스레드에서 호출 가능한가"를 문서화(`@Owned`/`ThreadOwner`가 이미 있음).
3. **레지스트리 이름 기반**: Material·BlockData·EntityType·Enchantment 등은 바닐라 레지스트리 키로 식별(`minecraft:oak_log`)하고, 어댑터가 Bukkit enum으로 매핑. 자체 정수 id를 API에 노출하지 않는다.
4. **텍스트는 자체 `Text` 타입** (2026-10-10 결정 변경): Furnace 플러그인은 자체 불변 `Text`(구조는 Adventure 와 1:1 대응 — 내용 6종·스타일·클릭/호버)를 쓰고, 마크업은 MiniMessage 문법 호환. Adventure 는 의존하지 않는다. Paper 플러그인 어댑터가 경계에서 Adventure `Component` ↔ `Text` 를 변환한다.
5. **명령·권한·완성**: Bukkit `CommandMap`/`Permission`(기본값 op/true/false, 상속)과 변환 가능한 구조. Brigadier 노드와 레거시 문자열 명령이 공존.
6. **플러그인 로더**: `plugin.yml` 호환 필드(name·version·main·depend·softdepend·loadbefore·api-version·commands·permissions)를 읽는 디스크립터와 클래스로더 격리를 처음부터 구현(자체 형식은 `furnace-plugin.yml|toml|json`. `plugin.yml` jar 는 `plugins/bukkit-plugins/`에 두고 어댑터만 읽는다).
7. **저장 데이터**: `PersistentDataContainer`(NBT 태그)를 엔티티·아이템·청크·월드에 일관 제공.
8. **스케줄러**: 틱 지연/반복 + 비동기 + 지역/엔티티별(Folia식)을 이미 가진 `FurnaceScheduler`를 그대로 확장.
9. 서버 내부 클래스(`org.domi.furnace.server.*`)를 API가 노출하지 않는다.

## 검증 방법 (영역별)
- 월드젠: 순정 서버 월드와 블록 단위 대조(Harness/StructCmp), 순정 2회 대조로 잡음 바닥 측정.
- 프로토콜: 순정 jar의 `StreamCodec`으로 Furnace 패킷을 디코드해 형식 검증, 같은 봇을 순정/Furnace에 접속시켜 시퀀스 차분.
- 암호화·인증·서명 채팅: 순정 클라이언트 대신 순정 `net.minecraft` 코드(서버 jar)의 서명 검증기를 오라클로 사용한 단위 테스트. 실제 Mojang 인증 서버 호출은 이 환경에서 막혀 있어 로컬 모의 세션 서버로 시험하고, 실서버 확인은 사용자 환경에서.
