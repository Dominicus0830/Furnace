# T-141 E4a: Bukkit 게임 규칙 API (2026-11-15)

FAWE 2.16.2 남은 구멍(`World#setKeepSpawnInMemory`, `ComplexEntityPart`)과 B6 코퍼스 `org.bukkit.GameRule`(4 플러그인·8곳)을 채운다.
기준은 Paper 1.21.1 `GameRule`·`CraftWorld` 게임 규칙 메서드와 Paper 33ff3dff `Add-WorldGameRuleChangeEvent.patch`.

## 무엇을
- `org.bukkit.GameRule`: Paper 와 같은 51 상수·같은 선언 순서. equals 는 이름·형, hashCode 는 Object 그대로, values() 는 이름 HashMap 순서(Paper 와 같은 표).
  Paper 는 Adventure `Translatable` 을 구현하지만 호환 계층은 Adventure 를 싣지 않아 `translationKey()` 메서드만 둔다.
- `World` 게임 규칙 메서드 7개 + `get/setKeepSpawnInMemory`(Paper 1.21.1: spawnChunkRadius > 0 / 켜면 기본값 2, 끄면 0).
  - `getGameRuleValue(String)`: null → null, 모르는 이름 → ""(Paper 는 배열 저장 패치로 null 키면 null 값 → ""). 예전 Furnace 는 null 을 줬다.
  - `setGameRuleValue`: null 인자·모르는 이름 → false, 빈 이름 → IAE(isGameRule 검사). 정수 규칙 값은 바닐라 `deserialize`(빈 문자열·숫자 아님 → 0, 숫자 아님은 경고 한 줄).
  - `setGameRule`: 범위 검사 없음(spawnChunkRadius 40 도 들어간다 — Paper 와 같다). 이벤트를 부르고 취소면 false.
- `io.papermc.paper.event.world.WorldGameRuleChangeEvent` + `Event#callEvent()`(Paper API, 이번에 처음 넣음).
  - API 로 바꾸면 보낸 쪽 null, `/gamerule` 이면 명령을 낸 쪽.
  - `/gamerule`: furnace-api 새 이벤트 `GameRuleChangeEvent`(값 문자열·취소) → 호환 다리 → Bukkit. 취소돼도 명령은 성공이고 지금 값을 알리며,
    값 바뀜 처리(바닐라 onChanged — 예: spawnChunkRadius 티켓 다시 걸기)는 지금 값으로 한 번 돈다(Paper 패치와 같다).
    처리기가 정수 규칙에 숫자 아닌 값을 주면 Paper 처럼 `Integer.parseInt` 예외로 명령이 실패한다.
  - Furnace 플러그인 규칙("ns:이름")은 Furnace 이벤트만 오고 Bukkit 이벤트는 없다(GameRule 상수가 없다).
- `ComplexEntityPart`·`EnderDragonPart` 형(인터페이스만). Furnace 는 드래곤 부분 엔티티를 Bukkit 에 드러내지 않는다.
- furnace-api `GameRuleRegistry#defaultValue(rule)`(새).

## Paper 와 다른 점(알고 둔 것)
- **게임 규칙은 서버 전체에 하나다.** Paper 는 플러그인이 만든 월드마다 level.dat 게임 규칙을 따로 두지만 Furnace 는 추가 월드도 같은 값을 본다
  (이미 /gamerule 이 그렇다). 어느 World 로 바꿔도 모든 월드에 적용된다. WorldGameRuleChangeEvent 의 월드는 바꾼 World(명령은 명령을 낸 쪽의 월드).
- 다른 월드에서 부른 `setKeepSpawnInMemory(false)` 도 주 오버월드 스폰 청크를 끈다(규칙이 하나라서). 주 오버월드가 아니면 무시+경고(B)로 갈지
  도미니코 결정 대기(T141E4a-D1, docs/user-todo/entries/2026-11-15-t141e4a-keepspawn.md). 결정 전엔 지금 동작.
- 처리기가 `setValue(null)` 하면 취소가 아니다(Paper: 불리언 false, 정수는 명령 실패) — PR #383 검토 R1 로 고침.
- `getGameRules()` 순서: 같은 51 이름을 HashMap 에 넣지만 넣는 순서가 바닐라 등록 순서가 아니라 같은 버킷 안 순서가 다를 수 있다(API 가 순서를 약속하지 않는다).
- `ComplexLivingEntity#getParts()` 는 아직 없다(부분 엔티티가 생길 때).
