# 2026-11-16 T-197 빛 다시 계산(Starlight relight) — 함정·교훈

설계·결과: `docs/feature-parity/compat-nms-n2b5-relight-2026-11-16.md`. 독립 검토 `furnace/reviews/t197-relight-design-review-2026-11-16.md`(공유 폴더).

- **Paper 계약(Moonrise `mc/1.21.1`)**: 받은 수 반환·비동기, 청크 C 마다 3×3 을 빈 빛에서 계산해 C 에만 넣는다 — 둘레 청크의 빛은 고치지 않는다. 그래서 FAWE 가 C 가장자리에
  광원을 넣거나 빼면 둘레에 빛 모자람·유령 빛이 남는 것이 **Paper 동작**이다. 대조(M5·V6)에서 차이로 보지 말 것.
- **결과를 그냥 끼우면 빛 갱신을 잃는다**: 계산 중 둘레 N 경계 횃불을 부수면 N 쪽은 이미 줄었는데 C 는 횃불 있던 빛으로 덮인다 → 다시 검사해도 안 지워진다.
  계산 중 3×3 의 빛 **검사**만 붙잡았다가 끼운 뒤 푼다(원천 고치기는 바로). 붙잡기를 끄면 퍼즈 시험이 실패한다(`RelightTest#withoutHoldsTheFuzzFails`).
- **붙잡힌 검사는 이웃 청크의 빛도 바꾼다**: 저장 stale 표시는 "그 청크에 붙잡힌 검사"가 아니라 체비셰프 1 안이어야 한다(검토 R1).
- **새 이웃의 빛 켜기는 검사가 아니라 전파다**: 계산 중 3×3 에 새로 올라온(또는 바뀐) 컬럼이 민 빛은 붙잡히지 않아 끼우기에 덮인다 → 설치 때 컬럼 객체를 비교해 다르면 다시 계산.
  재생성은 검사를 거쳐 빛을 고치므로 키만 비교해도 결과는 맞았다 — 정체성 비교는 안전장치다.
- **같은 자리 되풀이 relight 는 빛 갱신을 굶긴다**: 앞 relight 가 풀자마자 다음 준비가 다시 붙잡으면 검사가 영영 안 돈다. 다른 요청과 겹치는 타일은 미루고, 준비 전에 밀린 검사를 먼저 계산.
- **원천 다시 세기가 설치 비용의 90%**(0.1 ms/청크): 얼릴 때 `modCount` 가 설치 때 그대로면 일꾼이 센 원천을 쓴다(0.01 ms/청크). 빛 작업 게시도 `modCount` 를 올리므로 그때는 다시 센다.
- **얼림 표시는 원자 수로**: T-064 묶음과 relight 가 같은 구역을 같이 얼리고, 녹이기는 일꾼 스레드에서 한다. `ChunkSection.lightFrozen` 은 volatile int + VarHandle.
- **콜백 스레드**: Paper 는 빛 일꾼 한 스레드에서 차례로 부른다. region 스레드에서 부르면 플러그인이 콜백 안에서 주 스레드를 기다릴 때 틱이 멈춘다 → 요청마다 콜백 전용 스레드 한 줄.
- 측정(4코어 컨테이너, 일꾼 1): 일꾼 약 1 ms/컬럼(설계 때 추정 4 ms 보다 빠름), 1024청크 1.6~1.7 s, 준비 0.7~0.9 ms/타일.
