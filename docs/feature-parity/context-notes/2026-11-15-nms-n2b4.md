## 2026-11-15 NMS 거울·들여오기 함정 (N2b-4)

단계 문서: `../compat-nms-n2b4-2026-11-15.md`.

- **바닐라 1.21.1 `PalettedContainer.copy()` 의 팔레트는 원본의 크기 바꿈 처리기를 쥔다**(N2b-1 에서 그대로 옮김). 그래서 Furnace 가 컨테이너의 `data` 를 새로 만들 때 다른(임시) 컨테이너를 만들어 그 `.data` 를 빼 오면 안 된다 — 팔레트가 꽉 찼을 때 임시 컨테이너가 커지고 원래 컨테이너는 옛 0비트 저장소에 쓰다 `The value 1 is not in the specified inclusive range of 0 to 0`. 실체화·떼어 내기는 `furnaceDataFromIds(.., owner = this)` 로 만든다(`NmsMirrorTest.faweStyleSectionReplaceIsImported` 가 잡았다).
- **빠진 옛 객체는 들여오기 전에 굳힌다.** 들여온 뒤에 떼어 내면 공급원이 이미 새 내용을 내줘 옛 컨테이너가 새 내용으로 굳는다 — 플러그인이 옛 `biomes` 컨테이너를 다시 대입하면 새 바이옴이 그대로 남았다(Paper 는 옛 내용이 돌아온다). `biomesFieldAssignmentIsImported` 가 잡았다.
- **FAWE 는 새 섹션에 기존 섹션의 바이옴 컨테이너를 그대로 넘긴다**(`newChunkSection(.., existingSection.getBiomes())`). 옛 섹션을 떼어 낼 때 그 컨테이너도 굳히고, 새 섹션을 붙일 때 다시 그 자리의 보기로 붙인다 — Paper 에서도 두 섹션이 같은 바이옴 객체를 나눠 쥔다.
- **FAWE 의 섹션 CAS 는 "minecraft" 문자열이 없는 worldedit-core 클래스에 있다**(`ReflectionUtils.compareAndSet`, Object[] VarHandle). VarHandle 장벽을 NMS 이름 힌트 게이트 안에 두면 놓친다. 시험은 그 클래스에 "minecraft" 가 없다는 전제까지 단언한다.
- VarHandle 접근 메서드는 서명 다형이라 호출 자리 서술자가 정적 형을 따른다. Object 꼴이 아닌 NMS 원소 형(`LevelChunkSection[]`)도 Object 꼴 정적 메서드로 돌려도 VarHandle 의 invoke 의미가 형을 맞춘다 — 단 `withInvokeExactBehavior()` 핸들이면 깨지므로 원소 형이 `net/minecraft/` 인 것만 넓혔다.
- `Field.set*` 장벽은 `[f, t, v]` 스택을 `DUP_X2, POP, DUP2_X1, DUP2_X1, POP2` 로 `[f, t, f, t, v]` 로 만든다 — 값이 범주 1(short·int·Object 등)일 때만 맞다. `setLong`·`setDouble` 은 넣지 않았다(개수·참조 필드는 범주 1).
- 다리 쓰기(`setSectionStateRawNow` 등)는 `WorldHandle.ownedRegion` 맞춤 지점을 지나므로 재생 안에서 다시 맞추기가 불린다 — `ChunkColumn.mirrorSyncing` 과 거울 `syncing` 두 겹으로 막는다.
- 시험 서버(`FurnaceTestServer`)의 region 은 틱 사이에도 받은 작업을 돈다. "장벽 알림이면 틱 없이 들어온다"는 `server.tick` 없이 `onRegion` 으로 서버 칸을 몇 번 다시 읽어 확인했다(5초 상한). 반대로 알림 없는 대입은 `onRegion` 한 바퀴 뒤에도 안 들어오고 `tick(1)` 뒤에 들어온다.
