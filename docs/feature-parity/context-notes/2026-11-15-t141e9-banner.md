# T-141 E9 — 현수막 상태(Banner)·무늬 종류(PatternType) (2026-11-15)

기준: Paper 1.21.1 API(1.21.3 paper-api 모양으로 대조, `Deprecate-for-removal-all-OldEnum-related-methods.patch`), Youer 1.21.1 `CraftBanner`·`CraftPatternType`.

- `PatternType` 은 1.21 부터 열거형이 아니라 `OldEnum` 인터페이스다. 상수 43개는 `Registry.BANNER_PATTERN` 에서 꺼낸 같은 객체(`==` 가 됨).
  `ordinal` 은 상수 순서 0..42 로 고정, 데이터 팩 무늬는 처음 찾을 때 그 뒤(Paper 는 만든 차례라 보통 같지만, 상수보다 레지스트리 순회를 먼저 하면 서버 레지스트리 순서가 된다 — 저장하지 말 값), `name` 은 minecraft 값이면 대문자 경로, 다른 이름공간이면 키 전체.
  `getIdentifier` 짧은 이름은 바닐라 BannerPatternFormatFix 표(`rd`=diagonal_up_right, `rud`=diagonal_right 처럼 이름과 엇갈린 것 주의)와 Paper 가 붙인 `flw`·`gus`.
- 레지스트리는 바닐라 43개를 처음부터 들고, 데이터 팩이 더한 키는 서버 레지스트리(`gameRegistries().entries("minecraft:banner_pattern")`)에 있을 때만 만든다.
  돌 때는 서버 레지스트리 순서(서버가 없거나 레지스트리가 비었으면 바닐라 목록 — `getByIdentifier`·`Pattern(Map)` 이 onLoad 에서도 되게).
- `Pattern` 직렬화: `{color: 열거형 이름, pattern: 키}`. 되읽기는 옛 색 `SILVER`·옛 짧은 이름(`bs`)도 받는다. `ConfigurationSerialization` 에 별칭 `Pattern` 으로 등록.
- `CraftBanner`: 바탕 색은 블록 종류(`red_banner`·`red_wall_banner`)에서. `setBaseColor` 는 상태 안에서만 바뀌고 저장되지 않는다 — Paper 도 블록 엔티티 필드만
  바꾸므로 다시 읽으면 블록 색. (Paper 는 그 필드가 청크를 다시 읽기 전까지 픽 블록 아이템 색에 쓰이지만 Furnace 서버는 늘 블록에서 읽는다 — 차이는 이것뿐.)
- 무늬 NBT 는 바닐라 저장 꼴 `patterns: [{pattern: "minecraft:…", color: "red"}]`. 인라인 무늬(`{asset_id, translation_key}`)는 Paper 처럼 건너뛰고 update 하면 빠진다.
- **함정:** 블록 엔티티 load 는 바닐라처럼 `patterns` 가 없으면 옛 무늬를 그대로 둔다. Paper `applyTo` 는 `setPatterns` 로 직접 비우므로, Furnace 는 update 때
  빈 목록 `patterns: []` 을 적어 비운다. `getSnapshotNBT` 에서는 Paper(블록 엔티티 저장 꼴)처럼 빈 목록을 뺀다.
- 잘못된 겹(null 겹·null 색·null 무늬 종류)은 update 때 "Banner 무늬 N번째의 …" IllegalArgumentException(Paper 는 NPE·IAE 가 섞여 있다).
- 남은 것: `Skull`(PlayerProfile 필요), `BannerMeta`(아이템), `PlayerLoomPatternSelectEvent`.
