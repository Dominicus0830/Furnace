## 2026-11-16 접속 순서: PlayerJoinEvent 를 접속 탭 앞으로 (T-141 E11c-2 단계 0, R7)

근거: Paper `33ff3dff` 의 `Fire-PlayerJoinEvent-when-Player-is-actually-ready`·`Use-single-player-info-update-packet-on-join`·`Add-Listing-API-for-Player`·`Adventure` 패치(PlayerList.placeNewPlayer).

Paper 1.21.1 순서: 위치(teleport) → server_data → `players.add` → `addNewPlayer`(추적 보류 `supressTrackerForLogin`) → 커스텀 보스바 `onPlayerConnect` → 탈것 태우기 → **PlayerJoinEvent** → 내보냈으면(`!isAcceptingMessages`) 끝 → 접속 알림 방송 → 탭(새 플레이어 항목을 `canSee` 인 모두에게, 본인 포함 / 새 플레이어에게는 볼 수 있는 기존 접속자를 **한 패킷**, 없으면 안 보냄) → `sentListPacket = true`·추적 시작 → `sendLevelInfo` → 효과 → `initInventoryMenu` …

Furnace 에 맞춘 것:
- `ConnectionHandler.onEnterPlay`: 접속자 목록에 넣고(`world.playerOnline`) 발전 과제·통계·스코어보드·채널·보스바를 붙인 뒤 조인 이벤트 → 내보냈으면 끝(접속 알림도 방송하지 않음, 퇴장 알림은 Paper 처럼 연결 종료 때 나감) → 접속 알림 방송 → 본인 탭 → 기존 접속자 탭(조인 이벤트에서 숨긴 접속자·아직 조인 이벤트 중인 접속자 제외, 비었으면 안 보냄) → 보류 해제 → 레벨 정보 … 차례.
- `Player.holdTabListing/releaseTabListing/tabListingHeld`(Paper `!sentListPacket`): 보류 중인 플레이어는 관찰자 region 의 `syncTabList`·핑 방송이 건너뛴다(엔티티 스폰은 탭 등록을 전제하므로 함께 막힌다). 풀 때 접속자 번호를 올려 건너뛴 관찰자가 다음 틱에 올린다. 연결 처리기를 거치지 않는 시험용 플레이어는 보류하지 않는다(기본 거짓).
- 조인 이벤트 안에서 `getOnlinePlayers` 는 새 플레이어를 포함한다(Paper 와 같음).

관측 결과: 조인 이벤트에서 숨긴 플레이어(투명화 플러그인)가 관찰자 탭에 한 틱도 오르지 않고, 이벤트에서 바꾼 게임 모드가 첫 탭 항목부터 보이며, 이벤트에서 내보낸 플레이어는 탭·레벨 정보를 받지 않는다(시험 `JoinTabOrderTest`). 조인 이벤트 처리기를 붙잡아 두는 동안 관찰자 region 이 여러 틱 돌아도 새 접속자를 올리지 않는다(`observerRegionSkipsAPlayerWhileItsJoinEventRuns`, `syncTabList` 의 보류 검사를 빼면 실패).

남은 차이(이 단계 밖, 기존 그대로):
- 저장된 탈것(RootVehicle)은 Furnace 에서 region 이 플레이어를 받아들일 때 태운다 — 조인 이벤트 때 아직 탈것에 타 있지 않다(Paper 는 이벤트 전에 태움). region 편입 시점을 바꾸는 별도 작업.
- 조인 이벤트에서 플러그인이 보낸 패킷·접속 알림은 `Player.send` 대기열을 거쳐 이 접속 처리(레벨 정보·인벤토리까지 직접 쓴 패킷) 뒤에 나간다. 클라이언트가 처리하는 결과는 같다.
- 다른 접속자에게 새 플레이어 탭이 가는 것은 Paper 처럼 같은 자리에서가 아니라 관찰자 region 의 다음 틱(기존 Furnace 방식, 한 틱 이내).
