# T-261 함정 기록 (2026-11-23)

- 손 shim 에 껍데기 멤버를 덧붙일 때 **이미 상위에서 찾아지는 이름+서술자는 덧붙이면 안 된다.** 상위(손 shim·서버 클래스·JDK)의 진짜 구현을 던지는 몸통이 가린다. private 메서드도 같다 — JDK 11+ 의 invokevirtual 은 받는 클래스의 private 메서드를 먼저 찾는다.
- 인터페이스에 default 를 덧붙이면 그 인터페이스를 구현한 **손 하위**가 다른 인터페이스의 default 와 겹쳐(IncompatibleClassChangeError) 깨질 수 있고, 클래스에 메서드를 덧붙이면 손 하위가 받던 인터페이스 default 를 클래스 메서드가 이긴다. 손 하위를 아래로 훑어 그런 경우는 넣지 않는다(1.21.1 에서는 0건이지만 규칙은 둔다).
- Paper 가 `final` 인 메서드를 손 하위가 덮고 있으면 final 로 넣으면 그 하위가 올라가지 않는다 → final 을 뗀다.
- 합친 클래스는 같은 이름으로 껍데기 jar 에 들어가므로 **로더 순서가 껍데기 jar 먼저**여야 한다. `fullShellsTest` 가 합친 클래스가 정말 껍데기 jar 에서 올라오는지 센다.
- 열거형 상수에 몸통(`X {}`)을 주면 javac 가 바깥 열거형을 final 이 아니게(추상 메서드가 있으면 abstract) 만들고 `$1…` 를 상수 순서대로 번호 매긴다 — 바닐라도 상수 전부가 몸통이면 같은 번호다(서명표의 `$N` 수 = 상수 수로 확인).
- `sig-tables.sh` 의 Paper 서버 칸은 첫 실행에서 Maven 429 로 오라클 빌드가 실패하면 "Paper 저장소에 안 닿음"으로 건너뛴다. `./gradlew :worldgen-oracle:printPaperServerJar` 를 다시 돌리면 된다(이 클라우드에서도 Paper 표를 만들 수 있었다 — 지문 일치).
