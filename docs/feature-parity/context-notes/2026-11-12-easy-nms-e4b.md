## 2026-11-12 손 코덱 와이어 대조 (easy-nms E4b-1)

- **확인 방법: 바닐라 jar 의 패킷 코덱을 직접 돌린다.** Furnace 로 쓴 프레임(id + 본문)을 바닐라 1.21.1 서버 jar(번들러 안 `META-INF/versions/1.21.1/server-1.21.1.jar` + `META-INF/libraries` 전부를 클래스경로로)의 `GameProtocols` 코덱으로 읽고 다시 써서 바이트가 같은지 본다. 난독화 이름: `ab.a()` SharedConstants.tryDetectVersion, `akt.a()` Bootstrap, `lt.aA` BuiltInRegistries.REGISTRY, `ka.a(jz)` RegistryAccess.fromRegistryOfRegistries, `wk.a(ka)` RegistryFriendlyByteBuf.decorator, `agh.a`/`agh.b` 서버행/클라행 템플릿, `wh$a.a(Function)` bind, `wh.c()` codec. 동적 레지스트리(damage_type·dimension_type)는 `ju`(MappedRegistry) 를 직접 만들어 넣어야 한다 — damage_type 은 `brm(String msgId, float exhaustion)` 로 `registries/damage_types-1.21.1.txt` 순서대로. 하네스는 커밋하지 않는다(Mojang 코드 실행). E4b-1 표본 40 프레임 모두 같은 바이트·같은 값.
- **와이어 순서가 필드 순서와 다른 종류**: `set_experience`(진행도 f32, 레벨 varint, 총량 varint), `container_click`(바뀐 칸 목록이 들고 있는 아이템보다 먼저), `set_structure_block`(integrity·seed 가 플래그 바이트 앞, 플래그는 맨 끝). 손 코덱 필드는 와이어 순서로 둔다.
- **비트 묶음**: player_abilities(→클라) 1 무적·2 나는 중·4 날 수 있음·8 즉시 건설, (→서버) 2 나는 중만. player_input 1 점프·2 웅크림. set_command_block 1 출력 기록·2 조건부·4 항상 켜짐. set_structure_block 1 엔티티 무시·2 공기 보이기·4 경계 상자. stop_sound 1 범주·2 이름(범주가 먼저 나간다). player_position 의 RelativeMovement 집합은 서수 비트 u8.
- **조건부**: set_objective 는 method 가 0·2 일 때만 표시 이름·표시 방식·숫자 형식이 붙는다(bool 머리 없음). seen_advancements 는 OPENED_TAB 일 때만 탭 이름. player_look_at 은 bool atEntity 뒤에 엔티티·기준점.
- **set_equipment**: 칸마다 (EquipmentSlot 서수 | 뒤에 더 있으면 0x80) 바이트 + 선택 아이템. 바닐라 읽기는 do-while 이라 빈 목록은 쓸 수 없다(쓰면 다음 바이트를 칸으로 읽는다).
- **section_blocks_update**: i64 구역 위치, varint 개수, 칸마다 varlong `상태 번호 << 12 | (x<<8 | z<<4 | y)`.
- **damage_event**: 피해 종류는 `DamageType.STREAM_CODEC`(`brm.c` = `yv.b` holderRegistry, 번호 그대로), 원인·직접 원인 엔티티는 id + 1(0 = 없음), 위치는 bool + f64 셋.
- **container_click**: 바뀐 칸은 `ByteBufCodecs.map(Int2ObjectOpenHashMap, SHORT, ItemStack.OPTIONAL_STREAM_CODEC, 128)` — 128 넘으면 바닐라가 디코드 실패. 바닐라가 다시 쓸 때는 해시 맵 순서라 칸이 둘 이상이면 순서가 바뀔 수 있다(뜻은 같다).
- **number_format**: `NumberFormatTypes.STREAM_CODEC`(`yr.c`) = number_format_type 레지스트리 번호(blank 0, styled 1, fixed 2) + 종류별 내용(styled 는 Style NBT compound, fixed 는 텍스트 NBT), `yr.d` 는 그 optional(bool 머리). number_format_type·block_entity_type 은 Furnace `ItemContext` 레지스트리 파일에 없어 코드 표(`BlockEntity.TYPES`)로 번호를 낸다.
- **독립 검토(PR #252)로 더 찾은 것**: `ServerboundSetStructureBlockPacket` 의 data 는 `readUtf(128)`(129자면 바닐라 서버 디코드 실패). styled 숫자 형식의 스타일 NBT 는 바닐라 `Style.Serializer.CODEC` 이 엄격히 읽는다 — `color` 는 `#`+16진수(0~FFFFFF, 짧아도 됨) 또는 색 이름 16개 그대로(`dark_red` — 대소문자 구분, `TextColor.NAMED_COLORS` 조회, `xy.a(String)`), 참거짓 키는 숫자 태그만(문자열이면 "Not a number"), 모르는 키는 버림. 틀리면 클라이언트가 Network Protocol Error 로 끊긴다. 검토 하네스는 블록 엔티티 44종·피해 47종·모든 enum·비트 조합 205 프레임으로 넓혔다(/mnt/project-files/furnace/reviews/pr252-repro/).
