# T-170 생성 대기열 재설계 (2026-11-14)

`furnace-gen-wait`(FIFO `newFixedThreadPool`)를 `world/GenQueue` 로 바꿨다. 근거: 공유 폴더 `furnace/reviews/w60-explore/W60-explore.md` 2·2-1장, 독립 검토 `W60-review.md` 2장, 반론 X(`opt-review-r2/X-rebuttal.md`) 3.2절. 결정 W-4 ①(굶김 없음).

## 동작

| 무엇 | 어떻게 |
|---|---|
| 순서 | 생성 요청은 그 차원 플레이어들과의 지금 체비셰프 거리 순(50ms 마다 다시 잼), 같으면 넣은 순. 플레이어 없는 차원은 넣은 순. 위치 없는 작업(재생성 등)은 늘 먼저 |
| 취소 | 플레이어 미리 불러오기(`Region.loadChunk(cp, true)`)로 걸린 생성은 **시작 전에** 어느 플레이어의 추적 범위(`trackingDistance + 1` 체비셰프 — `ChunkTrackingView.contains` 의 바깥 한 겹까지)에도 없으면 취소. 취소된 로드는 `CancellationException` 으로 끝나 플레이어 자리(`chunkPrefetches`)가 돌아간다. 이미 시작한 생성(원형·장식 중간 상태)은 건드리지 않는다 |
| 고정 | 그 밖의 요청자(티켓·플러그인·스폰 청크·`chunkAt`)는 진행 중 요청을 `Ticket.pin()` 으로 고정 — 취소와 같은 원자 값 하나에 CAS 라 둘 중 하나만 이긴다. 이미 취소된 뒤에 붙으면 그 실패가 끝난 다음 새로 건다(취소가 새지 않는다). 고정 요청은 3초 넘게 기다리면 거리와 상관없이 먼저 |
| 생성 칸 | 플레이어당 "디스크에 없는 청크" 미리 불러오기 수 = `clamp(전역 예산 ÷ 생성 칸을 쓰는 플레이어 수, 1, 16)`. 전역 예산 = 생성 스레드 × 4(4코어 16). 혼자면 16(예전과 같음 — 첫 시야 안 늦음), 60명이면 1. 디스크 청크는 칸을 안 쓰고 예전 상한(16)만 — 이미 만든 땅은 느려지지 않는다. "디스크에 있나"는 열린 region 파일 위치표를 IO 없이 본다(`RegionFileStore.peekChunk`, 모르면 생성으로 셈) |
| 되돌리기 | `-Dfurnace.gen.order=fifo` = 예전과 같음(넣은 순, 취소·칸 없음) |

손잡이(시스템 속성, 측정·운영용): `furnace.gen.budget`(전역 예산), `furnace.gen.playerCap`(고정 칸, 0=예산으로), `furnace.gen.cancelDelayMs`(시야 밖이 된 뒤 취소까지, 기본 0), `furnace.gen.cancelMargin`(추적 범위 여유 칸, 기본 0), `furnace.gen.pinnedMaxWaitMs`(기본 3000), `furnace.gen.strictBudget`(전역 토큰 — 측정용).

## 바닐라 동일성

- 무엇을 만드는지는 그대로고 **생성 순서**만 바뀐다. 겹치는 장식 결과가 순서에 따라 다를 수 있는 것은 바닐라도 같다(1차·B2 에서 받아들인 기준).
- 취소는 시작 전 요청만 — `ChunkPipeline` 의 원형·장식 상태는 시작한 요청만 만진다.
- 바닐라 1.21.1 은 시야 안 청크에 티켓을 걸고 티켓 레벨(거리) 순으로 만들며, 시야를 벗어나면 티켓이 빠져 대기 작업이 내려간다 — 거리 순 + 시야 밖 취소와 같은 꼴.

## 함정

- `gen.queue` 는 시작한 요청만 잰다(생존자 편향). 굶김은 `batch.gqstale`(시작 못 한 채 아무 추적 범위에도 없는 생성 요청 수 — 취소되지 않고 남은 것)와 사람별 링 0~2(`r02zero`) 로 본다.
- FIFO 판은 봇이 청크를 거의 못 받아 땅 높이 모드가 y200 에 머문다(`ground` miss 가 큼) — 몹 부하가 작게 잡힌다. 판끼리 엔티티 수 비교는 같은 모드끼리.
