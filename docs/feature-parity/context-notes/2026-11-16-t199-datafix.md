# T-199 옛 판 데이터 고치기 — FAWE LegacyMapper "Unknown block" 30줄 (2026-11-16)

원인: FAWE `LegacyMapper` 는 `legacy.json` 의 1.13.2(DataVersion 1631) 이름을 `DataFixer#fixUp(BLOCK_STATE/ITEM_TYPE, …, 1631)`
→ Paper 어댑터 → `DataFixers.getDataFixer().update(References.BLOCK_STATE|ITEM_NAME, Dynamic, 1631, 3955)` 로 올려 본다.
N2b-6 의 `DataFixers` shim 은 판을 올리지 않고 그대로 돌려줘서 `grass`·`sign`·`wall_sign`·`grass_path`·`rose_red` 같은 옛 이름이 1.21.1 이름표에 없었다.

고침(호환 FAWE 전용 코드 아님):
- 서버 구조물 데이터 픽서의 고침 표(1452~3955)를 조각 단위로 쓰는 `StructureDataFixer.fixBlockState/fixBlockName/fixItemName/fixItem/fixBlockEntityPiece/fixEntityPiece`.
- 플러그인 API `Furnace.dataFixer()`(`NbtDataFixer`, 같은 판·밖의 판은 그대로).
- 호환 `DataFixers` shim 이 `block_name`·`item_name`·`block_state`·`item_stack`·`block_entity`·`entity` 를 이 픽서로 올린다. 다른 종류(chunk 등)와 1452 미만은 그대로 + 처음 한 번 경고.

함정:
- shim `NbtOps` 는 `DynamicOps` 가 아니다(상수만 — T-191). FAWE 는 이 상수를 `new Dynamic<>(OPS_NBT, tag)` 에 그대로 넣고, 고치기는 ops 를 건드리지 않고 `input.getOps()` 를 새 Dynamic 에 넘긴다(인터페이스 매개변수라 JVM 검증은 통과).
- 컴파일 대역 `Dynamic` 은 이제 `getOps/getValue` 를 가진 단순 상자다(시험 클래스패스에서만 쓰임, jar 에 안 들어감).
- 1451 이하(1.12 숫자 ID 평탄화)는 여전히 안 한다 — FAWE 는 숫자 ID 를 자기 `legacy.json` 으로 1631 이름까지 올려 주므로 이 길에는 필요 없다.
