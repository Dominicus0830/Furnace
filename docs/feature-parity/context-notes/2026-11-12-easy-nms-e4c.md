# 2026-11-12 easy-nms E4c-1b — NMS 패킷 다리 검토(R2~R8) 반영 중 확인한 바닐라 사실

출처는 바닐라 1.21.1 서버 jar 의 바이트코드(`javap -c -p`)다. jar·디컴파일 결과는 커밋하지 않았다.

## 필드 길이 상한(R2)
- `readUtf(int)`·`readByteArray(int)`·`ByteBufCodecs.stringUtf8(int)`·`byteArray(int)` 호출 바로 앞의 bipush·sipush·ldc 상수를 찾아 패킷 클래스(PacketType 상수로 이름 확인)에 맞췄다.
  - `ClientboundResourcePackPushPacket.hash` 40
  - `ClientboundStoreCookiePacket.payload`·`ServerboundCookieResponsePacket.payload` 5120
  - `ServerboundCommandSuggestionPacket.command` 32500
  - `ClientboundChunksBiomesPacket$ChunkBiomeData.buffer` 2097152
- 스키마(`protocol-767.schema`)에는 길이 표기가 없어 서버 `GenericCodec767.FIELD_LIMITS` 에 바이너리 이름 `#필드` 로 둔다. 다른 문자열은 기본 32767.

## 소리(R3·R8)
- `SoundEvent`(1.21.1)는 record 가 아니라 class 다. 필드는 위치·범위(float)·newSystem(bool)이다. `createVariableRangeEvent` = (16, false), `createFixedRangeEvent` = (r, true). `getRange(v)` = newSystem 이면 r, 아니면 v > 1 이면 16v, 그 밖에는 16. `fixedRange()` 는 private 이고 equals 를 덮어쓰지 않는다.
- 직접 정의 소리의 와이어는 holder(레지스트리, 직접 코덱)다. 0 + 이름 + Optional<Float> 고정 범위가 붙고, 이름이 등록돼 있어도 번호로 바꾸지 않는다.
- `SoundEvents` 의 public static final 필드는 1605개다.
  - 소리 필드 1603개. 타입별로 `SoundEvent` 1486, `Holder.Reference<SoundEvent>` 95, `Holder<SoundEvent>` 22 다. Holder 22개는 `ARMOR_EQUIP_*` 10, `CROSSBOW_*` 6, `LLAMA_SWAG`, `TRIDENT_*` 5 다.
  - 나머지 둘은 `int GOAT_HORN_VARIANT_COUNT = 8` 과 `ImmutableList<Holder.Reference<SoundEvent>> GOAT_HORN_SOUND_VARIANTS` 다.
  - 등록 도우미는 모두 createVariableRangeEvent 다. 고정 범위 도우미는 있지만 clinit 에서 부르지 않는다.
  - 레지스트리 1611개는 필드 1603개와 염소 뿔 변형 8개(item.goat_horn.sound.0~7)를 더한 것이다. 선언 순서가 서버 `builtin-1.21.1.txt` 의 번호 순과 같다.
- **필드 이름.** Mojang 매핑 파일을 받을 수 없어(piston 호스트 차단) 먼저 규칙으로 만들었다. 그 뒤 PR #263 검토가 1.21.1 Mojang 이름 디컴파일 소스(GitHub extremeheat/extracted_minecraft_data, client1.21.1 브랜치)와 1603개를 모두 대조했다. 순서·타입·소리 이름은 차이가 없었고, 이름은 아래 예외까지 넣어 모두 맞췄다. 이 소스는 비교에만 썼고 커밋하지 않았다.
  - 기본 규칙: 소리 이름에서 맨 앞의 `entity`·`block`·`item`·`event`·`particle`·`enchant` 마디를 떼고, 점을 `_` 로 바꿔 대문자로 쓴다.
  - 묶음 규칙: `music.(overworld|nether).X` → `MUSIC_BIOME_X`, `event.mob_effect.X` → `APPLY_EFFECT_X`, `item.brush.brushing.X` → `BRUSH_X`, `block.sculk.X` → `SCULK_BLOCK_X`.
  - 개별 예외:

    | 소리 이름 | 필드 이름 |
    |---|---|
    | block.bell.use | BELL_BLOCK |
    | item.honey_bottle.drink | HONEY_DRINK |
    | intentionally_empty | EMPTY |
    | block.sign.waxed_interact_fail | WAXED_SIGN_INTERACT_FAIL |
    | block.hanging_sign.waxed_interact_fail | WAXED_HANGING_SIGN_INTERACT_FAIL |
    | entity.mooshroom.suspicious_milk | MOOSHROOM_MILK_SUSPICIOUSLY |
    | item.crop.plant | CROP_PLANTED |
    | item.nether_wart.plant | NETHER_WART_PLANTED |
    | entity.breeze.wind_burst | BREEZE_WIND_CHARGE_BURST |
    | entity.wind_charge.wind_burst | WIND_CHARGE_BURST |
    | item.brush.brushing.sand.complete | BRUSH_SAND_COMPLETED |
    | item.brush.brushing.gravel.complete | BRUSH_GRAVEL_COMPLETED |
    | entity.allay.item_thrown | ALLAY_THROW |
    | block.frogspawn.step | FROGSPAWNSTEP(밑줄 없음, Mojang 원문) |
    | block.sculk_sensor.clicking | SCULK_CLICKING |
    | block.sculk_sensor.clicking_stop | SCULK_CLICKING_STOP |

  - 처음 규칙만으로 만든 이름 가운데 11개가 틀렸다(allay, frogspawn, sculk 7, sculk_sensor 2). 선언 순서를 보고 맞춘 것만으로는 부족했다. 이름을 추정할 때는 이름 소스와 대조하기 전까지 가정으로 둔다.
  - `GOAT_HORN_SOUND_VARIANTS`(Guava ImmutableList)는 두지 않았다. 서버 제공 Guava 는 그것을 쓰는 플러그인이 있을 때만 붙는다. 그런데 필드 타입이 ImmutableList 면, Guava 가 없을 때 `SoundEvents.class.getFields()` 같은 리플렉션이 NoClassDefFoundError 로 깨진다.
- 생성기는 scratchpad 의 일회성 스크립트다. 필드 종류 목록이 바닐라 jar 에서 나오므로 결과(`SoundEvents.java`)만 커밋했다.

## 상태 효과(R8)
- `MobEffects` 의 필드는 39개다. 모두 `Holder<MobEffect>` 이고 선언 순서가 레지스트리 순서와 같다.
- `MobEffect` 의 읽기 멤버는 `isInstantenous`(기본 false, 즉시 치유·피해·포화는 `InstantenousMobEffect` 하위), `getCategory`, `isBeneficial`, `getColor`, `getDescriptionId`(`Util.makeDescriptionId("effect", key)`, 등록 안 됨이면 `effect.unregistered_sadface`), `getDisplayName` 이다.
- `MobEffectCategory` 의 툴팁 색은 이로움 BLUE, 해로움 RED, 중립 BLUE 다.

## 묶음(R5)
- 바닐라 unbundler(`zf$1`)는 BundlePacket 을 만나면 구분자, `subPackets()` 각각, 구분자 순으로 내보낸다. 안쪽 패킷은 다시 풀지 않는다.
- 묶음 패킷 종류에는 코덱이 없다(구분자만 등록). 그래서 묶음 안 묶음은 인코딩이 실패해 연결이 끊긴다.
- Furnace 는 같은 입력을 플러그인에 `IllegalArgumentException` 으로 알리고 아무것도 보내지 않는다.

## Holder 직접 정의(PR #263 검토 R3)
- 바닐라 `ByteBufCodecs.holderRegistry` 는 `asHolderIdMap().getId(holder)` = `Registry.getId(holder.value())` 다. 그래서 `Holder.direct(등록된 효과 값)` 도 그 번호로 나간다.
- 다리는 효과를 `BuiltInRegistries.MOB_EFFECT.getKey(value)` 로 찾는다. Attribute·DimensionType 은 레지스트리 shim 이 아직 없어 직접 정의를 거절한다.

## 길이 상한 추가(PR #263 검토 R2·R5)
- `ServerboundEditBookPacket` 상한: 쪽은 `stringUtf8(8192).apply(list(200))`, 제목은 `stringUtf8(128).apply(optional)` 이다. 읽기·쓰기 모두 검사한다.
- `chunks_biomes` 버퍼 2MiB 는 바닐라가 읽기에서만 검사한다(`writeByteArray` 에는 상한이 없다). Furnace 는 쓰기에서도 거절해 플러그인에 예외를 준다. 묶음 안 묶음과 같은 "끊김 대신 예외" 방침이다.
