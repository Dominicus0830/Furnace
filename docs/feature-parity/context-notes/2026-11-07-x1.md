## 2026-11-07 X1 결과 같은 내부 최적화 (X1)
상세 측정·표는 `docs/feature-parity/perf-x1-2026-11-07.md`. 여기에는 다음 사람이 걸릴 함정만 적는다.

- **`Prop` 의 값 번호 표는 정의 때(`define`) 만든다.** 새 값 목록 모양(숫자가 아닌 값, `Integer.toString` 과 다른 문자열 "01" 같은 것)이 생기면 정수 빠른 길을 쓰지 않고 예전 문자열 경로로 돌아간다 — `PropFastPathTest` 가 모든 블록으로 검사한다. 정수 속성을 새로 읽는 코드는 `intValue`/`withInt` 를 그대로 쓰면 된다.
- **연결/모양 값을 번호로 쓰는 곳**(`RedStoneWireBlock` 의 `up|side|none`, `PoweredRailBlock` 의 `shape`)은 클래스 로드 때 값 목록 순서를 검사하고 어긋나면 예외를 낸다. 다른 버전 데이터로 바꾸면 이 검사가 먼저 알려 준다.
- **`B.id(String)` 기억은 직접 사상 표**라 서로 부딪히는 이름이 번갈아 와도 틀린 답은 없고 느려질 뿐이다(상수 문자열이 한 칸을 두고 다투는 일은 드물다). 동적으로 만든 이름을 수만 번 부르는 코드가 생기면 그쪽에서 번호를 들고 있게 한다.
- **`ItemContext.install` 은 아이템 기본 최대 수량 기억을 비운다.** 시험이 레지스트리를 다시 설치해도 이전 설치의 값이 남지 않는다. `MaxStackSizeCacheTest` 참고.
- **`Region.present` 는 `ChunkKeySet`**(키 집합 + 순회용 `long[]` 사본). 순회는 `present.snapshot()` 으로, 순회하는 동안 집합이 바뀌어도 사본은 그대로다. 사본 순서는 만들 때의 `ConcurrentHashMap` 순회 순서라 청크 틱 순서(섞기 전)도 예전과 같다.
- **블록 엔티티 틱 판정 기억은 `tickBlockEntities` 한 호출 안에서만** 산다(64칸 직접 사상). 호출이 끝나면 버려지므로 청크 로드/언로드·플레이어 이동 뒤에는 새로 판정한다.
- **`RegionLevel` 의 높이 범위는 생성자에서 한 번 읽는다.** 월드의 차원 타입을 실행 중에 바꾸는 기능을 넣으려면 이 필드도 같이 고쳐야 한다.
- 벤치 프로파일에서 `ChunkLevel$...Delegating.gameEvents`/`isRaining` 같은 위임 객체가 높게 나오는 것은 시험 서비스(`RegionTickBench` 가 바이옴 응답용으로 한 겹 더 씌움) 때문이다. 실서버 비중으로 읽지 말 것.
- 기준 브랜치에서 `net.DimensionChangeTest.playerWaitingInPortal_prewarmsNetherChunksBeforeTravelling` 이 이 작업 이전에도 실패한다(X1 변경을 빼고 돌려 확인) — M10 포털 대기 시험 수정 스레드 몫.
