# 2026-11-11 A06-01 구조물 조각 바닐라 저장 형식

- 청크 NBT `structures.starts.<id>.Children[]` 를 바닐라 `StructurePiece.save`(ejv.a(ekh)) 형식으로 쓴다: `id`(StructurePieceType 레지스트리 이름,
  eki), `BB`(IntArray 6), `O`(Direction.get2DDataValue, 방향 없으면 -1), `GD`(genDepth), 그리고 조각별 addAdditionalSaveData.
  예전에는 모든 조각이 `furnace:piece`(BB 만)여서 바닐라·Paper 로 옮기면 시작점이 빈 것이 되었다.
- 조각 종류(eki 순서 대조)와 조각별 키는 `StructurePieceSaveTest.KEYS` 에 정리했다. 바닐라 load 생성자(ub)가 읽는 키 기준이다.
  - 폐광 MineShaftPiece: MST(종류 순서), 복도 hr·sc·hps·Num, 교차로 tf·D, 방 Entrances(BoundingBox 목록), 계단 없음.
  - 네더 요새: 다리 끝 Seed, 작은 복도 좌·우 회전 Chest, 괴물 왕좌 Mob. 나머지는 추가 키 없음.
  - 요새: 모든 조각 EntryDoor(문 종류 이름), 상자 복도 Chest, 채움 복도 Steps, 5갈래 leftLow·leftHigh·rightLow·rightHigh, 서재 Tall,
    차원문 방 Mob, 방 교차 Type, 계단(시작 포함) Source, 직선 Left·Right.
  - ScatteredFeaturePiece: Width·Height·Depth·HPos. 정글 사원 placedMainChest…, 마녀 오두막 Witch·Cat, 사막 사원 hasPlacedChest0~3.
  - TemplateStructurePiece: TPX·TPY·TPZ·Template, 방향은 언제나 NORTH(O=2). 이글루·네더 화석 Rot, 바다 폐허 Rot·Integrity·BiomeType(WARM/COLD)·IsLarge,
    폐허 차원문 Rotation·Mirror·VerticalPlacement(직렬 이름)·Properties, 엔드 도시 Rot·OW, 대저택 Rot·Mi, 난파선 isBeached·Rot.
  - 직소(PoolElementStructurePiece): O=-1, GD 0, PosX/Y/Z, ground_level_delta, pool_element(StructurePoolElement 코덱), rotation(Rotation 이름),
    junctions, liquid_settings(기본 apply_waterlogging 이 아닐 때만).
  - 묻힌 보물 O=-1. 해저 신전은 건물 조각 하나(GD 0)만 저장한다 — 바닐라도 방 조각은 건물 안에만 있고 저장하지 않는다.
- pool_element: 요소마다 원본 JSON 에서 다시 만든다. single/legacy_single 은 location·processors(목록 id 면 문자열, 인라인이면 그대로 변환)·projection·
  override_liquid_settings(있을 때만), feature 는 feature id, list 는 elements 와 projection(안쪽 요소의 projection 은 목록 것으로 — 바닐라
  ListPoolElement.setProjectionOnEachElement), empty 는 element_type 만.
- 조각이 없는 시작점은 `id:"INVALID"` 만 쓴다(바닐라 StructureStart.createTag).
- 가정: 조각의 상태 값(높이 HPos·상자 놓음 표시 등)은 저장 시점의 시작점 객체 값이다. Furnace 는 장식에 쓴 시작점 객체(ChunkPipeline decoStarts)를
  그대로 저장하므로 바닐라처럼 "그때까지 장식한 이웃 청크" 기준이다. 바닐라 실서버로 같은 월드를 열어 본 대조는 아직 없다.
- Furnace 가 다시 읽을 때는 지금처럼 BB 만 쓰고 원본 NBT 를 그대로 보존한다.
