# 몹 목표 shim M1 (2026-11-24)

설계: 공유 폴더 `furnace/designs/mob-goals-shim-design-2026-11-24.md`(독립 검토 승인). 차이 결정 항목: `docs/user-todo/entries/2026-11-24-mob-goals-differences.md`.

- 월드 몹의 `goalSelector`·`targetSelector`(공개 필드, `Mob` 조각의 생성기 전용 생성자에서 채움)는 서버 선택기를 보는 shim. 모든 조작은 `NmsGoals.on` 으로 그 몹의 주인 스레드에서
  (`Entity#furnaceOnOwner` — 다른 월드 엔티티 조작과 같은 규칙). 서버 쪽은 `ChunkInternals.mobGoals` → `MobGoalsImpl`(호출마다 주인 확인).
- 목표 정체성: 서버 `Goal`·`WrappedGoal` 의 `compatView` 에 shim 하나를 붙인다. 클래스는 `GoalClasses` 가 서버 클래스에서 위로 올라가며 찾은 가장 가까운 바닐라 목표
  (서버 이름이 다른 `LookAtMobGoal`→`LookAtPlayerGoal`, `SitWhenOrderedToDoGoal`→`SitWhenOrderedToGoal`). 추상 부모뿐이면 `NmsGoals.ServerGoal`.
  바닐라 목표 클래스 67개는 `mob-goals.spec` 의 멤버 없는 class 줄(생성기 전용 생성자 → `NmsKinds.create`).
- 바닐라(Paper 1.21.1 jar javap): `removeGoal` 만 멈추고 빼고, `removeAllGoals` 는 멈추지 않는 `removeIf`. 집합 보기(`NmsGoalSet`)의 `remove/removeIf/clear` 는 서버
  `removeFromSet`(멈추지 않음 — 돌던 목표가 잠근 칸을 쥔 채 남는 것도 바닐라와 같다). 돌기 도중 빼면 `WrappedGoal.leaving` 표시로 그 패스에서 건너뛴다.
- 돌기 도중의 집합 변경은 순서 있는 미룬 목록(넣기·빼기 목록·취소된 넣기). 빼기는 판정 전에 목록에 걸어 예외여도 표시가 정리되고, 같은 패스에서 미룬 넣기도 판정해 취소한다.
  빠질 예정인 목표를 다시 넣으면 표시를 끄고 끝에서 빼고 넣는다(바닐라처럼 맨 뒤). 호환 보기(`available`·크기·contains)는 `visibleGoals` — 빠질 예정 제외, 미룬 넣기 포함.
- `WrappedGoal#isRunning`·`canBeReplacedBy` 는 주인 스레드의 지금 값(앞서 받은 객체도 `tick()` 뒤 값을 본다). 우선순위·안의 목표는 불변이라 만들 때 담는다.
- Paper `Goal#getFlags()` 반환형은 moonrise `OptimizedSmallEnumSet`(서명표에 없음 — javap 로 모양·예외 문구 확인, 손 클래스). `Goal$Flag` 순서는 Paper 대로 UNKNOWN_BEHAVIOR 가 0.
  UNKNOWN_BEHAVIOR 는 서버 목표가 쓰지 않아 `setControlFlag` 해도 바뀌는 것이 없다.
- 함정: 명세 `@each` 는 조각(손 shim)에도 몸통을 끼워 넣어 중복 정의가 된다 — 조각이 그 메서드를 쓰면 그 클래스 줄에 `-> @hand` 를 적는다(`WrappedGoal#canUse`).
- M2a: 플러그인이 상속한 목표는 `GoalSelector#addGoal` 때 서버 어댑터(`ChunkInternalsImpl.CompatGoal`, 콜백 `NmsPluginGoal`)로 넣는다. 보기는 플러그인 목표 객체 그대로,
  같음은 그 객체의 equals, `removeGoal` 은 같은 객체로 찾는다. 예외는 로그 한 번 뒤 그 목표만 멈추고, 플러그인이 꺼지면 두 선택기에서 빠진다(꺼진 뒤 stop 도 부르지 않는다).
  Paper `Goal` 은 깃발을 살아 있는 `goalTypes` 로 갖고 비면 UNKNOWN_BEHAVIOR(javap) — 플러그인 목표는 그대로 두고 서버는 확인마다 비트를 읽는다(서버는 UNKNOWN 칸을 쓰지 않음, user-todo G4).
- M2b-1(보충 설계 `furnace/designs/mob-goals-m2b-addendum-2026-11-24.md`, 검토 조건부 승인 반영): 바닐라 목표 생성자 21종은 그 자리에서 생성자 몹의 주인 스레드에 서버 목표를 만든다
  (`NmsGoals.vanilla` → `MobGoals.vanillaGoal` → 서버 `CompatVanillaGoals`, 형식 줄 `이름(DFIZT)` 로 생성자 고름). 조각은 `ai/goal/*.java`(머리줄은 `class X {` — 형식 인자는 잠금 파일이 준다),
  명세는 `<init>` 겹친 이름마다 서술자 줄. 엔티티 클래스는 ServerPlayer shim 의 조상이면 플레이어 포함, 종류 표에서 하위 종류 집합 — 둘 다면(사실상 LivingEntity) 거부.
  addGoal 거부 순서: 실제 클래스가 shim(`net.minecraft.`·`ServerGoal`)이 아니면 바닐라 조상이 Goal 이 아닌 한 T-237 거부(backing 이 있어도), 다른 몹의 목표 거부.
- 바닐라 대조(javap): LookAtPlayerGoal 은 공격 대상을 lookAt 에 넣어도 곧바로 검색 결과로 덮어쓴다 — 서버 `LookAtMobGoal` 이 대상을 그대로 보던 것을 고침(약탈자·소환사 등).
  문 목표 검사 문구 "Unsupported mob type for DoorInteractGoal".
- M3(설계 `furnace/designs/mob-goals-m3-detached-design-2026-11-24.md`, 검토 조건부 승인 반영): `EntityType#create` 로 만든 넣기 전 몹의 선택기는 칸 재생 상태(`DetachedEntityData`)의
  샌드박스 몹(빈 레벨)을 본다 — `Entity#furnaceGoals` 가 경로를 고르고(월드/스폰 이벤트 중 넣을 엔티티/샌드박스), 샌드박스 조작은 `NmsGoals.Sandbox#locked`(엔티티 shim 의 `Detached` 잠금 —
  데이터만, 판정 함수는 잠금 밖) 안에서 한다. 바꾸는 조작은 샌드박스에 먼저 하고 성공하면 `EntityOp.Goal*` 로 기록, 넣을 때 서버가 같은 차례로 재생한다.
  처음 보는 감싼 목표는 `GoalPin`(자리·바닐라 클래스·우선순위·깃발)으로 묶는다 — 설계의 "첫 재생 전 위치 짝짓기"를 처음 볼 때로 미룬 것(재생 순서가 같아 결과가 같고, 그 사이의 load 등도 반영된다).
  shim 의 `NmsGoals.Backing` 은 불변 `Route`(World/InSandbox/Dead) 하나를 volatile 로 쥔다. 서버는 재생 뒤·스폰 이벤트 전에 `GoalRef#bindWorld` 로 경로를 옮기고 보기 shim 을 붙인 뒤
  `EntityOp.AddHook` 으로 넣을 엔티티 핸들을 알린다(이벤트 처리기가 넣기 전 객체를 써도 넣을 몹을 본다). 넣기 실패면 샌드박스로 되돌리고, 성공인데 짝이 없으면 Dead(호출마다 거부, 경고 한 번).
  넣는 동안 다른 스레드: 넣을 엔티티가 정해지기 전이면 거부("being added"), 정해진 뒤면 주인 region 을 기다려 넣은 몹에 한다.
  함정: 칸 재생 상태가 목표 때문에 먼저 열렸으면 칸을 꺼내지 않았어도 뒤의 조작을 재생해야 한다(`Detached.replay`). 지원 안 하는 생성자(`GoalCreate`)의 실패는 몹을 바꾸기 전이라 재생 상태를 잠그지 않는다.
  바닐라 몹 전 종류에서 샌드박스와 넣은 몹의 목록이 하나도 빠짐없이 짝지어짐을 시험으로 확인(`NmsMobGoalsDetachedTest`). 차이는 user-todo G6(넣기 전 canUse 는 빈 세상 기준).
- M2b-2 TemptGoal: 아이템 판정 매개변수는 `NmsGoals.items` → `ChunkInternals.GoalItems`(형식 줄 글자 P). 정확하지 않은 `Ingredient`(영역 4, PR 620)는 아이템 종류 이름 집합으로 바꿔
  서버가 바로 판정한다(바닐라 Ingredient#test 는 종류만 본다, 비면 빈 스택만 — 태그는 만들 때 펼친다). 람다·정확한 Ingredient 는 서버가 주인 스레드에서 API 스택 → shim 스택 사본으로
  부른다. 판정 예외(LinkageError 포함)는 Lang `goal.item-test-threw` 로그 한 번 뒤 늘 거짓(그 목표만 멈춤 — G3 와 같은 완화), 판정을 올린 플러그인이 꺼지면 판정을 부르지 않고
  그 목표가 두 선택기에서 빠진다. Ingredient 하위 클래스(test 재정의)는 판정 경로. 판정 하나를 여러 몹이 나눠 쓰면 여러 region 스레드가 동시에 부른다(개발자 주의).
- 아직: 판정 함수 생성자(AvoidEntity 6·7인자, NearestAttackableTarget 판정 함수, Panic 태그 함수)·짝/무시 클래스·플러그인이 만든 감싼 목표를 집합에 바로 넣기는 M2b-2 나머지 — 지금은 UnsupportedNmsCall. 선택기 필드를 새 객체로 바꿔 끼우는 것·`aware` 필드 쓰기는 서버에 닿지 않는다(지원 밖).
