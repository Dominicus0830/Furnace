## 2026-11-07 H3 호환 계층 — 아이템·인벤토리·블록·엔티티 함정 (H3)

- **비동기판 Future 는 소유 스레드에서도 곧바로 끝나지 않는다.** `World.spawnEntity`·`nearbyEntities`(`submitAtOwnedChunk` → `Regionizer.enqueueIfOwned`)와 `Entity.editPersistentData`(`onEntity` → 엔티티 대기열)는 같은 region 스레드에서 불러도 큐에 넣고 다음에 끝난다. 반면 `Block.set/data`(동기)·`Player.inventory()` 읽기·`PlayerInventoryHandle.set`(`runOnOwner` — 소유 스레드면 곧바로, 아니면 다음 플레이어 틱)는 곧바로 끝난다. 그래서 Bukkit 의 동기 호출을 올릴 때 "Future 가 이미 끝났나"로 소유 여부를 판단하는 `Owned.read/write` 를 쓰고, 큐를 거치는 것은 동기 쌍(`*Now`)을 API 에 더했다.
- **접속 처리기(PlayerJoinEvent)는 netty 스레드에서 불린다.** 그 시점의 플레이어는 소유 region 이 없어 `runOnOwner` 가 다음 플레이어 틱으로 미룬다. 키트 지급 모양(`addItem` 연달아)이 서로 덮어쓰지 않으려면 `CompatInventory` 의 예약 겹침이 필요했다(처음엔 `ThreadOwnershipException` 으로 막았다가 접속 처리기 키트가 안 돌아서 바꿈).
- **`RegionFuture.join` 은 서버 스레드에서 끝나지 않은 Future 를 기다리면 `IllegalStateException`.** 그래서 호환 계층은 절대 기다리지 않는다(끝났으면 값, 아니면 예약 또는 거절).
- **`ItemStack` 은 Furnace 에서 불변 record 이고 Bukkit 에서는 가변 객체**라 `ItemSlot`(평범한 값 vs 칸 거울)로 감쌌다. 거울은 읽을 때마다 칸을 다시 읽으므로 `inv.getItem(0)` 으로 받은 스택의 `setAmount(0)` 이 칸을 비우고 `getType()` 이 AIR 가 된다(Bukkit 과 같다). 개수 0·음수 스택은 평범한 값에서만 그대로 들고 있는다.
- **`ItemFlag` 는 컴포넌트마다 `show_in_tooltip` 이다(1.21.1).** `Unbreakable(showInTooltip)` 에서 `false` 가 설명 숨김이다. 빈 `enchantments` 컴포넌트에 `showInTooltip=false` 를 붙이면 HIDE_ENCHANTS 가 표현된다(빛나지 않음). 속성 변경치는 `get` 이 아이템 기본값(칼의 공격력)을 돌려주므로 거기에 `showInTooltip=false` 만 바꿔 쓰면 기본값을 잃지 않는다.
- **`has/get(ItemComponent)` 는 아이템 기본값까지 본다.** 기본 아이템 이름(`item_name`)은 모든 아이템에 기본값이 있어 `hasItemName` 은 패치(`components()` 맵)에 키가 있는지로 판단했다.
- **시험 서버**: `server.onRegion(pos, supplier)` 로 소유 스레드를 흉내 낸다. 예약된 플레이어 쓰기는 플레이어 틱에 적용되므로 `server.tick(n)` 뒤 값을 단정할 때 한 번에 `tick(2)` 보다 "될 때까지 최대 N틱" 반복이 안전하다(드물게 한 틱 밀림).
- **`Material`·`EntityType`·`Enchantment` 는 생성 파일**(`tools/compat/gen-bukkit-material.py`, `gen-bukkit-registries.py`) — 손으로 고치지 말고 생성기를 고친다. Material 에 메서드를 더할 때도 생성기 템플릿에.
