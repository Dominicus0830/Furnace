# 2026-11-12 easy-nms E4c-2 — 손 코덱 종류 shim 다리에서 확인한 바닐라 사실

출처: 바닐라 1.21.1 서버 jar(직접 실행·`javap -c -p`)와 1.21.1 Mojang 이름 디컴파일 소스(GitHub extremeheat/extracted_minecraft_data, client1.21.1 브랜치 — 이름·write 순서 비교에만 썼다). jar·디컴파일 결과는 커밋하지 않았다.

## 지도 표시 종류(MapDecorationTypes)
- 필드 35개, 모두 `Holder<MapDecorationType>`. 선언 순서 = 레지스트리 번호 순서 = 서버 `builtin-1.21.1.txt` 순서.
- 등록 도우미 둘: `register(이름, 그림, 액자 표시, 개수 세기)` = 지도 색 -1(NO_MAP_COLOR)·탐험 아님, `register(이름, 그림, 액자 표시, 지도 색, 개수 세기, 탐험)`.
  record 성분 순서는 (assetId, showOnItemFrame, mapColor, explorationMapElement, trackCount) 로 도우미 인자 순서와 다르다.
- 값(바닐라 jar 를 부트스트랩해 읽음): 마을 5종·정글 사원·늪 오두막의 지도 색은 `MapColor` 필드에서 오는 10066329, 시험의 방 12741452, 저택 5393476, 해저 유적 3830373.
  그림 이름은 레지스트리 이름과 다른 것이 있다(mansion → woodland_mansion, monument → ocean_monument, banner_white → white_banner, village_desert → desert_village).
- 필드 이름은 Mojang 소스와 35개 모두 대조했다(WOODLAND_MANSION, OCEAN_MONUMENT, WHITE_BANNER…, DESERT_VILLAGE…, TRIAL_CHAMBERS).

## 패킷 write (손 코덱 종류)
- `ClientboundSetPlayerTeamPacket`: 이름, method 바이트, method 0·2 면 parameters(없으면 IllegalStateException), 0·3·4 면 players. 나머지 필드는 쓰지 않는다.
- `ClientboundSetObjectivePacket`: 이름, method 바이트, method 0·2 일 때만 표시 이름·그리기 방식·숫자 형식(Optional).
- `ClientboundSectionBlocksUpdatePacket`: `positions.length` 만큼 `Block.getId(states[i]) << 12 | positions[i]`. states 가 짧으면 배열 밖 실패, 길면 남는 것은 안 쓴다.
- `ClientboundSetEquipmentPacket`: 칸마다 (서수 | 뒤에 더 있으면 0x80) + 아이템. 빈 목록이면 엔티티 번호만 쓰지만 클라이언트는 적어도 한 칸을 읽는다.
- `ClientboundPlayerLookAtPacket`: from 기준점, x·y·z, atEntity, atEntity 일 때만 대상 번호·대상 기준점.
- `MapItemSavedData.MapPatch.write`: 있으면 width·height·startX·startY 를 writeByte(아래 8비트) + 색 바이트 배열, 없으면 0 한 바이트. record 성분 순서는 (startX, startY, width, height, mapColors).
- `StyledFormat`·`FixedFormat` 의 값 필드(`style`·`value`)는 package-private 이고 접근자가 없다. `BlankFormat.INSTANCE`, `StyledFormat.NO_STYLE`·`SIDEBAR_DEFAULT`(빨강)·`PLAYER_LIST_DEFAULT`(노랑).
- `AttributeModifier.Operation`: ADD_VALUE(add_value, 0)·ADD_MULTIPLIED_BASE(1)·ADD_MULTIPLIED_TOTAL(2), `BY_ID` 는 ByIdMap.continuous ZERO(범위 밖 = 첫 상수).

## PR #267 검토 반영
- `MapDecoration` 생성자 첫 줄은 `rot = (byte)(rot & 15)` 다. 받는 클라이언트도 다시 자르므로 화면은 같지만 `rot()` 값과 와이어 바이트가 다르다.
- `TextColor.fromRgb(int)` 는 이름을 붙이지 않는다(`new TextColor(v)`), `parseColor("#FF5555")` 도 fromRgb 다. 이름 있는 색은 `ChatFormatting` 16색에서 만든 것뿐이다. equals 는 값만 본다.
  Furnace api `TextColor.color(int)`·`fromHexString` 은 Adventure 처럼 이름을 붙인다 — 바닐라와 같은 직렬화가 필요하면 `TextColor.rgb(int)`.
