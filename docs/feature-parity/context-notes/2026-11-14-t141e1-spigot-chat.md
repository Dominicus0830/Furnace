# T-141 물결 1-E1: Player.spigot() BungeeCord 채팅, BiomeProvider 형 (2026-11-14)

## 기준(Paper 1.21.1 CraftBukkit)
- `CraftPlayer.spigot()`: 필드 하나. `sendMessage(ChatMessageType, UUID, BaseComponent...)` 는 접속이 없으면 조용히 끝나고,
  `ClientboundSystemChatPacket(components, position == ACTION_BAR)` 를 곧바로 보낸다. 대화 중 가림(Conversation)·채팅 표시 설정을 거치지 않는다.
  SYSTEM·CHAT 은 둘 다 채팅 창. sender 는 쓰지 않는다.
- 패킷의 BaseComponent[] 는 `ComponentSerializer.toString(components)` JSON 을 바닐라 JSON 해석기(`CraftChatMessage.fromJSON`)로 읽는다.
  여러 개면 빈 TextComponent 아래 extra 로 한 메시지.
- `ServerCommandSender.spigot()`(콘솔·명령 블록·RCON): `TextComponent.toLegacyText` 로 § 글을 만들어 sendMessage(String).
- `CraftEntity.spigot()`: 네 sendMessage 모두 아무 일 없음.
- `CommandSender.Spigot`·`Entity.Spigot`·`Player.Spigot` 의 몸은 Paper API 에서도 UnsupportedOperationException.

## Furnace 구현
- `CommandSender.spigot()` 은 기본 메서드(서버 쪽 보내는 이 동작). 엔티티·플레이어가 덮어쓴다.
- 컴포넌트 클래스를 만지는 코드는 `BungeeChat` 한 곳에만 둔다. bungeecord-chat 은 쓰는 플러그인이 있을 때만 공유 라이브러리 로더에 붙는다
  (서버 라이브러리 묶음 `bungeecord-chat`, 1.20-R0.2). 호환 모듈은 compileOnly, 시험은 testImplementation.
- `Player.Spigot#respawn` 은 UnsupportedFeature(플러그인 되살리기 API 없음). `getHiddenPlayers` 는 숨기기가 없어 늘 빈 집합.
  `getRawAddress` 는 `getAddress` 와 같다(프록시 앞 주소를 따로 두지 않는다 — 가정).
- `World#getBiomeProvider` 는 늘 null. Paper 도 WorldCreator 로 공급자를 주지 않은 월드는 null 이다. `World` 는 `WorldInfo` 를 넓힌다.

## 남긴 것(E2~E5)
- `setKeepSpawnInMemory`: CraftBukkit 은 게임 규칙 spawnChunkRadius 를 기본값 또는 0 으로 쓴다. 호환 계층에 게임 규칙 쓰기가 아직 없어 E4(월드 관리)로 미룸.
- 데이터팩 관리자(`Server#getDatapackManager`)는 Adventure Component·FeatureFlag·DatapackSource 가 얽혀 E4 로.
