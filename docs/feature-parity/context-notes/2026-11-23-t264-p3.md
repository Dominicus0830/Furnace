# T-264 P3 핸들 다리 — 함정 (2026-11-23)

- **서명표에는 합성 멤버가 없다.** `sig-table-paper-server.tsv.gz` 는 javac 가 만든 다리 메서드(ACC_BRIDGE·SYNTHETIC)를 담지 않는다. 그래서 Paper 클래스의 공변 반환 다리(예: `CraftWorld#getHandle()WorldGenLevel`)는 표만 보면 "없는 멤버"로도 안 보인다. 필요하면 Paper 계층의 덮어쓰기 관계(상위 형식의 같은 이름·인자, 다른 반환형)로 다시 계산한다 — `ShellMerge#addCompilerBridges`.
- **FullShells 의 NMS 범위에는 CraftBukkit 도 들어간다.** `FullShells.Scope.NMS` 는 Paper 서버 jar 안쪽 전부(7,139 클래스 = NMS + CraftBukkit)라 "바닐라 형인가"를 범위로 판정하면 `CraftItemStack` 같은 Craft 형도 통과한다. 바닐라 형은 `net/minecraft/` 접두로 본다.
- **API 형으로 좁히는 다리는 늘 던진다.** `CraftChiseledBookshelf#getInventory()ChiseledBookshelfInventory` 처럼 API 형으로 좁히는 메서드에 다리를 내면, Furnace 손 상위가 그 형의 객체를 아직 주지 않아 늘 `UnsupportedNmsCall` 인데 `CraftLiveMethodsTest` 는 "살아 있음"으로 센다. 다리는 핸들(바닐라 형)만, 나머지는 껍데기(d 칸)로 둔다.
- **컴파일러 다리는 실행 때 계층으로도 확인한다.** Paper 계층에서 하위여도 Furnace 손 클래스가 그 인터페이스를 아직 안 가지면(계층 기준선의 `interfaces` 줄) 다리가 그 형이 아닌 값을 돌려준다(인터페이스 반환은 검증기가 안 막는다 → 나중에 `IncompatibleClassChangeError`). `ShellMerge#furnaceSubtype`.
- **로컬 `fullShellsTest` 의 `FillParityTest` 는 채움 표가 캐시에 없으면 실패한다**(`filled classes: 0`). 채움 표(`fill-table*.tsv.gz`)는 `tools/compat/sig-tables.sh` 가 Paper 표와 함께 만든다 — CI 에는 있다. P3 와 무관.
