## 2026-11-12 범용 패킷 코덱 와이어 대조 (easy-nms E4a)

- **스키마의 `nullable` 은 늘 bool 머리가 아니다.** `ClientboundTagQueryPacket` 은 `FriendlyByteBuf.writeNbt(tag)`(바닐라 `afu.a(vw)` → `vw.a(uy)`)라 없으면 END 태그(0) 한 바이트, 있으면 이름 없는 compound 가 바로 온다. `GenericCodec767` 은 `CompoundTag nullable` 을 이렇게 읽는다. 다른 `nullable`(select_advancements_tab·reset_score·cookie_response)은 `writeNullable`(`vw.a(Object, yz)`) 로 bool 머리가 맞다.
- **Holder 와이어는 레지스트리마다 다르다.** `MobEffect.STREAM_CODEC`(`brx.b`)·`DimensionType.STREAM_CODEC`(`dwy.i`)은 `ByteBufCodecs.holderRegistry`(`yv.b`) — 번호 그대로. `SoundEvent.STREAM_CODEC`(`avo.d`)는 `holder(SOUND_EVENT, 직접)`(`yv.a(akq,yx)`) — 등록된 것 번호 + 1, 0 이면 이름 + 고정 범위(선택 float). E1 의 wolf_variant 와 같은 꼴.
- **이전 게임 모드는 i8 -1 = 없음**(`CommonPlayerSpawnInfo` 쓰기 `agd.a(wk)` → `dct.a(dct)` = getNullableId). 범용 값은 `Optional<String>`.
- 바닐라 `ByteBufCodecs` 이름(`yv`): b BOOL, c BYTE, d SHORT, e UNSIGNED_SHORT, f INT, g VAR_INT, h VAR_LONG, i FLOAT, j DOUBLE, l STRING_UTF8. `FriendlyByteBuf`(`vw`): c(I) writeVarInt, k(I) writeByte, l(I) writeShort, p(I) writeInt, b(J) writeLong.
- 패킷 클래스 찾기: `GamePacketTypes` 는 `agg`(이름 문자열 → 필드), 공용 `zy`, ping `ajk`, cookie `abq`. 패킷 클래스는 `type()` 이 `getstatic agg.<필드>` 하는 것.
- 확인 방법: 서버가 실제로 보내는 26종은 furnace-test `GenericPacketRoundTripTest`(읽고 다시 쓴 바이트가 같은가), 나머지 76종은 위 방법으로 바이트코드 쓰기 순서와 하나씩 대조. 서버 직렬화기와만 맞추면 둘 다 틀린 경우를 못 잡는다(E1 교훈) — 서버가 안 보내는 종류는 반드시 jar 와 대조한다.
