## 2026-11-08 명령 정합 (P1, commands)

비교 문서 `paper-vs-spigot-2026-11-08.md` 1장(A1·A2·A5·A6)을 Paper 1.21.1 패치 원문(`fix-empty-array-elements-in-command-arguments`, `Fix-commands-from-signs-not-firing-command-events`, `Add-PlayerSignCommandPreprocessEvent`, `Brigadier-based-command-API`)과 맞춰 고쳤다. 기준은 "Paper 1.21.1, 바닐라와 같은 결과".

- **A1 인자 빈 칸.** `LegacyCommands.splitLine` 하나가 Paper 의 `StringUtils.split(line, ' ')` 규칙(앞·가운데·끝의 빈 칸을 모두 버림)을 맡는다. `SimpleCommandMap.dispatch`(Bukkit.dispatchCommand 가 먼저 타는 길)와 `LegacyCommands.dispatch` 가 쓴다. 플레이어·콘솔이 치는 서버 명령 줄은 이미 `execArgs` 로 같은 규칙이었다. 자동완성은 끝의 빈 칸을 지켜야 해서(다음 인자 위치) 이 규칙을 쓰지 않는다 — 그대로.
- **A5 없는 명령.** `CommandRegistry.hasCommand(name)`(트리 루트에 그 이름이 있나, 스레드 무관)을 새로 열었다. `CraftServer.dispatchCommand`: 지도에 있으면 실행하고 true. 아니면 트리에서 이름(원래 이름, 없으면 소문자)을 찾아, 있으면 Paper 1.21.1 의 `VanillaCommandWrapper` 처럼 "이름 + 빈 칸 하나로 이은 인자" 로 다시 만들어 큐에 넣고 true. 트리에도 없으면 원래 줄을 그대로 보내 바닐라 오류 문장이 나오게 하고 **false**. 비어 있는 줄은 아무것도 안 보내고 false. 1.21.1 에서 바닐라 명령이 true 인 이유(독립 검토로 확인): `CraftCommandMap` 의 knownCommands 가 Brigadier 루트를 비추는 `BukkitBrigForwardingMap` 이라 `get("say")` 가 `VanillaCommandWrapper` 를 돌려주고, 첫 갈래 `commandMap.dispatch` 에서 true 로 끝난다. 끝의 `return false` 는 루트에 없는 이름일 때만 닿는다.
- **앞의 `/` 는 떼지 않는다(Paper 와 같다).** `dispatchCommand("/say hi")` 는 `/say` 라는 이름이 없어 false + 바닐라 오류 문장(명령은 안 돈다). 플러그인이 `/wand` 로 등록한 명령(WorldEdit 의 `//wand`)은 돈다. 서버 쪽 `performPrefixedCommand` 가 앞 `/` 를 하나 떼므로 없는 이름 길에서는 `/` 를 하나 더 붙여 보낸다. Furnace 고유 `LegacyCommands.dispatch` 는 예전처럼 `/` 를 뗀다(Bukkit API 가 아니다).
- **거절 문장.** 권한 없는 플레이어가 `Bukkit.dispatchCommand` 로 **옛 플러그인 명령**을 부르면 Bukkit 거절 문장이 나온다. **바닐라 명령**은 Paper 가 `minecraft.command.<이름>` 권한으로 거절 문장을 보이지만 Furnace 는 바닐라 소스 권한 레벨 규칙이라 "알 수 없는 명령" 류 문장이 나온다(반환값 true 는 같다) — 남은 차이.
- **채팅 명령 기록 순서.** `ConnectionHandler` 의 "issued server command" 를 이벤트 앞으로 옮겼다(원문 명령, 취소돼도 남음 — Paper 와 같고 표지판 경로와도 같다). `spigot.yml commands.log` 에 해당하는 옵션은 없다(항상 기록).
- **후속 후보.** Paper 1.21.1 은 바닐라 명령마다 `minecraft:<이름>` 노드를 만든다. Furnace 에는 없어 `dispatchCommand("minecraft:say x")` 가 false 다 — 별도 작업.
- **A6 표지판 명령.** `ServerCore.signCommand`: 앞에 `/` 를 붙여 `<이름> issued server command: /명령` 을 INFO 로 남기고(이벤트보다 먼저 — 취소돼도 남는다), `PlayerSignCommandPreprocessEvent` 를 부른다. 취소면 돌리지 않고 `false` → `SignBlockEntity.executeClickCommandsIfPresent` 가 그 줄에서 멈추고 false (Paper 와 같다 — 클릭이 "명령 없음" 으로 처리돼 편집 등 다음 동작으로 넘어간다). 아니면 (바뀐) 명령을 표지판 소스(권한 2, 칸 가운데)로 전역 스레드에서 돌린다. 면(front)이 `BlockLevel`/`LevelServices.runSignCommand` 의 새 오버로드로 전해진다(옛 오버로드는 기본 구현이 위임해 시험용 레벨이 그대로 동작). 다른 차원의 표지판은 `DimensionServices` 가 그 차원 키를 이벤트에 싣는다.
- **이벤트 구조.** Furnace API `PlayerCommandPreprocessEvent` 의 `final` 을 풀고 하위 `PlayerSignCommandPreprocessEvent`(world·pos·front)를 더했다. Furnace 버스는 상위 클래스 구독자에게도 보내므로 기존 구독자(명령 기록 플러그인)가 표지판 명령도 받는다. 호환 쪽은 `io.papermc.paper.event.player.PlayerSignCommandPreprocessEvent extends PlayerCommandPreprocessEvent` + `org.bukkit.block.sign.Side`. 이벤트 다리는 하위 이벤트면 Paper 하위 클래스를 만든다.
- **남은 차이.** ① Bukkit `BlockState`·`Sign` 이 없어 `getSign()` 이 없다(`getSide()` 만) — BlockState 가 생기면 더한다. ② `PlayerCommandPreprocessEvent#getRecipients()` 는 호환 쪽에 아직 없다(기존 한계). ③ 표지판 명령의 실패 문장을 클릭한 사람에게 보내는 `misc.show-sign-click-command-failure-msgs-to-player` 는 안 열었다(결정 대기, 기본 false = 지금 동작). ④ 거절 문장(`messages.no-permission`) 옵션도 안 열었다(결정 대기). ⑤ 이벤트는 표지판 칸을 가진 region 스레드에서 불린다(Paper 는 주 스레드) — 호환 다리가 전역이 아닌 스레드에서는 region 빌림 손잡이를 비워 두므로, 리스너가 다른 region 의 블록을 직접 만지면 안 된다.
- **시험.** `CommandParityTest`(compat: 모든 길의 빈 칸, 없는 명령 false·바닐라 문장, 표지판 이벤트·기록·취소·바꾸기), `SignBlockEntityTest.cancelledClickCommandStops…`(server).
