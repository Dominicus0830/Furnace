## 2026-11-07 H4 실제 플러그인 시험 — 도구·함정 (H4)

- **외부 jar 는 Maven Central 로만 받을 수 있다.** 이 컨테이너에서 닿는 것은 Central(`repo1.maven.org` 와 구글 미러 `maven-central.storage-download.googleapis.com/maven2`)뿐이다. Modrinth·Hangar·SpigotMC·JitPack·CodeMC·papermc·ender.zone·playpro·enginehub·viaversion 저장소와 `api.github.com` 의 릴리스 자산은 막혀 있다(코드 검색 API 의 `text_matches` 조각만 읽힌다). Central 의 `repo1` 은 429 를 자주 내서 구글 미러가 낫다. Central 에 없는 것(확인): Vault·PlaceholderAPI·ProtocolLib·WorldEdit·EssentialsX·ViaVersion·`io.papermc:paperlib`·`fr.mrmicky:fastinv`·`org.spigotmc:spigot-api`·`paper-api`·`com.mojang:brigadier`.
- **Gradle 설정 해석은 태스크 실행 때로 미룬다.** `realWorld` 설정을 `systemProperty(…, realWorld.files…)` 로 설정 단계에서 풀면 `:furnace-server:test` 를 돌릴 때도 jar 13개를 받으려 든다(모든 모듈이 설정되므로). `CommandLineArgumentProvider`(`@InputFiles`)로 실행 때 풀었다. 설정을 만들 때 `isTransitive=false` 라서 의존 jar(예 `bstats-base`)는 직접 적어 둔다.
- **상수 풀 읽기**(`ClassRefs`): `Class` 항목의 이름은 배열이면 `[Lfoo/Bar;` 꼴이라 `[`·`L…;` 를 벗겨야 한다. 멤버 참조의 owner 가 배열(`clone`)이면 건너뛴다. 자기 jar 의 클래스는 판정에서 뺀다(그림자 포함 라이브러리, jar 들끼리도 "자기 쪽"으로 본다).
- **심볼 해석**(`ApiIndex`): 반사로 `getDeclaredMethods` 를 쓰며 `Class.forName(…, false, …)` 로 초기화 없이 찾는다. 서명(반환형 포함)이 정확해야 한다 — Bukkit 으로 컴파일된 바이트코드가 선언 클래스 기준 서명으로 찾기 때문이다. 인터페이스 참조라도 `Object` 메서드는 해석된다. 비교는 "이름·서명이 있음"까지이고 동작 동등성은 아니다.
- **정적 수치의 성격**: 요구 상한이며(안 타는 코드 경로까지 센다), 리플렉션 문자열로 가려진 접근(특히 NMS)은 하한으로만 보인다. 순위는 "요구하는 jar 수 → 멤버 호출 수" 순.
- **실제 플러그인 기동 시험(`LivePluginProbe`)**: 서버 로그의 원인은 logback 루트에 `ListAppender` 를 달아 모은다(서버 모듈이 logback 을 `implementation` 으로만 가져 호환 모듈 시험에 `testImplementation` 을 따로 더했다). onLoad 가 던져도 `PluginManagerImpl` 은 onEnable 을 이어 부르므로 로그에는 오류가 둘 이상 보인다 — 처음 것이 원인이다. 시험 서버 디렉터리는 시험마다 새로 줘야 한다(`directory(...)`), 안 주면 서로 데이터 폴더를 공유한다.
- **기준표는 생성 파일**(`realworld-baseline.properties`, 생성 문서 `compat-h4-coverage-2026-11-07.md`): 호환 API 를 넣는 PR 이 `compatReport` 로 다시 쓴다. 생성 문서는 PR 마다 같은 자리라 병합 충돌이 나기 쉽다 — 충돌하면 문서·기준표를 버리고 병합 뒤 다시 생성한다. 시험은 "없는 심볼 수 ≤ 기준"만 막는다(좋아지는 것은 통과하고 알림만 출력).
- **`DamageCause.CAMPFIRE` 확인**: `api.github.com/search/code` 의 `text_matches` 로 PaperMC/Paper `EntityDamageEvent.java` 의 선언을 봤다(`HOT_FLOOR`·`CAMPFIRE`(@Deprecated since 26.2)·`CRAMMING` 순, `KILL`·`WORLD_BORDER` 등도 있음). 1.21.1 에서 캠프파이어 피해가 어느 원인으로 매핑됐는지는 원문(CraftEventFactory 1.21.1)을 못 받아 미확인이다(현재 master 는 `CONTACT`). 상세는 `compat-h4-2026-11-07.md`.
