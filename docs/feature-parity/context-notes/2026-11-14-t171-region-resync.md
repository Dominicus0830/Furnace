# T-171 region 틱 재스케줄 — 바로 다음 틱 (2026-11-14)

- 결정 W-1 ①(도미니코): region 틱이 50ms 를 넘기면 한 주기 쉬지 않고 바로 다음 틱. 따라잡기 몰아치기 없음(Folia 방식).
- 코드: `Regionizer.nextDueAfterTick(due, tickNanos, now)` = `due + tick` 이 이미 지났으면 `now`, 아니면 `due + tick`. 예전은 지났으면 `now + tick`.
  평상시 분기만 바뀌었다. `/tick sprint`·수동 시계·병합/나누기 분기는 그대로.
- 틱 순서·같은 틱 안 순서·게임 시간(틱 수)은 그대로다 — 바뀐 것은 마감 시각뿐이다.
- **측정(클라우드 4코어, 워커 4, 한 풀·한 차원, 무거운 틱 55ms 스핀, 가벼운 틱 2ms, 10초, 시험 `RegionTickResyncTest`)**

  | 장면 | 가벼운 region TPS | 가벼운 틱 간격 p99 | 무거운 region TPS (최소~최대) |
  |---|---|---|---|
  | 무거운 3개, 예전(now+tick) | 20.00 | — | 9.50 |
  | 무거운 3개, T-171 | 20.00 | 52.4ms | 18.10~18.20 |
  | 무거운 5개, 예전 | 20.00 | 95.2ms | 9.50 |
  | 무거운 5개, T-171 | 18.7~18.9 | 57.1ms | 14.30~14.50 |

- **알려진 대가(수요 > 워커)**: 5×55ms/50ms = 5.5 > 워커 4 처럼 수요가 용량을 넘으면, 예전의 "한 주기 쉼"이 워커를 비워 주던 틈이 없어져
  가벼운 region 이 무거운 region 과 같은 줄(마감 순)에 선다. 무거운 틱 4개가 같은 순간에 끝나는 무리(코호트)가 생겨 가벼운 region 은 무리마다 한 번 돌고
  TPS 가 20 → 약 18.8(−6%), 틱 간격 p50 50 → 55.6ms. 대신 무거운 region 은 9.5 → 14.4(+50%), 전체 처리량도 늘었다. 수요가 워커 안이면 손해 없음(3개 장면).
  이 가벼운 region 의 6% 를 되찾으려면 "직전 틱이 주기를 넘긴 region 은 동시에 워커 T−1 개까지"(차원 상한 perDimCap 의 region 판)가 필요하고, 그건 별도 작업(T-171b 후보)이다.
- 같은 풀·같은 큐의 다른 region 공정성: 큐는 그대로 마감 순(가장 오래 기다린 것 먼저). 무거운 다섯의 TPS 가 14.30~14.50 으로 고르다.
- 차원 사이(공유 풀 선택기): 지연 ≥ starve-ticks(기본 2틱) 면 먼저 뽑히는 "굶은 차원" 판정은 그대로이고, 상한(`perDimCap` = T−1)이 다른 차원 몫의 워커 하나를 남긴다.
