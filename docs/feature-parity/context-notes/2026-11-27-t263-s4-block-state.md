# T-263 S4 — 블록 상태 관용구와 O2 첫판 (2026-11-27)

## 한 일

- 관용구 `NmsBlockStateIdioms`(손 코드, 검사 `pure`): 받은 상태 하나의 속성만 읽거나 바꾸는 바닐라 짧은 몸통 9가지 —
  읽기(`get`), 참거짓 ? a : b(`pick-int`), 부정(`not`), 정수 비교(`int-lt`·`int-eq`·`int-ne`), 바꾸기(`set` 인자로, `set-int` 상수로), `cycle`.
- 연결 엔진: 같은 이름 관용구의 **겹침**을 멤버 꼴([받는 쪽] + 값 + 인자)로 고른다. 맞는 것이 둘이면 문제, 없으면 문제. 맞지 않는 겹침을 해 보며 생긴 값 문제는 버린다.
- 추론기(`LinkInfer.blockState`): javac 꼴과 정확히 같은 몸통만, 상태 인자가 멤버의 유일한 `BlockState` 인자일 때만 후보.
- 채택 42줄(`1-block.auto.links`): get 14, pick-int 8, int-lt 8, int-eq 4, not 4, int-ne·set·set-int·cycle 각 1.

## 함정

- **블록 클래스의 정적 속성 필드는 껍데기에서 대부분 값이 없다**(값 몸통 채움이 읽는 것만 채워져 있다 — 예: 작물 `AGE` 는 `kinds.spec` 손 줄).
  그대로 적으면 빌드 검사가 "static field has no value in the shim yet" 으로 거의 다 거른다.
  풀이: 바닐라·Paper 의 클래스 초기화가 그 final 필드에 **다른 클래스의 공개 정적 속성 필드를 그대로** 넣는 것(바로 앞 명령이 getstatic, 넣는 곳 한 번)이면,
  연결 줄 값은 그 원래 필드(`BlockStateProperties.X`, 손 shim)로 적는다. 같은 객체다. 블록 클래스가 스스로 만드는 속성(`BooleanProperty.create`)은 여전히 값이 없어 빠진다.
- 인터페이스의 속성 필드(`CaveVines.BERRIES`)는 선언 찾기가 상위 클래스 사슬만 보므로 빠진다(3줄 안팎, 가정 아님 — 이번 범위 밖).
- O3 시험(EntityOracleTest)의 연결 파일 읽기가 `raw.indexOf(" #")` 로 주석을 잘라, 지문 멤버 줄(`  #72d9…()I -> …`)을 통째로 빼고 있었다.
  연결 파일 규칙(주석은 `# ` 로 시작하는 줄·줄 끝 ` # …`)대로 고치니 엔티티 증명이 211 → 231(지문 멤버 20개가 새로 견줘졌고 다름 0).

## O2 첫판(`BlockStateOracleTest`, fullShellsTest)

- 바닐라: 시험 자원 `o3/VanillaBlockProbe.java` 를 실행 때 바닐라 jar 에 대고 컴파일(부트스트랩한 블록 등록). shim: 껍데기 jar 앞 따로 된 로더 + 시험 서버의 블록 표(`ShimBlockProbe`). 두 탐침 몸통은 글자 그대로 같다.
- 멤버마다 그 선언에 닿는 블록 전부를 받는 쪽으로, 그 블록의 **모든 상태**를 넣는다(정적 멤버는 모든 블록의 모든 상태 — 속성이 없는 상태는 두 쪽 모두 `IllegalArgumentException`).
  상태가 아닌 인자: 정수 0·1·7·15, 참거짓 둘, 그 밖 null(관용구 몸통은 쓰지 않는다). 블록 등록 순서와 상태 집합이 두 쪽에서 같아야 한다.
- 첫 측정: 42 멤버 모두 증명(바닐라의 던지지 않은 답 둘 이상), 입력 171,870, 다름 0. 돌연변이 카나리(같은 서술자 A·B, 바닐라 A 와 shim B 를 A 의 상태로) 22짝 모두 잡음.
- 하한: 줄 40, 증명 40, 카나리 5.
