## 2026-11-11 A11 중간·낮음 수정: 화염 저항·창조 대 Invulnerable·몹 무기 마법·낙하 속성·효과 순서 등 (a11-medium-low)

점검 보고서 `docs/audit/findings/A11-entity-physics-combat.md` 의 A11-05~14 와, A11 높음 수정(`2026-11-11-a11-high.md`) 때 찾은 NoAI 몹 중력·`#damages_helmet` 투구 0.75 배. 회귀 시험 `entity/A11MediumLowTest`(16개).

### 바닐라 근거(1.21.1 `javap -c -p`, 난독화 이름)
- 화염 저항(A11-06): `btn.a(brk,F)` 오프셋 31~52 — `#is_fire`(`awg.i`) 이고 `hasEffect(bsb.l)` 이면 false. 감금·사망·무적 검사 뒤, 수면 해제 앞이라 표시·소리도 없다.
- 창조 모드(A11-07): `bsr.b(brk)` — `invulnerable && !is(bypasses_invulnerability) && !source.isCreativePlayer()`. `brk.h()` 는 **원인 엔티티**(`brk.d()` = getEntity; 생성자 `(type, direct, causing)` 에서 `c`=direct, `b`=causing)가 `abilities.instabuild`(`cmu.d`) 플레이어일 때다 → 창조 모드 플레이어가 쏜 화살·삼지창·투척물도 Invulnerable 을 뚫는다(PR #207 독립 검토 R1 — 처음엔 직접 엔티티로 잘못 적었다). Furnace 는 `Entity.Damage.creativeSource` 칸을 더하고 `LivingEntity.hurtBy` 첫 줄이 attacker 가 instabuild 플레이어면 켠다(`Damage.playerAttack(p)` 도 같은 값).
- 무적 시간 우회(A11-13): `btn.a(brk,F)` 오프셋 229~244 `awg.e`(`bypasses_cooldown`). 1.21.1 데이터에 이 태그 파일이 없다(`bypasses_*` 는 shield·armor·wolf_armor·invulnerability·effects·resistance·enchantments 뿐) → 월드 밖·`/kill` 도 무적 시간 창을 거친다(`/kill` 은 `Float.MAX_VALUE` 라 늘 통과). 플레이어(`PlayerVitals.hurt`)는 이미 태그와 무관했다.
- 투구(새로 찾음): `btn.a(brk,F)` 오프셋 180~214 — `#damages_helmet`(`awg.a`, 떨어지는 모루·블록·종유석) 이고 머리 칸이 비어 있지 않으면 `hurtHelmet`(`btn.c`) 뒤 `amount *= 0.75`. `btn.c` 는 빈 함수이고 플레이어(`cmx.c`)만 `doHurtEquipment(HEAD)` 로 투구 내구도를 깎는다(`max(1, 피해/4)`, `ArmorItem` 인 것만 — 호박은 0.75 배만). 순서: 방패 막기 → 냉각 5배 → 투구 → 무적 시간 창.
- 몹 무기 마법(A11-08): `btp.D(bsr)`(Mob.doHurtTarget) — `dae.a(level, getWeaponItem(), target, source, f)` modifyDamage(날카로움·강타·살충·찌르기) → `hurt` → `btp.a(bsr,brk)F` getKnockback(attack_knockback + 밀치기 마법) → `dae.a(level, target, source)` doPostAttackEffects(맞은 쪽 가시 + 무기의 화염 점화·살충 느림). Furnace 는 `PlayerMelee.enchantDamageBonus`·`igniteByWeapon`·`baneSlowness` 를 몹과 나눠 쓴다. **돌풍(wind_burst) 반동은 플레이어 경로만**(몹은 안 한다 — 후속).
- 낙하 거리(A11-10): `btn.m_` 오프셋 591~611 — `bsb.B`(슬로 폴링)·`bsb.y`(부양)이면 `n()`=resetFallDistance, travel 호출 앞.
- 효과 틱 순서(A11-11): `btn.aw` 오프셋 765 `eo()`(tickEffects) 는 hurtTime--(623)·invulnerableTime--(647)·사망 틱(670)·마지막으로 때린 쪽 기록(687~761) **뒤**, 몸 회전 기록(773~) 앞. `super.baseTick()`(51) 직후가 아니다.
- NoAI 이동(새로 찾음): `btn.a(exc)`(travel) 첫 줄 `da()`(`bsr`, isControlledByLocalInstance — 조종 플레이어가 없으면 `db()`=isEffectiveAi, 서버 몹은 `btp.db` = `super && !isNoAi`)가 거짓이면 move 하지 않고 `calculateEntityAnimation` 만. 그래서 NoAI 몹은 중력·밀림·`checkInsideBlocks`(가루눈 표시·거미줄) 없이 제자리다. Furnace 는 `LivingEntity.travel` 첫 줄과 `FlyingMob.travel`(바닐라도 같은 검사)에 `isEffectiveAi()` 가드를 둔다. **오징어(`cgd.a`)는 검사가 없어** NoAI 여도 물 밖에서 떨어진다(독립 검토 R2). `travelRidden` 은 그대로.
- 월드 밖(PR #207 R3): `btn.aE`(LivingEntity.onBelowWorld) = `hurt(out_of_world, 4)` — Furnace 는 몹이 사라지기만 했다. `LivingEntity.onBelowWorld` 로 같게 했다(무적 시간 창을 거쳐 약 10틱마다 4, 죽음 처리까지).
- 낙하 속성(A11-12): `PlayerVitals.fallDamage`(바닐라는 float f = (float)안전 거리; distance − f) 가 `generic.safe_fall_distance`·`generic.fall_damage_multiplier` 를 `ceil((거리 − 안전) × 배율 × 속성 배율)` 로 읽는다. 속성 맵 값은 `Player.pushVitalsInputs` 가 (기본값 + 효과 밖 수정자)로 넘기고 **효과 몫은 `PlayerVitals` 가 지금 효과로 더한다**(점프 강화가 효과 변화와 속성 동기화 틱 차이로 어긋나지 않게 — 최대 체력과 같은 방식).
- step_height(A11-14): `PlayerMoveValidator.move` 의 `step` 을 `generic.step_height` 로(속성 맵은 같은 region 스레드 값).

### 엔티티 틱 범위(A11-05·A07-07) — 이미 고쳐짐
PR #182(A10 검토 R2)가 `Region.entityTicking` 을 "체비셰프 ≤ min(sim, 시야 거리)" 로 나눠 엔티티 ≤ sim 을 이미 바닐라와 맞췄고 `world/EntityTickRangeTest` 가 지킨다. 이번에 코드는 건드리지 않았다. **남은 것은 A07-02**: 블록 엔티티(`Region.blockEntityTicking`)가 아직 `sim − 1` 이다(바닐라 sim + 1) — A07 수정 스레드 몫.
