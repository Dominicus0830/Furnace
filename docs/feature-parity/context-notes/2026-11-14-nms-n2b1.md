# N2b-1 떨어진 섹션 객체 — 함정 (2026-11-14)

- **바닐라 jar 를 소스에서 부를 때 `io` 이름 충돌**: 난독화 클래스 `io` 가 기본 패키지에 있어 `io.netty.buffer.Unpooled` 같은 소스 이름이 그 클래스로 해석돼 컴파일되지 않는다. 정답기는 netty 버퍼를 리플렉션(`Class.forName("io.netty.buffer.Unpooled")`)으로 만든다. 중첩 클래스는 소스에서 `dvq$d` 가 아니라 `dvq.d`.
- **`PalettedContainer.Configuration`(`dvq$a`)은 바닐라에서 private 레코드**: 정답기는 `var` 로 받아 넘긴다. Paper 는 이 레코드를 공개로 바꿨고 FAWE 가 5인자 생성자로 직접 쓰므로 shim 은 공개로 둔다.
- **`getAll` 은 칸마다가 아니라 서로 다른 값만**: 바닐라는 팔레트 항목마다 한 번(전역 팔레트면 저장소의 서로 다른 값마다) 부른다. N2a 시험이 칸마다 부른다고 기대하고 있어 고쳤다(처음 나온 순서).
- **안정 정체성 뒤로 shim 상태가 시험 사이에 남는다**: 한 시험이 `WORLD_SURFACE_WG` 하이트맵을 만들면 같은 청크 shim 의 `heightmaps` 에 계속 있다(바닐라 모양). "4개만 있다"는 단언은 순서에 따라 깨진다 — 보존되는 4종이 있는지로 본다.
- **용암 블록은 블록 자체도 무작위 틱**: `LiquidBlock.isRandomlyTicking` = 유체의 판정이라 용암 칸은 tickingBlock 과 tickingFluid 를 둘 다 올린다. FAWE 처럼 `tickingFluidCount` 만 0 으로 써서는 용암 섹션의 `isRandomlyTicking` 이 꺼지지 않는다.
- **PR #358 뒤 보기 판정**: 서버 섹션이 바닐라 tickingFluidCount 를 가진 뒤로, 보기에서 유체 쪽을 지금 칸 다시 세기(용암만)로 답하면 `isRandomlyTicking`=참인데 블록·유체 둘 다 거짓인 섹션이 생긴다(양동이 물). 셋 다 서버 개수로 답하게 했다.
- **`new Integer(i)` 금지**: 정답기·시험의 정체성 맵 시험 값은 `Integer.valueOf` — 폐기 경고가 컴파일 로그를 더럽히고, 정답 해시에는 영향 없음(다시 만들어 바이트가 같은 것을 확인).
