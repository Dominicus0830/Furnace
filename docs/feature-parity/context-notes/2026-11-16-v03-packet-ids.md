# V-03 패킷 번호 생성과 버전 이름 클래스 개명 (2026-11-16)

버전업 선행 작업(`docs/roadmap/version-upgrade-plan-2026-11-16.md` V-03). **결과가 바뀌지 않는 정리**다.

## 한 일
1. **먼저 시험**: `PacketClassIdsTest` — 패킷 클래스 141칸(`ID`·`ID_PLAY`·`ID_CONFIG`)마다 "상태·방향·와이어 이름"을 손으로 적어 번호표(`protocol-767-ids.txt`)의 번호와 비교. 치환 전(손으로 쓴 숫자)에 통과한 것을 확인하고 넣었다.
2. **개명**(이름만): `Protocol767` → `ProtocolTable`, `GenericHand767/Codec767/Complex767` → `GenericHand/Codec/Complex`, `ProtocolIds.protocol767()`·`PacketSchema.protocol767()` → `current()`. `EntityData767`·`EntityDataIndex767` 는 V-04(엔티티 칸 번호)에서 바꾼다.
3. **`PacketIds` 생성**(`furnace-server` `generatePacketIds`, 입력은 번호표): 서버 패킷 클래스 141칸과 `ConnectionHandler` 의 `case` 68개(상태 4곳)가 상수를 쓴다. `ProtocolTable` 의 play 이름 배열 두 개도 같은 번호표에서 읽는다(손으로 적은 목록 삭제, 그래서 두 표를 견주던 `ProtocolIdsMatchServerTableTest` 는 의미가 없어 지웠다).

## 증명 (`tools/ci/javap-same.sh`, 전·후 javap 명령 비교)
- 개명 커밋: api 788 · server 3,853 · compat 1,877 클래스 **전부 같음**(`--rename` 으로 전 쪽 이름만 바꿔 견줌).
- 치환 커밋(개명 뒤 기준): api·compat **전부 같음**. server 3,853 중 **`ProtocolTable` 하나만** 다름 — 의도된 변화: 정적 초기화에서 배열 리터럴 대신 번호표를 읽는 `names()` 가 생김(클래스 로드 때 한 번, 람다 번호 이동 포함). 패킷 클래스 138개와 `ConnectionHandler` 는 **같음**(생성 상수가 컴파일 시간 상수라 javac 가 같은 숫자를 박는다).
- 함정: `PacketIds` 를 안쪽 클래스(`PacketIds.Play.…`)로 만들면 쓰는 클래스마다 `InnerClasses` 항목이 늘어 138개가 "다름"으로 나온다 → 안쪽 클래스 없이 `PLAY_CLIENTBOUND_…` 꼴 평평한 상수로 했다.
