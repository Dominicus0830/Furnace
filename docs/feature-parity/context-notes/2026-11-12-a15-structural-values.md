# A15 구조 후속 1 — 값 클래스·직렬화 (2026-11-12)

PR #247 이 남긴 A15-01(나머지)·A15-06(Location·Vector)를 처리했다. 회귀 시험: `A15ValueTypesParityTest`(서버 없이), `A15WorldLocationParityTest`(헤드리스 서버, PR #247 검토 R3 의 "월드 있는 Location 시험"). 원문 대조는 Paper 1.21.1 사본(Youer 1.21.1 브랜치)의 `Location`·`Vector`·`BlockVector`·`BoundingBox`·`RayTraceResult`·`SpawnRule`·`CraftOfflinePlayer`·`CraftPlayer#serialize`·`Block` 키 메서드.

- **새 클래스**: `BlockVector`(같음·해시가 정수 부분만), `BoundingBox`(Paper 와 같은 resize·expand 줄임 한계·반열린 `contains`·엄격한 `overlaps`·`rayTrace`), `RayTraceResult`(위치는 복사해 들고 있다), `SpawnRule`(인자 검사 문구도 Paper 와 같다). 설정 별칭은 각각 `BlockVector`·`BoundingBox`·`SpawnRule`. `BlockFace#getDirection`(대각선이 없어 단위 벡터).
- **Vector**: 필드 `protected`(BlockVector 가 쓴다), `setX/Y/Z`·`multiply` 의 int·float 중복정의, `rotateAroundX/Y/Z/Axis/NonUnitAxis`, `getCrossProduct`·`getMidpoint`·`midpoint`·`angle`·`isInSphere`·`isInAABB`·`isNormalized`·`isZero`·`divide`·`copy`·`toLocation`·`toBlockVector`·`checkFinite`·`getMinimum/Maximum/Random/Epsilon`. **`equals` 는 클래스까지 같아야 같다**(Paper): `Vector(1,2,3).equals(BlockVector(1,2,3))` 는 거짓. 안 한 것: JOML 변환(`toVector3f/d/i`·`fromJOML`) — JOML 은 서버가 필요할 때 내려받는 라이브러리라 컴파일 클래스패스에 없다.
- **Location**: `setDirection`, `set`, `add/subtract(base, x, y, z)`, `multiply`, `zero`, `toBlockLocation`·`toCenterLocation`·`toBlockKey`, `isWorldLoaded`·`isChunkLoaded`, `getNearbyEntities/Players/LivingEntities/EntitiesByType`(월드가 없으면 `IllegalArgumentException("Location has no world")`), `x()/y()/z()`·`isFinite`·`toLocation(World)`·`checkFinite`·`asString`·`normalizeYaw/Pitch`. `add(Location)`·`subtract(Location)` 는 월드가 다르면 `IllegalArgumentException("Cannot add Locations of differing worlds")`, `distanceSquared` 의 예외 문구도 Paper 와 같다(옛 Furnace 문구는 한국어였다). 안 한 것: `toHighestLocation`·`isGenerated` — Furnace 월드 API 에 "가장 높은 블록"·"생성된 청크인가" 조회가 없다(`HeightMap` 도 없음). `getWorld()` 가 약한 참조로 월드를 들고 "World unloaded" 를 던지는 Paper 동작도 따르지 않았다(월드 객체가 늘 서버에 하나씩 살아 있다).
- **World**: Paper 의 기본 메서드 `getNearbyEntitiesByType`·`getNearbyPlayers`·`getNearbyLivingEntities`(각 6꼴)를 더했다 — `getNearbyEntities` 결과를 `isAssignableFrom` 으로 거른다. `Block.getBlockKey` 와 정적 `getBlockKeyX/Y/Z`(Paper, 1.18.1 부터 deprecated).
- **OfflinePlayer 직렬화**: `OfflinePlayer` 가 `ConfigurationSerializable` 을 잇는다(Paper 와 같다 — 그래서 `Player` 도 직렬화 가능). `CraftOfflinePlayer`: 별칭 `Player`, 키 `UUID`, `deserialize` 는 옛 `name` 키가 있으면 이름으로. `CraftPlayer`: `@DelegateDeserialization(CraftOfflinePlayer)`, `serialize` 는 `name` 키. `ConfigurationSection#getOfflinePlayer/isOfflinePlayer` 추가.
- **등록부**: `BlockVector`·`BoundingBox`·`SpawnRule`·`CraftOfflinePlayer` 를 더했다. **`Pattern`(배너 무늬)은 못 넣었다** — 호환 계층에 배너 API(`PatternType`·`DyeColor` 연동)가 아직 없다. 배너를 다루는 플러그인이 보이면 그때.
- **일부러 Paper 와 다르게 둔 것**: `Vector#deserialize` 는 `NumberConversions` 로 읽는다(Paper 는 `(Double)` 캐스트라 손으로 `x: 5` 같이 정수를 쓰면 되읽기 실패 로그). 손으로 쓴 파일이 Paper 에서 실패하던 곳에서 되는 쪽이라 호환에는 해가 없다. 반대로 `SpawnRule#deserialize` 는 Paper 와 똑같이 `(int)` 캐스트다.
- **남은 A15 항목**: PDC `LIST`·`TAG_CONTAINER_ARRAY`·`serializeToBytes/readFromBytes`(A15-06 나머지), `pathSeparator`(A15-05), `isNewChunk`·`getExpToDrop`(A15-04), 같은 우선순위 이벤트 순서(A15-07).
