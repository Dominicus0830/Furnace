## 2026-11-11 월드젠 노이즈 계산 성능 — 결과 비트 동일 최적화의 함정 (worldgen-noise-perf)

상세·숫자는 `docs/feature-parity/perf-worldgen-noise-2026-11-11.md`.

- `PerlinNoise.wrap` 빠른 길의 경계는 2^23 이다. 2^24 바로 아래 값은 `v/2^25 + 0.5` 가 1.0 으로 반올림(짝수 반올림)돼 floor 가 1 이 된다 — 2^24 로 잡으면 결과가 달라진다.
- `x / 2^25` 와 `x * 2^-25` 는 같은 비트다(같은 실수값을 한 번 반올림). 2의 거듭제곱이 아닌 수의 나눗셈을 역수 곱으로 바꾸면 안 된다(`ImprovedNoise` 의 `d6 / yScale` 은 그대로 둔다).
- 보간 순서: 바닐라 블록 루프는 Y → X → Z 순 lerp 이고, cache_all_in_cell 채우기는 `lerp3`(X → Y → Z)다. 둘은 반올림이 달라 서로 바꿔 쓸 수 없다. 지연 보간도 루프와 같은 Y → X → Z 순서로 계산한다.
- 셀 꼭짓점 값은 라우터·셀 좌표만의 함수라 이웃 청크와 나눠 쓸 수 있지만, 꼭짓점을 채우는 동안 다른 보간기를 compute 로 부르면 "지금 블록 보간값"(상태)을 돌려준다(바닐라도 같다).
  그런 구성(보간기 안의 보간기, cache_all_in_cell)이면 공유하면 안 된다 — `NoiseChunk.interpolatorsArePositionPure`. 1.21.1 오버월드·amplified·large_biomes·네더·엔드에는 없다.
- `NoiseChunk` 를 광맥 없이(`reg == null`, 시험) 만들면 보간기 수가 다르다(5 대 8). 꼭짓점 캐시 키에 구성을 넣어 섞이지 않게 했다.
- `RangeChoice` 같은 DF 레코드는 NoiseChunk `wrapped` HashMap 의 키다(구조 동등성으로 같은 보간기를 한 번만 만든다). 레코드를 클래스로 바꾸면 이 공유가 깨져 같은 보간기를 두 번 계산한다 — 값 캐시는 레코드 성분으로 더한다.
- 측정 함정: 새 `NoiseWorldSource` 는 처음 구조물 조회 때 요새 고리(128개, 바이옴 탐색)를 계산한다 — 몇 초짜리라 예열 없이 프로파일하면 표본의 20% 가 여기 간다.
- 측정 함정: 컨테이너 4코어에서 다른 java 가 돌면 벽시계 값이 크게 흔들린다. 동일성 해시와 시간 측정을 같이 돌리지 않는다.
