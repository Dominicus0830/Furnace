# 2026-11-14 N2b-2 — 원시 쓰기·고정 하이트맵 함정

- **지연 재계수와 증분 갱신의 순서**: 개수가 "모름"인 섹션에 처음 쓸 때 쓰기 전 블록으로 다시 센 뒤 ±1 해야 한다. 정확한 비공기 수(`nonAirCount`)를 먼저 고치면 재계수가 "새 비공기 수 + 옛 블록"을 섞어 그 칸을 두 번 센다. 바닐라 jar 정답기(`VanillaRawWriteOracleTest`)가 60청크 중 몇 개에서 nonEmpty 를 1 차이로 잡았다 — 디버그 출력으로 개수를 미리 읽으면 재계수가 먼저 일어나 버그가 숨는다(관찰이 결과를 바꿈).
- **바닐라 섹션 개수는 음수가 될 수 있다**(필드 대입, 컨테이너 쓰기 뒤 섹션 쓰기). "모름" 표시를 -1 로 두면 진짜 -1 과 섞인다 → `Integer.MIN_VALUE`.
- **바닐라 `Heightmap.update`·prime 의 아래로 훑기는 `ChunkAccess.getBlockState` 를 거친다** — 섹션 nonEmpty == 0 이면 공기로 본다. 하이트맵 정답이 블록이 아니라 개수 필드에도 기댄다.
- **바닐라 prime 은 못 찾은 열을 옛 값으로 둔다**(0 으로 지우지 않음). 틀린 길이 `setRawData` 뒤 블록 없는 열은 그 전 값이 남는다.
- 바닐라 `getBiomes()` 는 `PalettedContainerRO` 를 돌려준다 — 플러그인은 `PalettedContainer` 로 바꿔 쓴다(시험도 그렇게).
- **저장값 채택은 "모르는 블록 번호" 청크에서도 낡은 하이트맵을 남긴다**: 저장 때 블록이던 칸이 읽을 때 공기가 되면(모르는 상태) 저장된 하이트맵이 그 칸을 센 값 그대로다 — 바닐라도 같다. `AnvilBulkDecodeParityTest` 의 무작위 상태 풀이 표에 없는 번호(`nameOf` 가 air 를 돌려줘 거르지 못함)를 넣고 있어 기준(블록에서 다시 셈)과 갈렸다 → 풀을 `canonicalKeyOf != null` 로 거름.
