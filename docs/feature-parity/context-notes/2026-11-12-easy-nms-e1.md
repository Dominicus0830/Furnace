## 2026-11-12 엔티티 메타데이터 와이어·칸 표의 함정 (easy-nms E1, PR #236 독립 검토)

- **wolf_variant 는 holder 다.** 바닐라 1.21.1 `WolfVariant.STREAM_CODEC`(`cgi.d`)은 `ByteBufCodecs.holder(WOLF_VARIANT, 직접 코덱)`(`yv.a(akq, yx)`)이라 등록된 종류는 번호 + 1, 0 은 "직접 정의가 뒤따름"이다. `painting_variant`(`cjd.d`)와 같은 꼴이고, `cat_variant`·`frog_variant` 는 `holderRegistry`(번호 그대로)라 다르다.
  서버 `SetEntityData` 가 이전에 +1 없이 보내서 실제 클라이언트에서 pale(3) 늑대는 chestnut 으로, ashen(0)은 직접 정의로 잘못 읽혔다(바이트코드 근거, 실제 클라이언트로는 확인 안 함). 이제 고쳤고, 바이트 고정 시험이 `EntityDataKeysTest.wolfVariantIsHolderIdPlusOneLikeVanilla` 에 있다.
- **서버 직렬화기와 같은 바이트인지만 보면 이런 버그를 못 잡는다.** 둘 다 같은 실수를 하면 통과한다. 와이어 꼴은 바닐라 jar(`javap -c` 로 `static {}` 의 StreamCodec 생성 호출)와 대조하고, 고정 바이트 시험을 하나씩 둔다.
- **칸이 있는지는 번호·값 종류로 정할 수 없다.** `interaction` 9번(height, float)과 `LivingEntity.HEALTH`(9, float)처럼 우연히 맞는 (종류, 칸) 쌍이 바닐라 기준 2064개다. 주인 부류 표(`resources/entity_data/owners-1.21.1.txt`, 바닐라 클래스 계층에서 뽑음)로 본다.
- `hurt`·`hurtdir`·`damage`(8~10)는 바닐라 `VehicleEntity` 소속이다. 광산 수레·보트 따로가 아니다. 그래서 바닐라 정의는 207칸이다.
- `layouts-1.21.1.txt` 는 바닐라 jar 와 130/130 같다. `EntityDataKeysTest` 가 서버 엔티티와 어긋난다고 하면 표를 다시 만들기 전에 서버 엔티티의 `defineSynchedData` 를 먼저 바닐라와 대조한다.
