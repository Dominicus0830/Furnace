# T-260 전체 껍데기 — 함정 기록 (2026-11-23)

- 껍데기 생성자는 `super(...)` 없이 바로 던져도 검증기가 받는다(던지기 전에 `this` 를 안 쓰므로). 그래서 상위 생성자 모양을 몰라도 된다.
- 손 shim 열거형이 바닐라와 달리 상수별 몸통이 없으면 바깥 클래스가 `final` 로 컴파일된다 → 바닐라의 `X$1` 익명 몸통 클래스는 만들 수 없다(15개). 손 열거형을 상수 몸통으로 바꾸면 풀린다(T-261).
- 추상 열거형(상수마다 몸통)은 껍데기에서 구체로 만든다 — 상수를 진짜 객체로 만들어야 `values()` 가 바닐라와 같은 순서·이름을 준다. 몸통 클래스는 따로 생기되 그 상수 객체는 바깥 클래스 인스턴스다(편차, 동작 없는 멤버라 관측 차이 없음).
- 손 shim 상위가 `final` 로 둔 메서드를 껍데기가 다시 선언하면 올릴 때 `VerifyError`/`IncompatibleClassChangeError` → 상위 사슬의 `final` 메서드를 모아 뺀다.
- 서버 기동 때 호환 jar 를 "늘 쓰는 라이브러리" 표지로 훑는 곳(`PluginBootstrapper.sharedLoader`)이 껍데기 jar 까지 훑으면 json-simple·commons-lang3·log4j 가 늘 준비 대상이 되어, 자동 내려받기가 꺼진 기본 설정에서 오류 줄이 난다 → 껍데기 jar(`CompatJars.SHELLS`)는 훑지 않는다.
- 시험 로더 부모를 앱 로더로 두면 JUnit 클래스패스의 호환 클래스가 먼저 잡혀 "껍데기 jar 밖" 판정이 틀린다 → 부모는 플랫폼 로더.
- 시험 로더에 바닐라 라이브러리의 `log4j-slf4j2-impl` 과 서버 제공 `log4j-to-slf4j` 가 함께 있으면 slf4j 를 처음 쓰는 클래스(`NmsShell`·Paper 내부 다수)의 초기화가 `LoggingException` 으로 실패한다 → 시험 클래스패스에서 뺀다(Furnace 는 그 백엔드를 싣지 않는다). 검토 전 "손 shim 상위 초기화 실패 209" 는 전부 이것이었다.
- NMS 밖 범위는 연결기가 보지 않으므로(NMS 이름 든 클래스만 변환) 값 없는 필드가 조용히 null 이 된다 → 그런 껍데기는 `<clinit>` 에서 던진다. 이때 RuntimeException 을 던지면 JVM 이 첫 번만 `ExceptionInInitializerError` 로 싸서 `catch (NoClassDefFoundError e)` 감지가 첫 호출을 놓친다 → **Error(`NoClassDefFoundError` 하위)를 던진다**(JVMS 5.5: Error 는 싸지 않음). 두 번째부터 JVM 은 원래 예외 대신 이름만 적은 원인을 주므로, 시험은 실패 메시지가 아니라 클래스 파일(상위 클래스·인터페이스까지)에서 덫을 찾는다.
- 추상 열거형을 구체로 만들면 자기 추상 메서드와 상수 몸통에만 있던 인터페이스 구현이 `AbstractMethodError` 가 된다 → 둘 다 표지 달린 던지는 몸통으로.
- `NmsSymbols` 가 private 필드를 건너뛰면 private 껍데기 필드가 리플렉션 덫을 빠져나간다 → 표지는 private 도 모으고 링크용 집합에는 안 넣는다.
- 바닐라 라이브러리 jar(`work/libs`)는 상위 타입 해석에만 쓰고 "이미 있음"으로 치지 않는다 — Furnace 가 DFU 등을 싣지 않으므로 바닐라 표에 있는 `com/mojang` 클래스는 껍데기로 만든다.
