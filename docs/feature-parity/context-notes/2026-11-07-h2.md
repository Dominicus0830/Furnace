## 2026-11-07 호환 계층 명령·스케줄러 (H2)

설계·구성·한계는 `docs/feature-parity/compat-h2-2026-11-07.md`. 여기에는 다음 사람이 걸릴 함정만 적는다.

- **H1 이 없었고 Bukkit API jar 를 받을 수 없어**(`repo.papermc.io`·`hub.spigotmc.org` 프록시 403, Maven Central 에 paper-api·spigot-api 없음) H2 는 Bukkit 타입 없는 호환 코어로 만들었다. `org.bukkit.*` 껍데기는 H1 이 Bukkit API 를 들일 방법을 정한 뒤 붙는다.
- 시험 서버에서 **플레이어를 `join` 한 직후에는 엔티티 스케줄러 작업이 돌지 않는다.** 플레이어가 region 에 올라가기까지 틱 6~7개가 필요하다(`join` → `tick(10)` 뒤에 예약해야 한다). Furnace `EntityScheduler` 를 직접 써도 같다.
- 시험 서버에서 `execute("op 이름")` 은 `TestPlayer` 의 오프라인 UUID 와 안 맞아 플레이어에게 권한이 안 생긴다(메시지는 "Made steve a server operator" 로 소문자). 권한 시험은 `player.addAttachment(plugin).setPermission(node, true)` 를 쓴다.
- `CommandRegistryImpl.register` 는 `BasicCommand.permission() == null` 이고 `furnace-plugin.yml` 에 그 명령의 `permission` 이 있으면 그 권한을 덧씌운다(트리 숨김이 그 권한으로 바뀐다). 호환 어댑터는 `setPermission` 으로 바꾼 권한·세미콜론 여러 권한을 따르려고 `permission()` 이 빈 문자열을 돌려줘 덧씌움을 막고 `canUse` 로 직접 판정한다.
- `BasicCommand.suggest` 는 연결 스레드에서 불린다. 호환 어댑터가 전역 스레드로 넘겨 `Future.get(1s)` 로 기다린다 — 연결 스레드가 막히는 대신 옛 완성기가 주 스레드에서 돈다. 전역 스레드가 길게 막히면 자동완성이 빈 목록이 된다(로그 경고).
- 동기 작업 하나가 느리면 같은 틱의 뒤 작업과 전역 틱 전체가 밀린다(Bukkit 주 스레드와 같은 성질). `/timings`(프로파일러)에는 플러그인 몫으로 잡힌다.
