## 2026-11-08 블록 틱 범위·횃불 과열 기록 (A07 수정: A07-01·02·03·04·08)

2차 점검 A07 보고서(`docs/audit/findings/A07-redstone-update-order.md`)의 치명 1·높음 2와 함께 풀리는 A07-04·08 을 고쳤다.

### 횃불 과열 기록(A07-01·04)
- 바닐라 `RedstoneTorchBlock.RECENT_TOGGLES` 는 레벨 키 정적 `WeakHashMap`. Furnace 는 region 스레드 여럿이 잠금 없이 써서 표가 깨졌다(재현: 8 스레드 모두 `WeakHashMap.get` 무한 반복).
- 이제 `ChunkLevel` 마다 `RedstoneTorchToggles` 하나(`BlockLevel.redstoneTorchToggles()`). region 스레드만 쓴다. `absorb` 는 두 목록을 시각 순으로 섞고, `splitTo` 는 칸이 속한 쪽으로 옮긴다 — 차원 전체로 보면 바닐라 목록을 청크별로 나눠 든 것과 같다.
- 같은지 따질 점: 바닐라는 목록 앞에서부터 60틱 넘은 것을 지우고(시각 순이라 모두 지워짐) 그 칸의 개수를 센다. 개수는 칸별이라 목록을 나눠도 결과가 같고, 각 목록을 시각 순으로 두면 지우기도 같다.

### 블록 틱 범위(A07-02·03·08)
바닐라 1.21.1 바이트코드(`aqk` DistanceManager, `ara` TickingTracker, `aqb` ChunkMap, `eyq` LevelTicks, `aqu` ServerLevel, `dvi` LevelChunk):
- 플레이어 TickingTracker 표 레벨 = `max(0, 31 − sim)`(`aqk.g()`), 청크마다 +1. 블록 틱 = 레벨 ≤ 32 → 체비셰프 ≤ `min(sim, 31) + 1`. 엔티티 틱 = ≤ 31 → ≤ sim. 시뮬레이션 거리는 자르지 않는다.
- 청크 단계: `aqb.a(int)` 가 시야 거리를 2~32 로 자르고 그 안 청크에 레벨 31 플레이어 티켓 → 시야 + 1 까지 BLOCK_TICKING. 두 조건 모두 가장 가까운 플레이어 거리로 정해지므로 플레이어 쪽 블록 틱 반경 = `min(min(sim,31)+1, 시야+1)`.
- `/forceload`(레벨 31)·플러그인 ticking 티켓: 그 청크 + 둘레 1칸. 영역 티켓(포털 3·드래곤 9·순간 이동 뒤 1, 레벨 33 − 거리): 거리 − 1 안(`World.blockTicketed`).
- 예약 틱: `eyq` 생성자 술어 `aqu.d(long)` = 엔티티 로드됨 && isPositionTicking. 범위 밖 청크 컨테이너는 그대로 두었다가 범위에 들면 돈다. 한도(65536)는 범위 안에서 꺼낸 것만 센다. Furnace `BlockTicks` 는 범위 밖에서 꺼낸 예약을 청크별로 `parked` 에 두고 매 틱 청크마다 한 번 다시 본다(같은 예약이 매 틱 큐를 들락거리지 않게).
- 블록 이벤트: `aqu.aw()` 가 `shouldTickBlocksAt` 거짓인 이벤트를 모아 끝에 다시 넣는다.
- 블록 엔티티: `dvi.h(pos)` = 보더 안 && BLOCK_TICKING && 엔티티 로드됨, 그리고 `shouldTickBlocksAt`. 보더는 `tickBlockEntities` 호출 처음 값으로 본다(보더 객체 잠금을 블록 엔티티마다 잡지 않게).
- Furnace `Region.blockTicking` 이 위 판정을 한 곳에서 한다(청크가 이 region 소유 + 엔티티 로드됨). 예약 틱·블록 이벤트는 이 region 이 갖지 않은(내려간) 청크의 것을 예전처럼 그대로 돌려 버린다(남겨 두면 쌓이기만 한다 — 바닐라는 이런 예약을 아예 받지 않는다).

### 남은 차이(이 수정 밖)
- 엔티티 틱은 아직 `sim − 1`(`Region.entityTicking`). 바닐라는 ≤ sim(A07-07) — 몹 쪽 점검·수정이 맞춘다.
- Furnace 는 플레이어 청크를 `min(서버 시야, 클라이언트 렌더 거리)` 안만 올린다. 바닐라는 서버 시야 + 2 까지 올리고 시야 + 1 까지 블록 틱을 준다 — 기본 설정(sim 10, 시야 10)에서 거리 11 청크는 바닐라에서 블록 틱을 받지만 Furnace 에서는 올라와 있지 않다. `/forceload` 청크의 둘레도 Furnace 는 올리지 않는다(올라와 있을 때만 블록 틱). 청크 로드 쪽 일이다.
- 관전자(spectatorsGenerateChunks 꺼짐)는 바닐라에서 티켓을 걸지 않아 주변이 틱하지 않는다. Furnace 블록·엔티티 틱 판정은 관전자도 센다(예전과 같음).
- A07-05(불러온 예약 틱 순번)·A07-06(`isHandlingTick` 범위)은 고치지 않았다.
