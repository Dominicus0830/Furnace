## 2026-11-20 플레이어가 아닌 엔티티의 텔레포트·차원 이동 나머지 (T-196 나머지, #506 후속)

대조: Paper 1.21.1-133 jar(`Entity#changeDimension`·`setRemoved`·`restoreFrom`, `CraftEntity#teleport`·`teleportAsync`,
`Entity#loadChunksForMoveAsync`, paper-mojangapi 의 `EntityTeleportEvent`·`EntityPortalExitEvent`·`EntityTeleportEndGatewayEvent`).

- **같은 월드 다른 region 으로 텔레포트**: Paper 는 같은 월드면 `moveTo` + `setYHeadRot` 만 한다(청크를 읽지 않는다).
  Furnace 도 같은 엔티티 객체를 옮기고, 틱 끝 `Region.handOffEntities()` 가 새 칸 주인 region 으로 그대로 넘긴다(추적기 포함).
  region 은 자기 칸의 엔티티만 틱하므로 넘어가기 전 한 틱 동안 두 번 틱되지 않는다. `teleport()`(비동기)는 Paper `teleportAsync` 처럼
  목적지 상자 ±3블록(1e-7 넓혀 `>>4`) 범위 청크를 먼저 읽는다.
- **다른 월드로 간 엔티티의 핸들**: Paper `setRemoved` 는 CHANGED_DIMENSION 으로 지워진 비플레이어의 스케줄러를 은퇴시키지 않고,
  `restoreFrom` 이 `bukkitEntity.setHandle(this)` 를 먼저 부른다 → 플러그인이 쥔 Entity 와 예약 작업이 새 엔티티로 이어진다.
  Furnace 는 `EntityTasks.rebind` 로 같은 대기열을 새 엔티티에 붙이고(`inheritApiTasks`), 도착 실패면 은퇴시킨다.
- **포털 경로 이벤트 순서(Paper changeDimension, 비플레이어)**: 살아 있지 않으면 null → to = (대상 월드, 전이 좌표, 전이 yRot, **지금 xRot**)
  → `portalProcess` 가 END_GATEWAY 이고 입구 칸 블록 엔티티가 관문이면 `EntityTeleportEndGatewayEvent`, 아니면 `EntityTeleportEvent`
  → 취소·to null 이면 null → `portalProcess != null` 이면 `EntityPortalExitEvent(from, to, before=지금 속도, after=전이 속도)`, 안 취소·to 있으면 to·after 를 쓴다
  → 같은 월드면 같은 엔티티 `moveTo` + 속도, 다른 월드면 새 엔티티.
  `EntityTeleportEndGatewayEvent` 는 HandlerList 가 없다(EntityTeleportEvent 것을 쓴다), `EntityPortalExitEvent` 는 자기 것.
- **Furnace 포털 경로**: 듣는 처리기가 없으면 예전처럼 한 번에 건넌다(비용 없음). 있으면 대상 스레드에서 목적지를 먼저 정하고,
  엔티티를 따라가는 대기열로 **다음 틱**에 돌아와 이벤트를 부른 뒤 떠난다(엔티티 소유 스레드에서 이벤트를 부르기 위해).
  바뀐 도착지로 갈 때 PLACE_PORTAL 티켓은 엔드 단상·관문·새로 만든 지옥문이면 도착 칸으로 옮기고, 찾은 지옥문이면 그대로 둔다(`DimensionTransition.ticketAtArrival`).

### 남은 차이(알려진 것)
1. 처리기가 있을 때 포털로 떠나는 시점이 목적지 준비 시간 + 1틱 늦다(Paper 는 같은 틱). 플러그인 teleport 의 두 번째 EntityTeleportEvent 는
   Paper 처럼 portalProcess 가 없으면 바꾼 to 를 버린다(취소·null 만 효과). 결정 항목: `docs/user-todo/entries/2026-11-20-t196-rest.md`.
2. 다른 월드로 가는 중(떠난 뒤 도착 전)에는 핸들의 주인 스레드가 없다: 읽기는 스냅숏, `*Now` 쓰기는 `ThreadOwnershipException`.
3. `teleportNow` 로 다른 region 의 안 읽힌 청크에 보내면 엔티티는 디스크에 저장된다(Paper 는 메모리에 남긴다). 다시 읽히면 같은 UUID 로 돌아온다.
4. 엔드 관문, 같은 월드로 바뀐 포털 이동은 여전히 새 엔티티 객체를 만든다(핸들·작업은 따라가지만 엔티티 id 가 바뀐다).
5. Bukkit `EntityPortalEvent`(포털 들어가기 전)는 아직 다리 없음(범위 밖).
6. `preloadAround` 의 청크 티켓 수명(PLUGIN, 20틱)은 가정.
