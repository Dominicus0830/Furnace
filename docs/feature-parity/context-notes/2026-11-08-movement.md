# P4 이동·텔레포트 정합 (movement) — 2026-11-08

`docs/feature-parity/paper-vs-spigot-2026-11-08.md` 의 C7(`PlayerMoveEvent` 간격)과 D1(`Entity#teleport` 반환·승객·내리기), 후속 후보 "processMoves 텔레포트 가지 상태 검사"를 Paper 1.21.1 관측 동작대로 맞췄다. 플러그인이 없으면 바닐라와 같다(이벤트는 구독자가 있어야 불린다).

## C7 — PlayerMoveEvent 간격
- 규칙(CraftBukkit `handleMovePlayer`, Paper 가 이 블록을 안 건드림 — 1.21.1 Paper 패치 어디에도 이 문턱 코드가 없고, `PlayerJumpEvent`·`PlayerFailMoveEvent` 패치가 같은 `lastPosX…lastPitch` 틀을 그대로 쓴다): **마지막으로 알린 자리**에서 거리² > 1/256 이거나 |Δyaw|+|Δpitch| > 10° 일 때만 부른다. 문턱 아래 움직임은 기준을 옮기지 않아 쌓여서 넘으면 부른다. 수치(1/256, 10°)는 CraftBukkit 원문을 컨테이너에서 못 읽어 기억에 의존한다.
- 구현: `Region.movedEvent`. 기준은 `Player.moveEventBase*`(소유 region 스레드 전용). 접속·텔레포트 직후에는 기준이 비어 있고 다음 이동 패킷이 도착 자리를 기준으로 잡는다(그 패킷은 문턱을 넘을 때만 부른다) — CraftBukkit 이 텔레포트마다 `lastPos` 를 도착 자리로 맞추는 것과 같다.
- 전에는 위치가 조금이라도 바뀌면 매번 불렀고 회전만 바뀌면 안 불렀으며, from/to 의 시선은 둘 다 현재 시선이었다. 이제 from 은 알린 위치+시선, to 는 새 위치+시선이다. 시선 감지·AFK 플러그인이 쓸 수 있고, 떨림 이벤트가 줄어 성능에도 이득이다.
- 취소: 서버 위치와 시선을 알린 자리로 되돌리고 보정 텔레포트(시선 포함, `PlayerTeleportEvent` 우회 — 전과 같다). 죽은·자는 플레이어는 CraftBukkit `isImmobile` 처럼 부르지 않는다. 탄 동안(회전만 받는 가지)은 그대로 부르지 않는다.
- Furnace API `PlayerMoveEvent` 에 `hasChangedPosition()`·`hasChangedOrientation()` 추가(호환 모듈의 Bukkit 이벤트는 이미 있었다).

## D1 — Entity#teleport 의 진짜 결과
- API: `Entity.teleportNow(Location)` 추가(소유 region 스레드에서 곧바로 옮기고 진짜 결과). 비동기 `teleport()` 의 Future 도 같은 규칙을 쓴다.
- 규칙(Paper `CraftEntity#teleport` / `CraftPlayer#teleport`, flags 없음): 사라진 엔티티·승객이 타고 있는 엔티티는 `false`(아무것도 안 바꾼다), 탈것을 타고 있으면 **먼저 내린 뒤** 옮긴다. 플레이어는 연결이 없거나 `PlayerTeleportEvent` 가 취소되면 `false`. 플레이어 이벤트의 도착 시선은 이제 요청한 yaw/pitch 다(전에는 현재 시선).
- 호환 모듈 `CraftEntity#teleport`: 전에는 늘 `true`. 이제 소유 스레드(플레이어는 어느 스레드나)에서 진짜 결과를 돌려준다. 소유 스레드가 아니면 옮기기를 맡기고 핸들이 살아 있으면 `true`(Paper 라면 주 스레드가 아니라는 오류인 호출 — 결과가 필요하면 `teleportAsync`).
- 남은 차이(사용자 결정 목록 참고): 다른 차원·다른 region 으로의 엔티티 텔레포트는 아직 `false`(핸드오프 미구현 — 이전에도 비동기 Future 는 `false` 였고 `Entity#teleport` 만 거짓으로 `true` 를 돌려줬다). `TeleportFlag`(승객·탈것 유지)와 비플레이어의 `EntityTeleportEvent` 는 없다.

## 독립 검토 반영(PR #152)
- 시선 비교는 패킷의 감기지 않은 yaw/pitch 원값끼리(CraftBukkit `to.setYaw(packet.yRot)`) — 감긴 서버 yaw 로 비교하면 북쪽(±180)을 2° 지날 때 358° 로 보여 헛 이벤트가 난다. 취소 복구에만 `wrapDegrees` 로 감아 서버에 넣는다.
- 플러그인 엔티티 텔레포트는 속도를 0 으로 지운다(Paper `moveTo`). 죽은 플레이어(체력 0)의 `teleport` 는 이벤트 없이 `false`(체력 줄은 기억 기준, 1.21.1 원문 미확인).
- 후속 후보: Paper `CraftPlayer#teleport` 는 열린 컨테이너 창을 `InventoryCloseEvent.Reason.TELEPORT` 로 닫는다(이 PR 전부터 없던 차이).

## 후속 후보 "processMoves 텔레포트 가지 탄 상태 검사" — 검토 결과 고치지 않음
바닐라 `handleAcceptTeleportPacket` 은 탄 상태와 상관없이 `absMoveTo` 로 서버 위치를 맞춘다. Furnace 도 같고, 보정 텔레포트를 보내는 길(플러그인 `teleport`·`/tp`·`stopRiding`)이 모두 먼저 내린 뒤 보낸다. 탄 채로 도착하는 텔레포트 표본은 승객 자리를 탈것이 다음 틱에 다시 정하므로 관측되는 차이가 없어 코드를 바꾸지 않았다.

## 시험
`MovementParityTest`·`MovementReviewTest`(server): 시선만 돌린 이동(10° 문턱, 기준 유지)·떨림 무시와 누적·취소 시 시선 복구·텔레포트 뒤 기준 다시 잡기, 엔티티 텔레포트(승객 거부·탈것 내리기·다른 차원·사라짐), 플레이어 텔레포트(이벤트 취소·내리기·요청 시선). `CraftTeleportResultTest`(compat): Bukkit 어댑터가 진짜 결과를 돌려준다.
