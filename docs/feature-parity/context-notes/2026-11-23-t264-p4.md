# T-264 P4 변환 가족 — 함정 (2026-11-23)

- **Paper `Registries` 필드의 형 인자는 손 shim 에서 `Object` 로 지워져 있다.** 손 `Registries` 는 NMS 형이 없던 필드를 `ResourceKey<Registry<Object>>` 로 두었다(예: `GAME_EVENT`·`POTION`). 그래서 생성기는 "M → 필드"를 손 클래스가 아니라 **Paper 서명표의 일반 서명**(`ResourceKey<Registry<M>>`)에서 찾는다. 서술자는 모두 `ResourceKey` 라 바이트코드 참조는 같다. 손에 없는 필드는 합치기가 값 없는 정적 필드로 덧붙이므로 실행 때 null — 도우미가 null 키를 껍데기 오류로 바꾼다.
- **`Class.getMethod` 는 그 클래스 메서드 서술자의 형을 전부 푼다.** 시험에서 한 메서드라도 없는 형(`net/minecraft/zz/NoReg`, 호환 계층에 없는 `org/bukkit/loot/LootTable`)을 서술자에 가지면 다른 메서드를 부를 때도 `NoClassDefFoundError`. 단위 시험 픽스처의 서술자에는 실제로 있는 형만 쓴다.
- **NMS 내장 레지스트리 shim 은 서버가 서야 값이 생긴다**(`Furnace.server().gameRegistries()`). 상태 효과·속성 등의 실제 왕복은 `FurnaceTestServer` 를 띄우는 `CraftConvertTest` 에서, 생성기 단위 시험(`ShellMergeTest`)은 검증기 통과·도우미로 가는 길(null·없는 레지스트리)만 본다.
- **"레지스트리가 아직 없으면 던지는 진짜 몸통"과 "늘 던지는 다리"는 다르게 센다.** P3 에서 API 형으로 좁히는 다리는 Furnace 가 그 객체를 영영 주지 않으므로 껍데기로 뒀다. 변환 가족은 레지스트리만 들어오면 몸통을 고치지 않고 사므로 c 칸으로 센다. 다만 `getHandle` 뿌리(`THROWING_ROOTS`)는 "던지는 getHandle" 을 세는 목록이라, 레지스트리 없이 늘 던질 `CraftTrimMaterial` 등은 몸통을 채우지 않고 남겼다.
- **바닐라 서버 레지스트리 묶음은 내장 레지스트리 전부를 담는다**(STATIC 층). Furnace `NmsRegistryAccess` 가 데이터 팩·일부 내장만 돌려줘 `registryOrThrow(ATTRIBUTE)` 가 "Missing registry" 였다 — 호환 계층의 내장 레지스트리 5개를 더했다.
