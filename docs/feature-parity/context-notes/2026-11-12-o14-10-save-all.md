# /save-all 비차단화 (P-O14-10, 2026-11-12)

## 바닐라 1.21.1 대조 (javap, `anz` SaveAllCommand · `MinecraftServer` · `dwl` IOWorker · `dwq`/`dwp` RegionFileStorage/RegionFile)

- `SaveAllCommand.saveAll(source, flush)`: `commands.save.saving`(알림 없음) → `saveEverything(suppressLogs=true, flush, forced=true)` → false 면 `commands.save.failed` → `commands.save.success`(관리자 알림) → 1.
- `saveEverything` 은 레벨이 하나도 없을 때만 false. 디스크 오류는 IOWorker 가 로그만 남긴다(성공 메시지는 그대로).
- `forced=true` 라 `/save-off` 상태에서도 저장한다(백업 스크립트 `save-off; save-all flush` 의 전제).
- flush 없음: 청크를 직렬화해 IOWorker 에 넣기까지만(기록은 기다리지 않는다). 플레이어 파일·level.dat 은 그 자리에서 쓴다.
- flush: `ChunkMap.flushWorker` → `IOWorker.synchronize(true)` = 넣은 기록이 다 끝난 뒤 `RegionFileStorage.flush` → 파일마다 `FileChannel.force(true)`. 실패 로그 문구 `Failed to synchronize chunks`.
- flush 일 때 로그 두 줄: 차원마다 `ThreadedAnvilChunkStorage ({}): All chunks are saved`(이름 = `ChunkMap.getStorageName` = 차원 저장 폴더 이름: 오버월드는 월드 폴더, `DIM-1`, `DIM1`), 끝에 `ThreadedAnvilChunkStorage: All dimensions are saved`.

## Furnace 구현

- `/save-all` 본문은 저장을 시작만 하고(`ServerCore.saveAllAsync(flush)`), 결과를 `source.defer(future, 10분)` 로 맡긴다. 이 명령 컨텍스트만 멈추고 전역 틱(시간·날씨·스케줄러·콘솔 입력)은 계속 돈다. 뒤 명령은 바닐라처럼 저장이 끝난 뒤 돈다(CommandQueue FIFO). RCON 응답도 저장이 끝난 뒤 두 줄을 함께 돌려준다.
- 기다림은 `maintenance.ServerSave` 의 저장 스레드 하나(`Furnace Save Thread`)에서, 저장은 한 번에 하나씩. 플레이어 저장 요청·level.dat 값 옮기기(`ServerCore.writeLevelData`, 전역 상태)는 부른 스레드(=전역)에서 바로, level.dat 파일 쓰기는 저장 스레드에서.
- 지연 결과의 기본 한도 5초는 그대로 두고 `defer(future, timeout)` 로 명령마다 늘릴 수 있게 했다.
- 종료: FLUSH_WORLDS 머리에서 저장 스레드를 닫고 돌던 저장을 최대 30초 기다린다. **저장 스레드를 인터럽트하지 않는다** — `FileChannel.force` 중 인터럽트는 지역 파일 채널을 닫아 뒤 기록이 실패한다.
- 차이(관측 결과 아님): 바닐라는 저장 동안 서버 전체가 멈추고 뒤에 따라잡거나(2초 넘으면 건너뜀) 하지만, Furnace 는 저장 동안에도 게임 시간이 흐른다. tick 함수는 앞 실행이 명령 큐에서 기다리는 동안 건너뛴다(FunctionManager 기존 동작).
