# T-211 2단계 — 플러그인이 부른 구조물 배치 (2026-11-17)

- **Paper 의 `StructureStart#placeInChunk` 는 레벨을 `TransformerGeneratorAccess` 로 감싼다.** 감싸개의 `setBlock(인자 3개)` 은 `setBlock(…, 512)` 로 가서
  조각 쓰기는 모두 인자 4개·깊이 512 로 레벨에 닿는다. 그런데 `StructureTemplate#placeInWorld` 는 감싸개를 벗겨(`getHandle()`) 원래 레벨의 인자 3개를 부른다.
  평범한 `BlockStateListPopulator` 는 인자 4개를 재정의하지 않아(`DummyGeneratorAccess` → 거짓) 조각 블록은 버리고 템플릿 블록만 모은다 — 그대로 따른다.
  `afterPlace` 는 감싸지 않은 레벨로 불린다.
- **템플릿 NBT 칸은 먼저 방벽을 flag 20 으로 쓴다.** Paper 나무 기록(`captureTreeGeneration`) 아래에서는 방벽 칸이 "부술 수 없는 블록"이라 다음 쓰기가 거절되어
  FAWE `//structure` 결과에 블록 엔티티 칸(상자·화로·침대 등)이 방벽으로 남는다. Paper 와 같은 결과이므로 고치지 않는다.
- **스포너는 레벨 난수를 부르지 않는다.** Paper `placeCraftSpawner` 의 `CraftBlockStates.getBlockState(LevelReader…)` 는 `registryAccess()` 만 묻고 월드 없는
  상태를 만들어 `setSpawnedType` 이 `RandomSource.create()` 를 쓴다(`isPlaced()` 거짓). 처음엔 레벨의 `getRandom()` 을 부른다고 잘못 읽었다(검토 #497).
- **FAWE 는 배치 난수로 `serverLevel.getRandom()` 을 주고 populator 의 `getRandom()` 도 같은 원천이다.** 조각의 `world.getRandom()` 자리(사막 피라미드 지하실·저택,
  몹 `finalizeSpawn`)는 같은 수열에서 섞여 뽑힌다 — 레벨 난수는 뽑을 때마다 레벨에 묻는다.
- **이글루 조각은 놓을 때 지표 높이로 내려간다**(`IglooPiece#postProcess`). 시작의 상자는 옮기기 전 값이라 시험에서 상자 높이만 보면 아무것도 없다.
- **몹 `finalizeSpawn` 은 아직 이식이 없다** → 그 자리에서 오류(T-221). 이글루 템플릿은 `finalizeEntities` 가 꺼져 있어 주민·좀비 주민을 만들기만 한다(된다).
