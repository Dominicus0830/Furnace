# T-141 물결 1-E3: getChunkAtAsync·refreshChunk·Chunk#getBlock (2026-11-14)

## 기준(Paper 1.21.1)
- `CraftWorld.getChunkAtAsync(x, z, gen, urgent)`(MC-Utils 패치): 주 스레드에서 이미 올라와 있으면 완료된 Future.
  아니면 moonrise `ChunkSystem.scheduleChunkLoad(…, gen, FULL, addTicket=true, priority, cb)` 뒤 `scheduleOnMain` 으로 완료한다(없으면 null).
  urgent 는 우선순위(HIGHER/NORMAL)만 바꾼다. 올리는 동안 티켓을 걸고, 청크를 얻으면(Add-Plugin-Tickets-to-API-Chunk-Methods 패치)
  PLUGIN 티켓(레벨 33 — 올려만 두고 틱은 안 함)을 `min(20, chunk-gc.period-in-ticks)` 틱 붙잡는다 → 완료 뒤 약 1초 남는다.
- 콜백판(Consumer·ChunkLoadCallback)은 `thenAccept(cb).exceptionally(경고 "Exception in chunk load callback")`.
- `refreshChunk`: 청크 홀더가 없으면 false. 있으면 그 청크를 보는 플레이어에게 청크 패킷을 다시 보내고 true.
- `CraftChunk.getBlock`: x·z 0..15, y 는 minBuildHeight..maxBuildHeight(최고 높이도 받는다). 문구 "x out of range (expected 0-15, got N)".

## Furnace 구현
- furnace-api `World#loadChunkAsync(cx, cz, generate)`: 결과는 그 청크를 가진 region 스레드에서 완료된다(Folia 와 같은 뜻 — Paper 의 주 스레드 자리).
  - 그 region 스레드에서 이미 올라와 있으면 완료된 Future.
  - generate=false: 올라와 있지 않으면 그 지역 파일 IO 레인에서 `RegionFileStore.hasChunk` 로 본다(앞선 저장 뒤에 줄 선다). 없으면 false, 있으면 보통 로드.
  - 디스크 저장소가 없는 월드 소스(시험 서버 평지 등)는 "저장된 청크 없음"으로 false.
- `World#refreshChunk`: 올라와 있지 않으면 false, 아니면 주인 region 에서 `Region.resendChunk`(지금 상태 스냅샷)로 보내고 true.
- 올린 청크(이미 올라와 있던 빠른 길 포함)에 20틱 시간 티켓(`World.addTicket(cx, cz, 0, 20)`, 레벨 33 과 같은 반경 0)을 건다 —
  퇴출 유예(`chunk-eviction-grace-ticks`, 1 까지 허용)가 20 보다 짧아도 Paper 처럼 1초는 남는다.
- 완료 스레드: 사슬을 주인 작업 안에서 잇는다(`submitAtChunk(r -> r.loadChunk(cp).whenComplete(... out.complete ...))`). 밖에서 thenCompose 로 이으면
  주인 작업이 붙이기보다 먼저 끝났을 때 돌려준 Future 가 호출 스레드에서 끝날 수 있다. 단 플러그인이 **이미 끝난** Future 에 붙인 작업은
  붙인 스레드에서 돈다(CompletableFuture 규칙, Paper 도 같다) — api javadoc 에 `thenAcceptAsync(..., scheduler(pos)::execute)` 안내.
- generate=false 의 줄서기 순서(검토 R4): 퇴출은 주인 region 스레드에서 `saveChunkAsync`(레인 제출) → `removeChunk` 순이고, 확인 작업도 같은 스레드에서
  그 뒤에 돈다. 확인이 "안 올라와 있음" 이면 그 청크의 퇴출 저장은 이미 레인에 있으므로 뒤에 넣은 hasChunk 는 그 뒤에 선다.
  이 순서를 지키는 시험은 아직 없다(검토 변이 M3 — 레인 대신 공용 풀 — 이 살아남음, 퇴출 유예 1틱 월드로 잡는 시험은 다음에).
- generate=false 탐색은 `submitAtChunk` 로 주인 없는 구역에 region 을 만든다(검토 R7). 정확성 문제는 없고, 수천 청크를 훑는 플러그인이 생기면
  주인 없을 때 호출 스레드에서 바로 레인에 넣는 길을 잰 뒤 정한다.
- urgent 는 무시한다(Furnace 생성 대기열에 우선순위가 없다. T-170 재설계가 들이면 연결).

## 다른 점(가정·남김)
- generate=false 로 디스크의 미완성(proto) 청크를 만나면 Paper 는 null, Furnace 는 보통 로드처럼 마저 생성한다(디코더가 proto 를 버리고 새로 만든다). 드문 경우라 그대로 둔다.
- Paper 는 콜백을 주 스레드에서 돌리지만 Furnace 는 그 청크의 region 스레드다. 다른 region 의 청크를 콜백 안에서 만지면 ThreadOwnershipException.
