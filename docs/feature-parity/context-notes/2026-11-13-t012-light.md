# T-012 빛 묶음 — 바닐라 대조와 다를 수 있는 점 (2026-11-13)

T-012 = O07-05(빛 층 지연 할당·균일 층 공유) + O02-01(디스크 빛 읽기, `attachPrecomputed` 가장자리 맞추기는 유지) + O07-06(`pushEdge` 균일 섹션 건너뛰기) + 빛 검사·`markLightChanged` 박싱 제거.

## 바닐라 근거 (1.21.1)

- `ChunkSerializer.read`: `isLightOn` 이면 섹션의 `BlockLight`·`SkyLight` 를 `queueSectionData` 로 넣는다. 그 뒤 `ThreadedLevelLightEngine.lightChunk(chunk, true)` 는 전파하지 않고(`retainData`·`setLightEnabled`), `LayerLightSectionStorage.markNewInconsistencies` 는 데이터를 바꿔 끼울 뿐이다. **바닐라는 빛이 켜진 청크를 올릴 때 가장자리를 다시 맞추지 않는다** — 저장 빛을 그대로 믿는다.
- `ChunkHolder.sectionLightChanged` → `setUnsaved(true)`: 이웃 때문에 빛만 바뀐 청크도 저장 대상이다.
- 바닐라는 편집되는 청크의 이웃이 늘 올라와 있다(티켓 단계). 그래서 "빛을 줄이는 전파가 내려간 청크에 막힘"이 생기지 않는다.
- `ChunkSerializer.write`: `DataLayer.isEmpty()`(= `data == null && defaultValue == 0`)가 아니면 쓴다 — 값이 모두 0 이어도 배열이 있으면 쓴다.

## Furnace 가 하는 것

- 쓰기: 빛이 있으면 `isLightOn=1` + 섹션 빛 + **`furnace:light_version=1`**(모르는 키라 바닐라는 무시).
- 읽기: 표시가 1 이고 `isLightOn=1`·`DataVersion=3955`·`yPos`=이 차원 최저 섹션·층 길이 2048 일 때만 저장 빛을 쓴다(생성 풀에서는 하늘빛 원천만 센다). 하나라도 어긋나면 예전처럼 다시 계산. **바닐라·Paper·다른 서버가 쓴 월드는 표시가 없어 예전과 똑같이 다시 계산한다** — 가져온 월드 이음매가 밝아질 위험(코디네이터 경고)은 이 PR 로 생기지 않는다.
- 가장자리 맞추기(`attachPrecomputed`)는 그대로 한다. 바닐라보다 한 일이 많지만, 저장 빛이 일관되면 바뀌는 칸이 없다.
- 빛이 바뀐 청크는 dirty(바닐라 `setUnsaved`). 올리기 가장자리 맞추기가 저장 빛을 고쳤을 때도 dirty.
- 바닐라에 없는 경우(이웃이 내려간 채 편집): 감소 전파가 내려간 청크에 막히면 `<차원>/data/furnace_light_stale.dat` 에 그 청크와, 그 청크를 거쳐 빛이 닿았을 수 있는 내려간 8방 이웃(막힌 칸에서 상자 거리 ≤ 14)을 적는다. 다음에 올릴 때 저장 빛을 버리고 예전 경로(고립 계산 + 가장자리 맞추기)로 다시 계산하고 dirty.

## 바닐라·예전 Furnace 와 다를 수 있는 점

1. **다시 올릴 때 같은 값 빛 갱신 패킷이 줄었다.** 예전에는 디스크 청크를 다시 계산·맞추면서 그 청크 가장자리 칸이 "바뀜"으로 쳐져 이웃 섹션까지 빛 갱신 패킷을 보냈다(값은 같음). 지금은 저장 빛이 일관되면 아무것도 바뀌지 않아 보내지 않는다. 클라이언트가 가진 빛은 같다(장면이 클라이언트 빛으로 확인). 바닐라도 `initializeSection`·`markSectionAndNeighborsAsAffected` 로 올릴 때 이웃 섹션 갱신을 보낼 수 있어, 패킷 개수는 예전에도 지금도 바닐라와 정확히 같다고 할 수 없다(가정 — 패킷 단위로 대조하지 않음).
2. **빛만 바뀐 청크도 저장한다** — 바닐라와 같아졌다. 예전 Furnace 보다 저장이 늘 수 있다(이웃 편집이 빛을 바꾼 청크).
3. **충돌(비정상 종료):** dirty 청크나 표시 파일이 저장되기 전에 죽으면 낡은 저장 빛(지운 빛이 남은 밝은 칸)을 읽을 수 있다. 바닐라도 충돌 시 블록·빛 불일치가 남을 수 있어 같은 급으로 본다. 표시 파일은 `flushAll`(자동 저장·종료)에서 쓴다.
4. **네더·엔드 차원 밖 빛 섹션**(최저 섹션 −1 아래, 최고 섹션 +1 위)은 0 으로 읽는다 — 바닐라와 같다. 예전 다시 계산은 0 이 아닌 값을 둘 수 있었지만 보이지 않는 칸이다.
5. **이미 있던 문제(바꾸지 않음):** 올라온 청크 모양이 볼록하지 않을 때, 내려간 청크를 돌아 들어온 빛은 줄지 않아 메모리 빛이 밝게 남을 수 있다(기준 코드에서도 디버깅으로 확인, 청크 0,0·1,0·4,3). 표시 파일은 이런 청크가 다시 올라올 때만 고친다.
6. **쓰기 쪽 관찰(바꾸지 않음, 확인 안 함):** Furnace 는 모두 0 인 빛 층을 빼고 쓴다. 바닐라는 모두 0 이어도 배열이 있으면 쓰고, 하늘빛 층이 빠진 섹션은 위쪽 섹션의 맨 아래 줄을 끌어온다(`SkyLightSectionStorage.getLightValue`·`createDataLayer` 의 `repeatFirstLayer`). 그래서 **바닐라가 Furnace 월드를 열면** 위 섹션 맨 아래 줄에 하늘빛이 있는 열의 어두운 동굴 섹션이 밝게 보일 수 있다. Furnace 가 다시 읽을 때는 쓰기와 짝이 맞아 문제없다. 후속 확인 후보.

## 장면(IdentityKit `light-batch-scene`)

- 기준 코드(dec5d2c7)에서 금 파일을 만들고 새 코드가 그대로 통과한다(금 파일 갱신 없음).
- "packets" 줄은 패킷 바이트가 아니라 **클라이언트가 가진 빛**(청크를 받을 때 통째로 담고 빛 갱신 패킷으로 고침)을 해시한다. 같은 값 중복 갱신은 관측 결과가 아니라서다. 빠뜨린 갱신은 잡힌다.
- 돌연변이 점검: 빛 변경 dirty 끄기·막힌 감소 표시 끄기·`pushEdge` 건너뛰기 조건 틀리기는 장면이, 대각 표시 끄기는 `StoredLightReloadTest` 가 잡는다.

## 함정

- `AnvilChunkCodec.fromNbt` 는 dirty 청크를 돌려준다. 실제 경로는 `AnvilWorldSource.decodeChunk` 가 `clearDirty()` 한다. 시험 레벨이 이를 따라 하지 않으면 디스크에서 올린 청크가 늘 다시 저장돼 dirty 경로를 시험하지 못한다.
- 장면에서 광원을 지형 속(돌)에 두면 빛이 안 번져 시험이 아무것도 안 본다. 굴을 파서 번짐을 확실히 할 것.
- 공유 층(`ChunkLight.ZERO`·`FULL`)은 절대 고치지 않는다. 쓰기는 `writable*`·`set*`·`fillSkyFull` 만. `ChunkLight.set` 은 `-ea` 에서 공유 층 쓰기를 막는다.

## 측정 (`:furnace-server:bench --tests '*LightLoadBench*'`, 노이즈 오버월드 36청크, 한 스레드)

- 빛 층 메모리: 청크당 가진 층 52 → 평균 4.3(104 KiB → 8.6 KiB).
- 디스크 청크 올리기의 생성 풀 몫(fromNbt + precomputeLight): 다시 계산 627~655 µs·120 KiB → 저장 빛 374~412 µs·72 KiB(예열 뒤 3라운드).
- 틱 스레드의 가장자리 맞추기·`pushEdge` 건너뛰기 이득은 따로 재지 않았다.
