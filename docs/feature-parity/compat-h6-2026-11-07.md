# CraftBukkit 어댑터 (H6) — 2026-11-07

작업 묶음 H6 은 `org.bukkit.craftbukkit.*` 어댑터다: `CraftServer`·`CraftWorld`·`CraftPlayer`·`CraftEntity`·`CraftItemStack`(`asNMSCopy`/`asBukkitCopy`)과 `getHandle()` 이 NMS shim 을 돌려주게 하고, 버전 접미사 패키지(`v1_21_R1`)와 접미사 없는 Paper 패키지를 둘 다 받는다. 설계는 [H5 문서](compat-h5-2026-11-07.md)를 따랐고, 다른 점은 4장에 적었다. 함정·근거는 `context-notes/2026-11-07-h6.md`, 사용자 확인은 `docs/user-todo/entries/2026-11-07-h6.md`.

## 2. NMS shim 표면 (Mojang 이름, H6 최소분)

shim 은 서버 객체가 아니라 Bukkit 객체를 거쳐 Furnace API 를 읽는다(바닐라 클래스를 싣지 않는다 — EULA, clean-room). **여기 없는 멤버는 호출할 때 `NoSuchMethodError`/`NoSuchFieldError`** 다(조용히 틀리지 않는다). 있지만 같은 값을 줄 수 없는 것은 `UnsupportedNmsCall`(`UnsupportedFeature` → `UnsupportedOperationException` 하위)을 던진다.

## 3. CraftItemStack 규칙 (CraftBukkit 기억 기준 — 원문 대조 못 함)

- `asNMSCopy(null 또는 공기)` = `ItemStack.EMPTY`. `CraftItemStack` 이면 그 NMS 스택의 `copy()`. 평범한 스택은 종류·개수(0·음수 포함 — NMS 쪽에서 비었나로 판정)·컴포넌트를 옮긴 새 스택.
- `asBukkitCopy(빈 스택)` = `new ItemStack(Material.AIR)`(null 이 아니다). 나머지는 평범한 사본.
- `asCraftMirror(null 또는 빈 스택)` = 빈 거울(`handle == null`). 거울은 `ItemStack.EMPTY` 를 들지 않는다 — 빈 거울에 종류를 주면 개수 1 인 **새** NMS 스택을 만든다(EMPTY 는 바뀌지 않는다).
- 거울에서 `setAmount(0)` 이나 `setType(AIR)`(아이템 아닌 종류도) 을 하면 CraftBukkit 처럼 NMS 스택에서 떨어진다(`handle = null`). 그 뒤 NMS 스택은 개수 0 인 채 그대로다.
- 붙은 거울의 `setType` 은 같은 NMS 스택에서 종류만 바꾼다(개수·컴포넌트 패치 유지). NMS 쪽에서 개수가 0 이 된 거울도 떨어지지 않고 종류만 바뀐다 — 지금 종류는 공기로 보이므로 `setType(AIR)` 은 아무 일도 하지 않는다(CraftBukkit `getType() == type` 조기 반환).
- 필드 `handle` 은 리플렉션으로 바꿔 끼워도 거울이 따라간다(읽을 때마다 필드를 본다). `ItemStack.EMPTY` 를 넣으면 빈 거울로 본다(EMPTY 는 바꾸지 않는다).
- 인벤토리(`getInventory().getItem`)가 돌려주는 거울은 H3 의 칸 거울(평범한 `ItemStack`) 그대로다 — CraftBukkit 은 그것도 `CraftItemStack` 이다. `instanceof CraftItemStack` 으로 가르는 라이브러리는 그 경우 평범한 경로로 간다(`asNMSCopy` 는 둘 다 받는다).

## 5. Bukkit·Paper 와 다른 점·한계

1. **Spigot 난독화 이름은 풀지 않는다**(H7d, 변환표 결정 대기). Spigot 이름으로 컴파일된 NMS 호출은 대개 `NoSuchMethodError` 다. 클래스 이름이 Mojang 과 Spigot 에서 같은 것(`Entity`·`ItemStack`·`MinecraftServer`)은 클래스는 풀리고 멤버에서 실패한다. 드물게 Spigot 의 짧은 난독화 멤버 이름이 shim 의 Mojang 이름과 서술자까지 겹치면(예: 두 글자 `is`) 다른 의미로 불릴 수 있다 — H7d 의 변환기가 없앤다.
2. `net.minecraft.server.level.ServerPlayer` 가 실제로 있으므로 Paper `reflection-remapper` 류는 이 서버를 Mojang 이름 런타임으로 본다(설계 H5 발견 8 — 의도한 것).
3. 다른 버전 접미사(`v1_20_R3` 등)는 일부러 풀지 않는다 — 여러 버전 모듈을 싣고 "어느 접미사 클래스가 있나"로 고르는 라이브러리가 엉뚱한 모듈을 고르지 않게. 1.17 이전 `net.minecraft.server.vX_Y_RZ.*` 도 그대로(없음).
4. 서버 패키지 이름에서 접미사를 읽는 옛 코드(`getPackage().getName().split("\\.")[3]`)는 Paper 와 같이 실패한다(접미사가 없다).
5. 변환은 플러그인 jar 의 클래스에만 한다. `libraries:` 로 자동으로 받은 jar 의 클래스는 그대로다. 메서드 참조로 넘긴 `Class::forName`(invokedynamic)은 다리로 돌리지 않는다.
6. 변환기가 읽지 못하는 클래스는 원래 바이트로 올리고 경고를 한 번 남긴다(그 클래스가 접미사 이름을 쓰면 그 자리에서 실패한다). 클래스 파일 버전 49(Java 5) 미만은 `Class.forName(String)` 을 다리로 돌리지 않는다(호출한 클래스를 `ldc` 로 넘길 수 없다) — 그런 플러그인은 1.21.1 에 사실상 없다. 닫힌 플러그인 로더는 jar 를 다시 열지 않는다(변환기 없는 `URLClassLoader` 처럼 `ClassNotFoundException`).
6a. 옵션 `plugins.compat.nms.enabled` 를 끄면 이 묶음의 접미사 변환만이 아니라 **모든 플러그인 형식의 클래스 변환기**(`PluginFormat#transformer`)를 끈다 — 지금 변환기는 Bukkit 호환 형식의 것 하나뿐이다.
7. `Entity#getId()` 는 `UnsupportedNmsCall`. 엔티티 shim 의 위치·생사는 Furnace 핸들 스냅샷 값이다(CraftBukkit 의 NMS 엔티티는 살아 있는 객체). 같은 `CraftEntity` 는 가장 나중에 만든 스냅샷을 든다 — 스냅샷에 순번(`Entity#snapshotStamp`, 서버가 매긴다)이 있어 늦게 도착한 옛 이벤트 객체가 새 값을 되돌리지 않는다. 같은 엔티티를 여러 스레드가 처음 감싸도 `CraftEntity` 는 하나다(캐시를 `compute` 로 고친다).
8. `CraftHumanEntity` 는 추상(사람 모양 엔티티는 플레이어뿐). CraftBukkit 의 NPC 사람 엔티티 경로는 없다.
9. `CraftServer#getHandle()`(PlayerList)·`CraftPlayer#getProfile()`(authlib)·`CraftWorld` 의 블록 shim 은 없다 — H7b(authlib 결정)·H7e.

## 6. 시험

- `CraftAdapterReviewTest`(6개, 독립 검토 회귀): 옛 스냅샷이 새 위치를 되돌리지 않음, 두 스레드 동시 첫 감싸기에도 정체성 하나, `getDamageValue` 잘림(돌 0·다이아 검 1561), `getMaxStackSize` 기본값(지운 패치·EMPTY 1, 개수 0 엔더 진주 16), EMPTY 를 든 거울, 개수 0 붙은 거울의 `setType`. 서버 `PluginClassLoaderCloseTest`: 닫은 로더가 jar 를 다시 열지 않음.
- `CraftAdapterTest`(8개): 계층·캐스트·서버 클래스 이름, 플레이어·몹 핸들 정체성(새 스냅샷이 와도 같다), 월드·서버 핸들, `asNMSCopy`↔`asBukkitCopy` 왕복(이름·내구도), 바닐라 규칙(`matches`·`split`·빈 스택), 거울 쓰기 반영·떨어짐·`handle` 필드, 사본·`clone` 독립.
- `NmsPluginLoadTest`(3개): 시험 안에서 컴파일한 진짜 플러그인 jar. 접미사 클래스는 **컴파일에만 쓰는 스텁**이라 jar 에 없다(실제 Spigot 플러그인과 같은 모양). 리플렉션 4종이 같은 클래스로 풀림, 다른 접미사·없는 이름은 원래 이름으로 `ClassNotFoundException`, Mojang 이름 판정, 바이트코드 직접 참조(캐스트·`getHandle`·정적 다리)가 링크됨, 코드 출처가 플러그인 jar, 옵션을 끄면 바이트 그대로(리플렉션 `ClassNotFoundException`·직접 참조 `NoClassDefFoundError`). 변환기를 빼면 앞의 두 시험이 실패하는 것을 확인했다.
- 대조표 다시 만들기: `compat-h4-coverage-2026-11-07.md` 의 CraftBukkit·`net.minecraft` 줄이 바뀌었다 — 이제 클래스(`MinecraftServer`·`ItemStack` 등)가 있으므로 "클래스는 있는데 없는 멤버"(4장)에 Spigot 난독화 멤버(`MinecraftServer#aA` 같은 것)가 올라온다. H7d 전까지는 그 줄들이 정상이다.
