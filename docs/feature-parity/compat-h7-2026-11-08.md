# NMS 호환: 변환 확장과 값 shim (H7a 나머지·H7b·H7c) — 2026-11-08

작업 묶음 H7 은 H6(#139)이 만든 로더 훅·CraftBukkit 어댑터 위에서 **NMS(`net.minecraft.*`)·CraftBukkit 을 직접 쓰는 플러그인**을 한 걸음 더 돌게 한다. 설계는 [H5 문서](compat-h5-2026-11-07.md)(등급 A/B/C, Mojang 정규 이름, "조용히 틀리지 않는다"), 그 위의 [H6 문서](compat-h6-2026-11-07.md)를 따랐다. H7d(Spigot→Mojang 이름 변환표)는 이번 범위가 아니고, 대신 표지 측정 결과를 5장에 적었다. 함정·근거는 `context-notes/2026-11-08-h7.md`, 사용자 확인·결정은 `docs/user-todo/entries/2026-11-08-h7.md`.

## 4. 한계 (조용히 틀리지 않는 쪽으로 남긴 것)

- **검증기가 없는 클래스를 올리는 경우는 클래스 전체가 죽는다(검토 REPRO-1):** 없는 클래스 타입의 값(인자·필드·프레임의 지역 변수)이 **있는** 클래스(인터페이스·Object 가 아닌) 자리로 넘어가면(`LivingEntity e = zombie;`, `Zombie` 없음), HotSpot 이 클래스를 링크하며 모든 메서드를 검증하다 그 대입을 확인하려고 `Zombie` 를 올리고 실패한다. 그러면 **그 클래스의 모든 메서드**(있는 심볼만 쓰는 것까지)가 `NoClassDefFoundError` 다. NMS 어댑터 클래스 하나에 모든 걸 모은 플러그인이면 피해가 크다. 후속 후보: 메서드마다 ASM `Analyzer` 로 그런 대입이 생기는지 보고(`NmsSymbols` 상속 정보로 충분), 생기면 그 메서드 본문만 덫으로 바꾸고 보고에도 센다.
- **덫이 못 바꾸는 자리:** `catch (없는NMS클래스 e)` 의 예외 종류, 필드·메서드 서술자에만 나오는 없는 클래스. 이때는 JVM 의 링크 오류가 그대로 난다(그 자리에서).
- `Entity#getId()` 는 여전히 `UnsupportedNmsCall`(공개 API 가 실제 엔티티의 네트워크 id 를 내보내지 않는다). 패킷으로만 보이는 엔티티는 패킷 API 의 `nextEntityId()` 를 쓴다.
- `TagParser.parseTag` 는 잘못된 SNBT 에 바닐라의 `CommandSyntaxException` 대신 `UnsupportedNmsCall` 을 던진다(brigadier 가 이 모듈 컴파일 경로에 없다). `Component` 는 brigadier `Message` 를 구현하지 않는다.
- `TextColor` 는 이름 붙은 색(`red`)과 같은 RGB 값을 JSON 에서 이름으로 쓴다(Furnace Text 규칙). `Style`·`MutableComponent` 의 `toString` 은 바닐라 레코드 문자열과 다르다. `ClickEvent`·`HoverEvent`·`ItemLore#styledLines` 는 없다.
- serverbound 패킷·패킷 가로채기·`Connection` 객체는 없다. 블록 상태(`BlockState`·`ClientboundBlockUpdatePacket`)는 아직 없다.
- Spigot 난독화 이름(1~2글자 멤버, `EnumChatFormat` 같은 Spigot 클래스 이름)은 풀지 않는다(H7d).
- 다른 버전 모듈 판정은 클래스 이름의 표지만 본다. 표지 없이 리플렉션으로 버전을 고르는 라이브러리의 다른 버전 코드는 보고에 "아직 없음" 으로 섞인다. 반대로 이름에 `1_16`·`1_20_4` 같은 조각이 우연히 든 클래스(`Updater1_16`, `LegacySchema1_12`)는 1.21.1 에서도 쓰이는데 보고·strict 에서 빠진다(거짓 양성).
- 서버 `PluginClassLoader` 는 변환기가 던진 `UnsupportedOperationException` 전부를 정의 거부로 본다. 변환기 버그로 우연히 생긴 UOE 도 원래 바이트로 되돌아가지 않는다. 지금 변환기는 compat 하나뿐이라 전용 표지 예외는 두지 않았다(후속 후보).

**결론:** Paper 표지는 이름 체계를 가르지 못한다. 같은 commandapi 10.1.2 의 Spigot 판과 Mojang 판이 표지 수까지 똑같고(3/9), 표지가 있는 jar 대부분은 NMS 를 쓰지 않는 Paper 감지 코드(`Class.forName("com.destroystokyo.paper…")`)다. 표본에서 이름 체계를 확실히 알려 준 것은 매니페스트 하나(19개 중 1개)뿐이다. 그래서 H7d 를 한다면 판정은 "매니페스트 → 없으면 없는 멤버 이름 모양(1~2글자 비율)" 순이 맞고, 표지는 쓰지 않는다. 지금 보고의 "난독화로 보임" 수가 그 두 번째 신호다(Spigot 판 17·7, Mojang 판 0).
