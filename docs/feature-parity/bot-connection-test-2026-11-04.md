## 판정 방법
- mineflayer 는 바닐라 클라이언트 물리(prismarine-physics)를 흉내 내서 위치를 보낸다. 서버가 거절하면 `player_position` 패킷이 온다.
  스크립트가 직접 시킨 `/tp` 의 위치 패킷은 빼고 나머지를 "되돌림"으로 센다. 같은 구간의 서버 로그에서 `moved wrongly`·`moved too quickly`·`floating` 줄을 센다.
- **대조군**: 한 틱에 15칸 앞으로 가는 위치 패킷과 돌벽 속으로 0.8칸 들어가는 위치 패킷을 직접 보냈다. 둘 다 되돌림 1건과 로그(`moved too quickly! 0.0,0.0,15.0`, `moved wrongly!`)가 나왔으므로 검출은 동작한다.
- 한계: mineflayer 물리는 바닐라와 완전히 같지 않고, 웅크림(1.5칸)·수영·기어가기 자세의 몸통 크기를 흉내 내지 않는다. 급류 삼지창도 없다. 그래서 아래 결과는 "봇이 흉내 낸 정상 이동을 서버가 거절하지 않았다"까지만 말한다.

## 찾아 고친 것: 말에 탈 때마다 `moved wrongly` 와 되돌림 텔레포트
- 증상: 말을 우클릭해 타는 순간 서버 로그에 `<이름> moved wrongly!` 가 찍히고, 탄 클라이언트에 위치 패킷(탈것 위 자리)이 한 번 간다. 1차 실행에서 탈 때마다 났다(3번 탐 → 3번).
- 원인: 연결(IO) 스레드는 걸음 패킷을 검증 대기열에 넣고, region 틱이 꺼내 검증한다. 클라이언트가 **타기 직전에 보낸 걸음 패킷**이 region 에서 **탄 뒤에** 검증되면,
  서버 위치(탈것 위, y+0.84)와 클라이언트가 말한 땅 위 위치의 차이가 커서 되돌린다. 바닐라 `handleMovePlayer` 는 메인 스레드에서 차례로 처리하고 `isPassenger()` 면 위치를 버리고 회전만 받으므로 이런 일이 없다.
- 고침: `Region.processMoves` 가 검증 대기 패킷을 꺼낼 때 플레이어가 이미 탔으면 위치는 버리고 회전만 받는다(바닐라 isPassenger 분기). 재현 시험 `RegionMoveValidationTest.movePacketQueuedBeforeMountingIsNotRejectedAfterMount`(고치기 전 실패 확인).
- 영향: 말·돼지·스트라이더·보트·수레 등 모든 탈것. 실제 클라이언트에서 탈 때 화면이 한 번 튀었을 수 있다(미확인).

## U4 말 재탑승 (`horse.js`, 수정 jar)
`set_passengers` 패킷으로 내린 시각부터 다시 탄 시각까지를 쟀다(우클릭 간격 200~800ms 라 그만큼 늦게 잡힌다). 두 번 돌렸고 두 번 모두 서버 로그 `moved` 0줄.
| 내리는 방법 | 1회 | 2회 |
|---|---|---|
| 웅크림 0.3초 누르고 뗌 | 3.35초 | 3.11초 |
| 웅크림 한 틱(0.05초) | 3.10초 | 3.28초 |
| 웅크림 2초 유지 후 뗌 | 3.05초(뗀 뒤 1.15초) | 3.23초 |

바닐라 `Entity.canRide` = 웅크리지 않음 && `boardingCooldown`(내릴 때 60틱) ≤ 0 과 맞다. **웅크림이 서버에 남아 다시 못 타는 경우는 재현되지 않았다.**
사용자가 본 "내린 직후 재탑승이 안 됨"은 바닐라에도 있는 3초 대기로 보인다. 위의 탈 때 튐은 이번에 고쳤다.

## U2 파괴수 나뭇잎 (`rav.js`)
- 바닐라 1.21.1 `Ravager.aiStep`(`cki.m_`, Vineflower 로 디컴파일해 대조): `horizontalCollision && mobGriefing` 이면 몸통을 0.2 넓힌 상자 안의 `LeavesBlock` 을 `destroyBlock(pos, true, this)`, 하나도 못 부수고 땅 위면 점프. 길찾기는 생성자의 `setPathfindingMalus(LEAVES, 0)` 뿐이다(전용 길찾기 클래스 없음). Furnace `Ravager` 와 같다(`#leaves` 태그 10종 = LeavesBlock 하위 10종).
- 봇 시험: 속 빈 나뭇잎 상자(7×4×7)에 가두고 상자 밖 서바이벌 플레이어(쉬운 난이도). 20초 동안 부순 수: 참나무 21, 참나무(자연) 35, 가문비 21, 자작 12, 맹그로브 18, 진달래 27, 벚나무 0·21·18(3번).
- 0 개인 경우는 파괴수가 움직이지 않았다. 나뭇잎이 시야를 막아 목표를 못 잡으면 느리게 돌아다니기만 해서(속도 0.4) 벽에 안 닿을 수 있다 — 바닐라와 같은 동작으로 본다.
- 결론: **나뭇잎을 부순다.** 사용자가 본 "안 부순다"는 목표 없이 서 있던 파괴수였을 가능성이 크다(가정).

## 덤으로 찾은 차이(고치지 않음)
- 플레이어 저장에 `RootVehicle` 이 없다(`grep '"RootVehicle"'` 결과 0). 바닐라는 탄 채로 나가면 탈것을 플레이어 파일에 같이 저장하고 다시 들어오면 태워 준다. Furnace 는 탄 채로 나가면 내려진다(가정: 재접속 동작은 봇으로 안 봄). 선택자 `@s[nbt={RootVehicle:{}}]` 도 그래서 늘 거짓이다. 별도 작업으로 남김.
