# H2 — 호환 계층: 명령·스케줄러 (2026-11-07)

작업 묶음 H2(`work-packages-2026-11-06.md` 2.7): 옛 Bukkit·Paper 플러그인이 부르는 **명령(`CommandExecutor`·`Command`)** 과 **스케줄러(`BukkitScheduler`·Paper 스케줄러 넷)** 가 Furnace 위에서 같은 결과를 내게 한다. 새 모듈 `furnace-compat-paper`(공개 API `furnace-api` 에만 의존).

## 범위를 이렇게 잡았다 (가정 — 확인 필요)

- **H1 이 아직 없다.** H2 의 선행은 H1(`furnace-compat-paper` 뼈대·`plugin.yml` 로더·이벤트 매핑)인데 병합된 것도 열린 스레드도 없었다. 그래서 H2 가 모듈 뼈대(빌드 파일·패키지)를 만들었다 — H1 은 이 모듈에 이어서 쓰면 된다.
- **`org.bukkit.*` 클래스를 이 컨테이너에서 받을 수 없다.** paper-api·spigot-api 는 `repo.papermc.io`·`hub.spigotmc.org`(둘 다 프록시 403)에만 있고 Maven Central 에는 없다. 그래서 H2 는 Bukkit 인터페이스에 거는 껍데기가 아니라 **껍데기 밑의 의미(호환 코어)** 를 Bukkit 타입 없이 만들고 시험했다. 이름도 `LegacyCommand`·`LegacyScheduler` 처럼 일부러 Bukkit 이름과 다르게 했다. `org.bukkit.command.PluginCommand`·`BukkitScheduler`·`BukkitRunnable`·`Bukkit.getScheduler()` 는 H1 이 Bukkit API 를 들일 방법(아래 결정)이 정해진 뒤 이 코어를 한 줄씩 부르는 얇은 클래스로 붙는다.
- 그래서 H2 가 끝났다고 해서 Bukkit 플러그인이 곧바로 도는 것은 **아니다**. H2 가 보장하는 것: 그 껍데기가 부를 코어가 Bukkit 과 같은 규칙으로 돌고, 시험으로 못 박혀 있다.

## 설계: "소유 region 로 넘기거나 global 직렬화"

| Bukkit 호출 | Furnace 에서 도는 곳 | 근거 |
|---|---|---|
| 동기 작업(`runTask*`, `scheduleSync*`, `callSyncMethod`) | **전역 스레드 하나에 직렬화**(같은 틱은 예약 순서) + `PrimaryThread` 표시 | 옛 플러그인은 정적 필드·비스레드 안전 컬렉션을 "주 스레드 하나"가 쓴다고 믿는다. region 스레드로 나누면 경쟁이 생긴다. |
| 비동기 작업(`runTask*Asynchronously`) | 틱에 맞춰 전역에서 도착 → `asyncExecutor()`(가상 스레드) | Bukkit 도 틱 대기열이 먼저 돌고 풀로 넘긴다. 틱 규칙이 같아지고 시험 서버의 결정적 틱에서도 재현된다. |
| 명령 실행 | 서버 명령 큐가 이미 전역 스레드에서 부른다(PrimaryThread 표시) | `Commands.performPrefixedCommand` 가 전역으로 모은다. |
| 명령 자동완성 | 연결 스레드가 부르므로 **전역으로 넘겨 결과를 기다림**(1초 한도, 넘으면 빈 목록+경고) | 완성기도 주 스레드에서 돈다고 믿는 코드가 많다. |
| `dispatchCommand` | 옛 명령이면 주 스레드에서 바로 실행·성공 여부 반환, 아니면 전역으로 넘기고 접수(true) | Bukkit 은 주 스레드가 아니면 예외지만 Furnace 에서는 region 스레드의 리스너가 부르는 일이 흔해 넘겨 준다. |
| Paper `GlobalRegionScheduler` | 전역 스레드 | 1:1 |
| Paper `RegionScheduler`(월드+청크 또는 `Location`) | 그 칸을 가진 region 스레드(`World.scheduler(pos)`) | 1:1 — Folia 를 아는 플러그인이 쓰는 길 |
| Paper `Entity#getScheduler()` | 엔티티를 따라다니는 `EntityScheduler`, 사라지면 `retired` | 1:1 |
| Paper `AsyncScheduler` | 벽시계 시간 단위 → `asyncExecutor()` | 1:1 |

블록·엔티티 같은 **region 이 가진 상태**를 전역(주) 스레드에서 만지는 호출은 H3 의 어댑터가 소유 region 으로 넘겨야 한다(여기서는 스레드를 고르는 데까지). 이를 위해 H1 의 이벤트 리스너 호출도 region 스레드에서 옛 코드를 부를 때 `PrimaryThread.enter()` 로 표시해야 `Bukkit.isPrimaryThread()` 가 맞게 나온다.

## 구성

- `compat/thread/PrimaryThread` — `Bukkit.isPrimaryThread()` 대역(표시된 구간 또는 전역 스레드).
- `compat/sched/LegacyScheduler` — `BukkitScheduler` 의미. 인자 보정은 CraftScheduler 와 같다: 지연<0→0, 주기 0→1, 주기<-1→-1(반복 없음), 지연 0·1 은 다음 틱. 예외가 나도 반복 유지(로그 `Task #id for 플러그인 vX generated an exception`), `cancelTask`/`cancelTasks`/`isQueued`/`isCurrentlyRunning`/`getPendingTasks`/`getActiveWorkers`, 꺼진 플러그인의 예약은 `PluginDisabledException`, 플러그인이 꺼지면 작업·`callSyncMethod` future 모두 취소.
- `compat/sched/PaperSchedulers` — Paper 스케줄러 넷. `ScheduledTask` 상태(`IDLE/RUNNING/FINISHED/CANCELLED/CANCELLED_RUNNING`)와 `CancelledState` 여섯 가지 반환. 지연·주기 1 미만은 `IllegalArgumentException`. 한 작업이 자기 자신과 겹쳐 돌지 않는다.
- `compat/command/LegacyCommand` — `Command`/`PluginCommand` 의 설정(이름·별칭·설명·`usage`·`permission`(세미콜론 여러 개)·`permissionMessage`)과 실행 규칙: 권한 없으면 거절 문장(기본 문장·`<permission>` 치환·빈 문자열이면 침묵), 실행기가 `false` 면 `usage`(`<command>` 치환, 여러 줄), 예외는 로그+보낸 사람에게 `An internal error occurred while attempting to perform this command`, 자동완성은 완성기 → (실행기가 완성기면) 실행기 → 접속자 이름(대소문자 무시, 정렬) 순.
- `compat/command/LegacyCommands` — 명령 지도: `declareFromDescription`(`furnace-plugin.yml` 의 `commands:` 를 미리 만들고 나중에 실행기를 붙인다 — `JavaPlugin.getCommand` 와 같은 순서), `command`/`find`, `register`/`unregister`, `dispatch`. 서버 명령 등록소가 이름·별칭·`플러그인:이름` 을 붙인다.
- API 한 줄 추가: `BasicCommand.execute(sender, label, args)`·`suggest(sender, label, args)`(기본 구현은 기존 메서드로 위임). 서버 등록소가 트리에 붙은 이름(사용자가 친 별칭·`플러그인:이름`)을 넘긴다. Bukkit `onCommand(sender, command, label, args)` 의 `label` 에 필요하다.

## 알려진 차이·한계

1. **권한 없는 사람이 명령을 치면**: Furnace 는 트리에서 명령을 숨겨 "알 수 없는 명령"(`Unknown or incomplete command`)이 나온다. Bukkit·Paper 는 거절 문장(`I'm sorry, but you do not have permission…`)이 나올 수 있다(모던 서버의 실제 동작은 도미니코 확인 항목 — `user-todo/entries/2026-11-07-h2.md`). 직접 호출하는 `LegacyCommand.testPermission` 은 거절 문장을 보낸다.
2. 브리지가 없는 부분: `label` 의 대소문자는 Brigadier 리터럴이 소문자만 받아 소문자로만 들어온다. Bukkit 은 `KIT` 도 받는다.
3. 지연 틱: `runTaskLater(0)` 과 `(1)` 이 모두 다음 틱인 것은 Bukkit 과 같다. 시험 서버(결정적 틱)에서는 전역 `runLater(0)` 이 "다음 틱 머리"에서 돈다(`docs/api/testing.md`).
4. `Bukkit.dispatchCommand` 로 **바닐라·다른 플러그인 명령**을 부르면 결과를 알 수 없어 접수 `true` 만 돌려준다(`Furnace.dispatchCommand` 와 같다).
5. 사용법 문장은 `§` 서식을 `LegacyTextSerializer.section()` 으로 풀어 Text 로 보낸다. `usage` 에 MiniMessage 같은 것은 해석하지 않는다.
