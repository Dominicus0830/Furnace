# O4 — 플레이어 데이터 비동기 저장 · 빈 서버 일시정지 · 주기 백업 (2026-11-07)

불만 표(`paper-spigot-dev-complaints-2026-11-06.md`) 75·76·97번. 모두 `furnace.properties` 키로 켜고 끄며 **기본은 꺼짐**(1.21.1 바닐라 동작 그대로).

## 1. 75번 — 플레이어 데이터 비동기 저장 (이미 되어 있었다, 빈 곳 하나 채움)

- 확인 결과: 플레이어 저장은 이미 이벤트 루프에서 스냅샷만 뜨고, 기록은 전용 직렬 스레드 `furnace-playerdata-io`(`PlayerData.io()`)가 한다. region·전역 스레드는 디스크를 기다리지 않는다(Paper #4209 의 "느린 디스크가 메인 스레드를 막는" 문제 없음). 시퀀스 번호로 늦게 온 옛 스냅샷이 새 것을 덮지 않는다.
- 채운 곳: `/save-all` 이 접속자를 저장하지 않았다(바닐라 `saveEverything` 은 `PlayerList.saveAll` 을 먼저 한다). 이제 `Player.requestSave()`(연결이 다는 입구 — 이벤트 루프에서 스냅샷 → 실행기)로 모두 저장하고, 기록이 끝날 때까지(최대 30초) 기다린 뒤 성공을 알린다. 탈것(RootVehicle)도 `flushAll` 이 region 스레드에서 덧쓴다. 추가 월드 level.dat 도 같이 저장한다.

## 2. 76번 — 빈 서버 일시정지 (`idle-pause.*`)

| 키 | 기본 | 뜻 |
|---|---|---|
| `idle-pause.empty-seconds` | `0`(끔) | 접속자가 없는 채로 이만큼(초) 지나면 게임 틱을 멈춘다. 바닐라 1.21.2+ `pause-when-empty-seconds` 와 같은 규칙 |
| `idle-pause.flush-caches` | `true` | 멈출 때 저장 뒤 지역 파일 핸들을 닫고 GC 를 권한다(Paper #13864) |

- 판단은 전역 틱에서: 접속자가 없고 `/tick sprint` 중이 아니면 빈 틱을 센다. 문턱(초×20)에 닿는 틱에 `Server empty for N seconds, pausing` 을 찍고 그 틱부터 건너뛴다(바닐라 문구 그대로). 접속자가 생기면 다음 전역 틱(50ms 안)부터 다시 돈다.
- 멈춘 동안: 전역 틱(시간·날씨·함수·잠·포위 스포너)과 모든 차원 region 게임 틱을 건너뛴다. region 은 작업 큐·플러그인 지연 작업은 계속 돌린다(접속 처리·명령·플러그인 논리는 산다).
- 들어갈 때 할 일은 유지보수 스레드(`furnace-maintenance`)에서: 바닐라 `autoSave` 와 같은 `/save-all` → (flush-caches) 레인이 빈 뒤 모든 지역 파일 저장소 `closeAll`(다음 읽기·쓰기가 다시 연다) → `System.gc()`.
- 청크를 따로 내리지는 않는다: Furnace 는 구독자 없는 청크를 유예 뒤 이미 내리므로, 멈출 때 남는 것은 `/forceload` 청크뿐이고 그것은 사용자가 붙잡아 둔 것이라 그대로 둔다.
- 1.21.1 바닐라에는 일시정지가 없으므로 켜면 결과가 달라진다(빈 서버에서 시간·작물·강제 로드 청크가 멈춤) → 켜면 시작 로그에 경고.

## 3. 97번 — 주기 백업 (`backup.*`, `/furnace backup`)

| 키 | 기본 | 뜻 |
|---|---|---|
| `backup.interval-minutes` | `0`(끔) | 주기 백업 간격(분). 5 미만이면 경고 |
| `backup.directory` | `backups` | 백업 폴더(서버 폴더 기준). 월드 폴더 안이면 거부 |
| `backup.keep` | `10` | 남길 개수, 넘으면 오래된 것부터 지움. `0` = 지우지 않음(경고) |
| `backup.format` | `zip` | `zip` 또는 `folder` |
| `backup.skip-if-no-players` | `true` | 지난 백업 뒤 아무도 안 들어왔으면 주기 백업을 건너뜀 |
| `backup.hold-timeout-seconds` | `10` | 기준점을 잡는 동안 틱을 붙잡는 최대 시간. 넘으면 이번 백업 포기 |

명령: `/furnace backup` (권한 4, 유지보수 스레드에서 돌고 끝나면 결과를 알림), `/furnace backup status`. 주기가 꺼져 있어도 명령은 쓸 수 있다. 결과 파일 이름은 `yyyyMMdd-HHmmss.zip`, 안에 `world/`(네더·엔드 포함)와 불러온 추가 월드 폴더가 들어간다. `session.lock`·`*.tmp` 는 뺀다. 풀어서 서버 폴더에 두면 그대로 켜진다.

### 3.1 한 시점(기준점)을 뜨는 방법

Furnace 는 region 마다 따로 틱을 돈다. 차례대로 저장하면 그 사이 엔티티가 region 을 건너가 백업에 둘이 되거나 빠질 수 있다. 그래서:

1. **틱 붙잡기**(짧다): 전역 틱과 모든 차원의 region 게임 틱을 붙잡고(`World.holdTicks`, `ServerCore.holdGlobalTicks`), 지금 도는 틱이 끝나기를 기다린다(`World.quiesce` — 모든 region 작업 큐에 빈 작업을 넣고 기다림). `Region.runTick` 은 작업 큐를 비운 **뒤에** 붙잡힘을 다시 보므로 빈 작업이 돈 차례는 틱을 하지 않는다 → 이후 어느 region 도 게임 틱을 돌지 않는다. 엔티티·플레이어 넘겨주기는 틱에서만 생기므로 붙잡은 동안에는 없다.
2. **기준점 저장**: 접속자 저장 요청, 모든 region 의 dirty 청크·엔티티·POI·탈것·습격·명령 저장소·강제 청크·지도 저장(`flushAll`, 저장 역압 무시), level.dat. 저장은 모두 IO 레인(또는 플레이어 데이터 실행기)에 들어간다.
3. **레인 기준점**: IO 레인(같은 region 파일의 저장·읽기를 FIFO 로 줄 세우는 16줄)마다 marker 를 넣는다. marker 가 돈 레인의 파일은 "기준점 뒤" 다. 저장소(region·entities·poi)마다 `RegionFileStore.Snapshot` 을 건다.
4. **작은 파일**(level.dat, `data/`, 데이터 팩 등)은 붙잡은 동안 바로 복사한다. 플레이어 데이터(`playerdata`·`stats`·`advancements`)는 그 직렬 실행기에 복사 작업을 넣는다 — 기준점 저장 뒤, 놓은 뒤의 저장 앞 차례.
5. **놓는다**. 틱이 다시 돈다. 붙잡은 시간은 결과 메시지의 "기준점 정지 N ms".
6. **복사(쓰기 전 복사)**: 기준점 뒤 어떤 파일에 첫 쓰기가 오면, 그 파일 키 잠금 안에서 쓰기 직전에 그 파일(+ 그 region 의 외부 청크 `.mcc`)을 먼저 백업 폴더로 복사한다. 나머지는 복사기가 하나씩 같은 잠금을 잡고 복사한다. 기준점 뒤에 새로 생긴 파일은 첫 쓰기가 "없었음"으로 표시해 넣지 않는다. 그래서 디스크 쓰기는 기준점 뒤에도 멈추지 않고, 기다리는 것은 그 파일 하나를 복사하는 시간뿐이다.
7. zip(빠른 압축 단계 — 지역 파일은 이미 압축돼 있다)으로 묶고 임시 폴더를 지운 뒤 보관 수를 넘는 오래된 백업을 지운다. 도중에 서버가 꺼져 남은 임시 폴더(`backups/.staging-*`)는 다음 기동 때 지운다.

### 3.2 한계 (의도한 차이)

- 접속자 스냅샷은 각 연결의 이벤트 루프에서 붙잡은 동안에 뜬다. 붙잡은 동안에도 작업 큐(상자 클릭 등)는 돌기 때문에, 그 몇 ms 사이에 상자↔인벤토리로 옮긴 아이템은 백업에서 한쪽에만 있거나 양쪽에 있을 수 있다(바닐라 `save-all` 은 한 스레드라 없음). 붙잡는 시간이 짧아(시험 월드 수 ms) 실제로는 드물다.
- 붙잡은 동안 작업 큐에서 엔티티를 안 불러온 청크로 옮기는 작업(명령으로 먼 곳 순간이동 등)이 돌면 그 엔티티가 백업에 둘이 될 수 있다.
- 전역 틱은 붙잡지만 전역 스레드 작업(명령)은 돈다.
- 내려 둔(불러오지 않은) 추가 월드 폴더는 백업에 넣지 않는다.

## 4. 시험

- `RegionSnapshotTest`: 기준점 뒤 첫 쓰기 전 복사, 같은 파일 두 번째 쓰기는 다시 안 뜸, 기준점 뒤 새 파일 제외, 레인 기준점 전 쓰기는 백업에 들어감, `.mcc` 함께 복사, 스냅샷 겹치기 거부.
- `WorldBackupTest`: 실제 World(Anvil·IO 레인)로 — 저장 안 한 dirty 청크는 백업에 들어가고, 놓은 직후 바꿔 저장한 청크·플레이어 데이터·level.dat 은 백업에 안 들어감(쓰기 전 복사 1회 이상), 붙잡힌 동안 게임 틱 0·작업 큐는 돔, 보관 수 정리(다른 파일은 안 건드림), 월드 안 백업 폴더 거부.
- `IdlePauseTest`: 문턱 틱에 멈춤·저장 한 번·접속하면 다시 돎, sprint 가 셈을 되돌림, 설정 기본 꺼짐·검증·경고.
- 실제 서버 jar(오프라인, 평지) 확인 2026-11-07: `idle-pause.empty-seconds=8` → 8초 뒤 `Server empty for 8 seconds, pausing`, 지역 파일 저장소 9개 닫음, 멈춘 동안 `time query gametime` 이 그대로(159). 멈춘 상태에서 `/forceload`·`/setblock` 은 그대로 됨. 금 블록을 놓고 `/furnace backup`(기준점 정지 59 ms) → 다이아 블록으로 바꾸고 `save-all` → zip 을 새 서버 폴더에 풀어 켜니 `execute if block 1 100 1 gold_block` 통과, `diamond_block` 실패(백업 순간 상태).
