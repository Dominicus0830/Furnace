# H3 — 호환 계층: 아이템·인벤토리·블록·엔티티·월드 (2026-11-07)

작업 묶음 H3(`work-packages-2026-11-06.md` 2.7): 옛 Bukkit·Paper 플러그인이 부르는 `ItemStack`·`ItemMeta`·`Inventory`·`Block`·`Entity`·`World` 가 Furnace 위에서 Bukkit 규칙대로 돈다. H1(`furnace-compat-paper` 뼈대·이벤트 24종)과 H2(명령·스케줄러 코어) 위에 쌓았다. 사용법 요약은 `docs/api/compat-paper.md` 의 "H3" 절.

## 범위를 이렇게 읽었다 (가정 — 확인 필요)

"어댑터"를 **플러그인이 가장 흔히 부르는 API 의 동작이 Bukkit 과 같게** 만드는 일로 읽었다. 그래서 종류를 넓히기보다 자주 쓰는 것을 끝까지(스레드 규칙·실패 방식 포함) 만들었다.

| 영역 | 넣은 것 | 뺀 것(호출하면 `UnsupportedFeature`) |
|---|---|---|
| 아이템 | `ItemStack`(평범한 것 + 칸을 비추는 "거울"), 마법 부여, 내구도, `ItemMeta`(이름·기본 이름·설명·CustomModelData·마법·ItemFlag·내구도·수리비·부서지지 않음·불 저항·툴팁 숨김·마법 반짝임·영속 데이터)·`Damageable`·`Repairable` | 종류별 메타(가죽 갑옷·책·깃발…), `Attribute`·속성 변경치, 아이템 직렬화 |
| 마법 부여 | `Enchantment` 42종(키 기준 상수) | `getMaxLevel`·`getStartLevel`·`canEnchantItem`(서버 데이터라 API 가 모른다) |
| 영속 데이터 | `org.bukkit.persistence`(PDC 종류 12종 + 중첩), 아이템 메타·**엔티티·플레이어** | `PersistentDataType.LIST` |
| 인벤토리 | `Inventory`·`PlayerInventory`(Bukkit 의 모든 칸 조회·addItem·removeItem·장비 칸·단축 칸) | 가상 인벤토리 `createInventory`·열기·`InventoryView`·상자 등 블록 인벤토리(BlockState 필요) |
| 블록 | `setType`·`setBlockData`·`getBlockData`·`BlockData`(문자열 상태)·`createBlockData`·`isEmpty`·`isLiquid`·`getRelative(face,n)`·`getFace`·`getChunk` | `BlockState`(표지판·상자), `setType(.., applyPhysics=false)`, 빛·바이옴·드롭 |

## 기준: 바닐라/Bukkit 과 결과가 같거나, 모르면 지어내지 않는다

- 값이 서버 데이터에서 오는데 API 가 모르면 던진다(예: 마법 최대 레벨). 그래서 `ItemStack#addEnchantment` 는 Bukkit 이 하는 "최대 레벨·적용 아이템" 검사를 **하지 않고** 레벨 1~255 만 검사한다(문서화된 차이 — 아래 1번).
- 숨길 수 없는 표시 항목(`HIDE_DESTROYS`·`HIDE_PLACED_ON`·`HIDE_ARMOR_TRIM`)은 그 컴포넌트가 아이템에 **없을 때만** 받아 준다(효과 없는 Bukkit 과 같다). 있으면 `UnsupportedFeature`.

## 스레드 규칙 (H2 가 H3 로 넘긴 "소유 region 으로 넘기기")

Bukkit 코드는 "주 스레드 하나에서 부른다"고 믿고, Furnace 에서는 플레이어·블록·엔티티마다 소유 region 스레드가 다르다. 이 모듈의 규칙:

1. **소유 스레드(이벤트 처리기 안 등)**: 모두 Bukkit 처럼 곧바로 돈다.
2. **읽기**: 플레이어 인벤토리·영속 데이터는 서버가 잠가 두므로 **어느 스레드에서나** 된다. 블록·엔티티·월드 읽기는 소유 스레드가 아니면 `ThreadOwnershipException`(Furnace 자신의 규칙과 같다. 다른 region 의 것을 동기로 읽지 않는다).
3. **쓰기**: 소유 스레드가 아니면 소유 스레드로 **예약**한다(블록 `setType`, 인벤토리 `setItem`·`addItem`, 엔티티 PDC `set`). 예약은 순서가 유지된다.
4. **쓰자마자 읽기**: 플레이어 인벤토리의 `Inventory` 객체는 "아직 적용되지 않은 쓰기"를 들고 있다가 읽을 때 겹쳐 보인다. 그래서 접속 처리기(netty 스레드)나 전역 스레드의 명령 안에서 `addItem` 을 연달아 불러도 서로 덮어쓰지 않는다(`KitPluginTest` 가 접속 처리기 모양으로 확인). 블록·엔티티 쓰기는 이런 겹침이 없다 — 쓰고 바로 읽으면(소유 스레드가 아닌 한) 읽기가 거절된다.
5. **결과가 필요한 것**(`World#spawnEntity`, `getNearbyEntities`)은 소유 스레드에서만, 아니면 `ThreadOwnershipException`.

이를 위해 Furnace API 에 작게 더했다(서버 쪽 구현은 `plugin/` 안):
- `Player.heldSlot()`(어느 스레드나)·`Player.setHeldSlot(int)`(소유 스레드, 예약 가능).
- `World.spawnEntityNow(type, at)`·`World.nearbyEntitiesNow(center, radius)`: 비동기판과 같은 일을 소유 스레드에서 곧바로. 비동기판(`spawnEntity`·`nearbyEntities`)은 region 대기열에 넣어 **같은 스레드에서 불러도 다음 틱에야** 끝나므로 Bukkit 의 동기 호출을 올릴 수 없었다.
- `Entity.editPersistentDataNow(edit)`: `editPersistentData` 가 항상 다음 틱인 것과 달리 소유 스레드에서 곧바로(플레이어는 어느 스레드나).

## Bukkit 원문과 달라질 수 있는 곳 (컨테이너에서 Bukkit 원문 대조 불가 — 기억 기준)

1. **`addEnchantment` 검사 생략** — 위. Bukkit 은 최대 레벨 초과·적용 불가 아이템에서 `IllegalArgumentException`.
2. **`addItem` 의 쌓기 한도** — 빈 칸에 새로 넣을 때 아이템 종류의 최대 스택(예: 진주 16)으로 쪼갠다(바닐라와 같음). CraftBukkit 이 인벤토리 한도(64)로 쪼갠다는 기억이 있는데 확신이 없어 바닐라 규칙을 택했다.
3. **`getNearbyEntities`** — Bukkit 은 엔티티의 충돌 상자가 겹치는지 보지만 Furnace API 는 엔티티 **위치**만 알려 위치가 상자 안인지로 판단한다(가장자리에서 적게 잡힐 수 있다).
4. **`ItemMeta#getDisplayName`** — 이름이 없을 때 `null`(Bukkit 은 구현에 따라 `""` 또는 예외일 수 있다고 기억; javadoc 은 `hasDisplayName` 으로 먼저 보라고 한다).
5. **이름·설명 서식** — `§` 문자열 ↔ Text 변환은 색·굵게 같은 서식만 왕복한다(호버·클릭 이벤트는 사라진다).
6. **`Block#setType`/`setBlockData`** — 청크가 로드돼 있지 않으면 Bukkit 은 청크를 동기로 불러오지만 Furnace 는 `IllegalStateException`(동기 청크 로드가 없다).
7. **`EntityType` 상수 이름** — 레지스트리 키를 대문자로 한 것(`Material` 과 같은 규칙). Bukkit 1.21 에 남은 옛 별칭(예 `DROPPED_ITEM`)은 없다.
8. **`PlayerInventory#getItemInMainHand`** — 빈 손은 `null` 이 아니라 공기 스택(Bukkit 문서와 같음).

## 시험 (`furnace-compat-paper`, 신규 28개 + 서버 1개)

헤드리스 서버 위에서 소유 스레드(`onRegion`)와 아닌 스레드를 오가며: 평범한 스택·거울 스택 쓰기, 메타 복사 규칙, 컴포넌트 왕복, ItemFlag 와 속성 변경치 보존, PDC 왕복·중첩·복사, 인벤토리의 모든 조회·addItem 병합·removeItem·방어구·왼손·단축 칸, 소유 스레드가 아닌 쓰기 예약과 바로 읽기, 블록 쓰기·`BlockData` 문자열·`matches`, 엔티티·월드 소환과 근처 찾기(상자 판정), 엔티티·플레이어 PDC, `KitPluginTest`(접속 처리기에서 이름·마법·PDC 를 단 칼을 지급하는 jar). 서버 쪽은 `EntityWorldApiTest.synchronousTwinsRunOnlyOnTheOwningThread`. `RegistryValueTypesTest` 는 `EntityType`·`Enchantment` 가 레지스트리와 같은지 본다(생성기 `tools/compat/gen-bukkit-registries.py`).
