# 클라이언트 청크 로딩 속도 진단과 chunks-per-tick=auto — 2026-11-07

질문: "클라이언트에서 청크 로딩이 느린데 생성이 느린 건지, 패킷 전송량이 모자란 건지."
측정: 4코어 컨테이너, 시드 12345 노이즈 월드, 빠른 바닐라 클라이언트처럼 `chunk_batch_received` 에 64 를 답하는 가벼운 접속기
(`tools/bot-test/chunkrate/chunkrate.js` — minecraft-protocol 직접, 청크 본문은 해석하지 않음. mineflayer 는 JS 파싱 시간 기준으로 느린 값을 답해 속도 측정에 못 쓴다).
`r4`·`r8` = 플레이어 둘레 반경 4·8 청크가 다 온 시각.

## 1. 진단 (빌드 9b6b2f0b)

| 상황 | 걸린 시간 | 초당 청크 | 원인 |
|---|---|---|---|
| 새 땅, 시야 16 (1089청크) | 15.7~16.0초 (r4 3.1초, r8 7.6초) | 70 | JFR: CPU 의 약 95% 가 월드젠(노이즈 33%, 장식 단일 스레드 레인 15%), 직렬화 1%, 네트워크 0.2% |
| 디스크의 땅, 시야 10 (441청크) | 3.5~3.8초 | 130~140 | 전송 상한 — CPU 는 놀았다 |
| 메모리의 땅, 시야 10 | 2.0~2.1초 | 260~270 | 전송 상한 |
| 네트워크 | 청크당 원본 70KB, 압축 후 9~11KB, 최대 초당 8MB | | localhost 는 무관. 원격이면 업로드 20~65Mbps 필요 |

상한의 정체: 바닐라에는 없는 두 개 — `chunks-per-tick`(기본 16) 과 플레이어당 동시 진행 상한 `World.maxChunkSendsInFlight`(= max(16, 2×코어)).
둘 다 올려야 빨라졌다(`chunks-per-tick=64` 만 올리면 변화 없음, 동시 상한 64 까지 같이 올리면 메모리 0.85초). 여기에 region 작업 큐가 틱마다 한 번 비워져
청크 하나가 1~2틱(50~100ms) 기다렸다.

바닐라와 다른 점(클라이언트 속도 따르기·미확인 배치 10개는 같았다):
- 바닐라 `PlayerChunkSender` 는 **준비된 청크만** 배치에 넣는다. Furnace 는 아직 생성 중인 좌표도 넣어, 배치 끝(Finished)이 가장 느린 생성을 기다렸다(배치 최대 0.5~0.9초).
- 바닐라는 클라이언트가 알린 값(최대 64/틱)만 따른다. Furnace 는 위 두 상한이 더 있었다.

## 2. 바꾼 것

- `furnace.properties` 의 `chunks-per-tick` 에 `auto` 추가, 기본값이 `auto`(파일이 없을 때도). 숫자를 쓰면 예전 방식 그대로.
- `auto` (`Region.sendQueuedChunksAuto`): 대기열을 가까운 것부터 훑어
  - 이미 로드된 청크는 클라이언트가 알린 만큼(최대 64/틱, 첫 응답 전에도 64) 배치로 보낸다. 주인 region 스레드에서 바로 본문을 꺼내 같은 틱에 나간다(`World.serializedChunkBody(cp, true)`).
  - 아직 없는 청크는 배치에 넣지 않고 생성·디스크 로드를 미리 걸어 둔다(동시 상한은 그대로 `maxChunkSendsInFlight` — 생성이 몰려 가까운 청크가 밀리지 않게). 이 region 청크면 작업 큐를 거치지 않고 바로 건다. 다 되면 다음 틱 배치에 들어간다.
  - 미확인 배치가 한도라 보낼 수 없는 틱에도 미리 불러오기는 계속한다. 한 틱에 훑는 수는 1024 로 묶었다(시야 32 = 4225청크).
- `furnace.properties` 자동 생성(`FurnacePropertiesFile`): 서버를 켤 때 없으면 모든 옵션을 기본값·설명과 함께 만들고, 있으면 아직 적히지 않은 옵션(주석으로 적힌 것도 적힌 것으로 봄)만 끝에 덧붙인다. 기본값 그대로 쓰므로 동작은 바뀌지 않는다. 코어 수에 따라 달라지는 `region-threads`, 비워 두면 뜻이 달라지는 `proxy-protocol.trusted`·`dimension-seed.*` 는 주석으로 쓴다.
