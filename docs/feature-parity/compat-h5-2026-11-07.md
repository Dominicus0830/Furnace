# NMS·CraftBukkit 직접 사용 플러그인 지원 설계 (H5) — 2026-11-07

결정 R2(2026-11-07 확정)는 Bukkit·Paper API 표면(H1~H4)만이 아니라 `net.minecraft`(NMS)와 `org.bukkit.craftbukkit` 를 **직접 쓰는 플러그인도 최대한 돌게** 하라는 것이다. H5 는 그 일을 하는 H6·H7 이 무엇을 어떤 순서로 어떻게 만들지 정하는 **설계·측정 묶음**이다. 코드(shim·어댑터)는 이 PR 에 없다 — 있는 것은 측정 도구(`NmsScan`·`nmsReport`)와 그 결과 표뿐이다.

- 호출 빈도 표(생성 파일): [`compat-h5-nms-calls-2026-11-07.md`](compat-h5-nms-calls-2026-11-07.md)
- 사용자 결정·확인: `docs/user-todo/entries/2026-11-07-h5.md`, 함정·근거: `docs/feature-parity/context-notes/2026-11-07-h5.md`

**작업 묶음 정의와 H4 의 순위 1 이 다르다.** H4 문서는 "다음 묶음 제안 A(명령·스케줄러·서비스를 `JavaPlugin` 에 연결)"를 1위로 꼽았지만, 작업 묶음 문서의 H5 는 **NMS·CraftBukkit 지원 설계 + 호출 빈도 표**다. 정의를 따랐다(코디네이터 지시). A 는 H5 와 독립이며 `CompatServer`·`JavaPlugin` 을 만지므로 H6 와 같은 파일에서 부딪힌다 — A 를 먼저 병합하고 H6 를 시작하길 권한다(6장).

## 1. 측정이 알려 준 것 (표본 19개)

표본은 Maven Central 에서 받을 수 있는 실제 jar 뿐이다: 플러그인 3(helper·CommandAPI 두 변종), 라이브러리 16(NMS 를 쓰는 것을 일부러 더했다: 서명 GUI·반사 도우미·스코어보드·파티클·발광 엔티티·InventoryFramework 등). **인기 NMS 플러그인(ProtocolLib·WorldEdit·Citizens·EssentialsX·LuckPerms 등)은 Central 에 없어 표본에 없다** — 이 표는 "방향을 정하는 근거"이지 인기 플러그인의 호출 통계가 아니다. 사용자가 jar 를 주면 `-PextraJars=<폴더>` 로 같은 도구를 돌려 표를 늘린다(`user-todo` 참고).

## 2. 지원 등급

플러그인 하나가 "돈다"는 말은 그 플러그인이 부르는 NMS·CraftBukkit 표면이 전부 덮였다는 뜻이다. 표면(클래스·메서드·필드 묶음) 하나마다 등급을 매긴다.

| 등급 | 뜻 | 약속 | 구현 방식 |
|---|---|---|---|
| **A 완전** | 바닐라와 같은 결과를 내는 shim. 모양(이름·서명·부수효과)이 같다 | 호출하면 Paper 와 같게 동작한다. 시험으로 고정한다 | Furnace 값·API 위에 얇게 얹는다(순수 값 클래스, NBT, 좌표 등) |
| **B 부분** | 일부 메서드·일부 종류만 된다. 되는 것은 A 와 같고 **되지 않는 것은 반드시 `UnsupportedNmsCall`** | "조용히 틀리지 않는다" — 값을 지어내거나 무시하지 않는다 | 소유 스레드 규칙(4.3)·지원 종류 표를 두고, 밖은 5장 방식으로 실패 |
| **C 불가** | 모양을 맞춰도 의미를 지킬 수 없다(서버 구조가 다르거나 Furnace 의 멀티스레드 모델과 충돌) | 로드 때 표시하고 호출·상속 시 `UnsupportedNmsCall`. 대체 Furnace API 가 있으면 메시지가 알려 준다 | 만들지 않는다. 대체 API 문서 링크만 둔다 |

**등급은 "표면 단위"이고, 플러그인 단위 판정은 H4 식 대조표가 한다**: 플러그인이 닿는 모든 표면이 A·B(B 중 쓰는 부분이 지원 범위)이면 "돌 가능성 있음", C 가 하나라도 있으면 "그 기능만 실패"(플러그인 전체가 죽지 않는다 — 5장).

## 3. 이름 체계와 변환 규칙

### 3.1 네 가지 이름

| 체계 | 예 | 누가 쓰나 | 이 서버에서의 지위 |
|---|---|---|---|
| **Mojang 이름** | `net.minecraft.server.level.ServerPlayer`, 멤버 `connection`, `getX()` | Paper 1.20.5+ 런타임, Paper 용 최신 플러그인(`paperweight-userdev` mojang 매핑) | **정규 체계(shim 이 실제로 갖는 이름)** |
| **Spigot 이름** | `net.minecraft.server.level.EntityPlayer`, 멤버 `b`·`a` | Spigot·옛 Paper 용으로 컴파일된 플러그인(대부분의 기존 jar) | 로드 때 Mojang 이름으로 **변환**한다 |
| **버전 접미사** | `org.bukkit.craftbukkit.v1_21_R1.entity.CraftPlayer`, 구 `net.minecraft.server.v1_16_R3.*` | Spigot(접미사 있음), 옛 플러그인 | 접미사를 지우고 정규 이름으로. 구 `net.minecraft.server.vX.*`(1.17 이전)는 1.21.1 에서 의미 없다 — 해당 모듈은 어차피 안 고른다(버전 모듈 선택, 발견 5) |
| **Furnace 내부 이름** | `org.domi.furnace.server.entity.Zombie` | `Internals` 로 꺼낸 플러그인(`docs/api/internals.md`) | 그대로. shim 은 이 위에 얹힌다 |

**정규 체계를 Mojang 이름으로 두는 이유**: ① 발견 8 — Paper 의 변환 라이브러리가 `net.minecraft.server.level.ServerPlayer` 가 있으면 변환을 끄므로 Mojang 이름 쪽이 "변환 없는 길"이다. ② Furnace 패킷 API 의 래퍼가 이미 Mojang 이름(`ClientboundSystemChatPacket` …)이다. ③ Spigot 이름은 난독화 위에 얹은 별칭이라 본질이 "Mojang 이름에서 바뀐 이름표"다 — 한 방향(Spigot→Mojang)만 있으면 된다.

### 3.2 jar 의 이름 체계 판정

1. 매니페스트 `paperweight-mappings-namespace` 가 `mojang` 이면 Mojang, `spigot` 이면 Spigot(기억 기준: Paper 가 쓰는 속성, 이 도구가 CommandAPI mojang 변종에서 값 `mojang` 을 확인함. `spigot` 값은 실물 미확인).
2. **속성이 없으면 Spigot 이름으로 가정**한다(Paper 의 규칙, 기억 기준). 측정 도구의 관찰 어림(멤버 이름 1~2글자·`$a` 내부 클래스)은 **로그 힌트로만** 쓴다 — 가정과 어림이 어긋나면 `플러그인 X: Spigot 가정이나 Mojang 이름으로 보임` 경고만 남기고 결정에는 쓰지 않는다(통계 어림은 jar 단위 투표라 섞인 jar 에서 틀린다).
3. 둘이 섞이면(예: 한 jar 안에 여러 버전 모듈을 합친 라이브러리) **클래스 단위**로 정한다 — 버전 모듈마다 체계가 다를 수 있다(signgui 의 `Wrapper*`/`MojangWrapper*`, IF 의 최신 모듈만 Mojang 이름이 그렇다).
4. 판정 결과를 로드 로그 한 줄로 남긴다(`플러그인 X: NMS 이름 체계=Spigot(관찰), 변환 적용`).

### 3.3 변환 순서 (로드 때 클래스 하나마다)

1. 버전 접미사 제거: `org/bukkit/craftbukkit/v1_21_R1/` → `org/bukkit/craftbukkit/`, 구 NMS 패키지는 건드리지 않고 5장 방식으로 처리(1.21.1 에 없음).
2. Spigot 이름이면 클래스·필드·메서드 이름과 서명을 Mojang 이름으로(상속 사슬을 따라 멤버의 선언 클래스를 찾는다 — `EntityPlayer#b` 는 상위 클래스가 선언했을 수 있다).
3. 바이트코드의 리플렉션 호출을 `ReflectionBridge` 호출로 바꾼다(5.2).
4. shim 에 없는 심볼을 가리키는 호출 위치를 `UnsupportedNmsCall` 던지기로 바꾼다(5.1).

### 3.4 서버가 알리는 이름

플러그인이 서버 이름을 보고 모듈·경로를 고르므로 **알리는 값이 중요**하다.

- `Bukkit.getBukkitVersion()` → `1.21.1-R0.1-SNAPSHOT`(H1 이 이미 맞춤). 표본에서 모듈 선택의 주 경로다(발견 5).
- `Bukkit.getServer().getClass()` 의 패키지 이름 → 기본 **접미사 없는 `org.bukkit.craftbukkit`**(기억 기준: Paper 1.20.5 이후. Spigot 은 `v1_21_R1` 접미사. 원문 대조 못 함). 검토 지적: 표본에서 접미사를 읽는 것은 signgui 뿐이고 폴백이 있어 "접미사 포함이 안전"이라는 처음 근거는 표본이 지지하지 않는다. Paper 호환을 겨냥하므로 Paper 와 같게 두고, **두 이름 모두 클래스 로딩이 풀리게** 한다(`Class.forName("org.bukkit.craftbukkit.v1_21_R1.entity.CraftPlayer")`·접미사 없는 이름 둘 다 같은 클래스). 옵션 `plugins.compat.nms.version-package`(`plain` 기본 / `versioned`)로 바꾼다.
- **Paper 탐지 마커.** 라이브러리가 Mojang 이름 모듈로 갈지 Spigot 이름 모듈로 갈지를 `Class.forName("com.destroystokyo.paper.ParticleBuilder")` 같은 Paper 전용 클래스 존재로 가른다(signgui, 검토가 바이트코드로 확인). 지금 `furnace-compat-paper` 에는 `com.destroystokyo.paper.*`·`io.papermc.*` 클래스가 없어 이런 라이브러리는 **Spigot 이름 모듈(변환표 필요)** 로 간다. 같은 jar 가 Mojang 모듈도 싣고 있으므로 마커 클래스만 있으면 **변환표 없이** 돈다 — H7d(변환표)의 한계 가치를 낮출 수 있다. 어떤 마커 클래스가 쓰이는지는 NmsScan 이 상수 풀 문자열에서 `com.destroystokyo.`·`io.papermc.` 리터럴을 모아 측정한다(후속). **H7d 는 마커로 Mojang 모듈로 가는 길을 먼저 측정한 뒤에 시작한다.**
- 실제 클래스 이름(`getClass().getName()`)은 정규 이름(접미사 없음)이다. 플러그인이 `getName()`·`getPackage().getName()`·`getPackageName()` 으로 읽을 때 `ReflectionBridge` 가 위 옵션대로 접미사를 붙여 준다(CraftBukkit·NMS 클래스일 때만).
- Mojang 이름 런타임 판정(발견 8)이 참이 되도록 `net.minecraft.server.level.ServerPlayer` 는 실제로 로드 가능해야 한다.

### 3.5 데이터 공급 (사용자 결정 필요)

Spigot→Mojang 변환표는 **Mojang 공식 매핑**(난독화 → Mojang 이름)과 **Spigot 매핑**(난독화 → Spigot 이름)에서 얻는다. 둘 다 이 컨테이너에서 받을 수 없고(Mojang·Spigot 호스트 차단), 규칙상 Mojang 데이터를 저장소에 커밋하지 않는다. 그러므로 변환표 자체는 **이 PR 이 만들 수 없다**(값을 지어내지 않는다). 설계는 이렇다.

- 도구 `tools/compat/gen-nms-mappings.py`(H7): 사용자가 가진 두 매핑 파일을 읽어 `furnace-nms-mappings-1.21.1.tsv`(소스 이름 → Mojang 이름, 클래스·필드·메서드+서명)를 만든다. 저장소에 커밋하지 않고 서버 `plugins/.compat/` 에 둔다.
- 서버는 이 파일이 없으면 Spigot 이름 플러그인에 대해 **정직하게 거절**한다(`NMS 이름 변환표가 없어 Spigot 이름 플러그인을 돌릴 수 없다`, 변환표 만드는 법 안내). Mojang 이름 플러그인은 표 없이 돈다.
- 선택지(결정): ① 운영자가 매핑 파일을 직접 두기(기본, 라이선스 안전). ② 운영자가 명시적으로 켜면 서버가 매핑을 내려받기(R1 의 "라이브러리 내려받기"와 같은 옵트인·체크섬). ③ 우리가 가장 흔한 N개 이름만 손으로 적은 표(저작권 문제는 낮지만 틀린 이름이 섞이는 위험 — 지어내기에 해당하므로 비추).

## 4. 구조

### 4.1 모듈

```
furnace-api ← furnace-compat-paper (Bukkit API·CompatXxx, H1~H3)
                    ↑
              furnace-compat-nms (신규, H6·H7)  ──compileOnly──▶ furnace-server
```

- **`furnace-compat-nms`** 는 `net.minecraft.*`(shim)와 `org.bukkit.craftbukkit.*`(어댑터)를 **같은 모듈**에 둔다 — 서로 타입을 주고받는다(`getHandle()` 의 반환형이 shim). `furnace-compat-paper` 는 "서버 구현에 의존하지 않는다"가 원칙이지만 NMS 는 정의상 서버 내부이므로 이 모듈만 `compileOnly(project(":furnace-server"))` 를 허용한다(`Internals` 다리의 구현 클래스를 쓰기 위해). 서버 내부가 바뀌면 이 모듈이 **컴파일 오류로 먼저 알려 준다** — 조용히 어긋나지 않는다는 이점.
- 호환 계층의 객체 공장(`Compat.player(...)` 등)은 ServiceLoader(`CraftFactory`)로 NMS 모듈이 있으면 `CraftPlayer`·`CraftWorld` … 를 만들고 없으면 지금의 `CompatPlayer` 를 만든다. `CraftPlayer extends CompatPlayer`, `CraftServer extends CompatServer` 로 이어 캐스트(`(CraftPlayer) p`)가 성립한다.
- `fatJar` 가 이 모듈도 합친다(H1 의 `furnace-compat-paper` 와 같다). 새 옵션 `plugins.compat.nms.enabled`(기본 켜짐 — 안 켜면 NMS 쓰는 플러그인은 어차피 못 도므로).
- 새 의존: 바이트코드 변환용 **ASM**(`org.ow2.asm:asm`·`asm-commons`, BSD, Maven Central). 서버 jar 에 합친다. JDK 21 에는 공식 클래스 파일 API 가 없다.

### 4.2 로더 훅

서버의 `PluginClassLoader`(URLClassLoader)는 `findClass` 에서 jar 바이트를 읽어 그대로 정의한다. H7 은 `furnace-api` 의 `PluginFormat` 에 **기본 메서드**를 더한다:

```java
default ClassTransformer transformer(PluginDescription d, Path jar) { return null; }   // null = 변환 없음
interface ClassTransformer { byte[] transform(String className, byte[] bytes); }
```

서버는 변환기가 있으면 `findClass` 에서 바이트를 변환기에 거쳐 `defineClass` 한다(코드소스·패키지 정의는 지금과 같다). 호환 형식(`CompatFormat`)이 NMS 모듈이 있으면 변환기를 돌려준다. 변환기는 **jar 를 처음 열 때 한 번** 상수 풀 전체를 훑어(측정 도구와 같은 리더) 이름 체계를 판정하고 호환 보고(5.3)를 만든다. 핫 리로드(B8)는 로더를 새로 만들므로 변환도 다시 일어난다 — 별도 상태를 로더 밖에 두지 않는다.

### 4.3 shim 규약

1. **스레드**: shim 은 H3 의 `Owned.read/write` 패턴을 그대로 쓴다. 소유 스레드가 아니면 쓰기는 예약 겹침, 읽기는 `ThreadOwnershipException`(조용히 틀린 값을 주지 않는다). `Future` 를 기다리지 않는다. NMS 코드는 "메인 스레드에서만 부른다"는 가정으로 짜여 있으므로 이 규칙이 가장 자주 부딪힐 곳이다 — `isSameThread()` 같은 질의는 "이 스레드가 그 객체의 소유자인가"로 답한다.
2. **정체성**: 같은 서버 객체에 대한 `getHandle()` 은 같은 shim 객체를 준다(`==` 비교·`Map` 키로 쓰는 플러그인이 많다). 약한 참조 캐시를 객체 소유 쪽에 둔다(엔티티가 사라지면 같이 사라진다).
3. **값 객체**: `ItemStack`·`BlockPos`·`Component` 같은 값은 shim 이 Furnace 값의 가변·불변 모양 차이를 흡수한다(`ItemStack` 은 H3 의 `ItemSlot` 거울을 쓴다. 거울은 칸에 묶이지 않고 NMS 객체에 묶인다는 H3 검토 지적을 그대로 따른다).
4. **필드**: 공개 필드(`ServerPlayer.connection` 등)는 변하지 않는 값이면 실제 필드, 변하는 값이면 바이트코드 변환으로 접근자 호출로 바꾼다(필드 읽기 → 정적 도우미).
5. **하지 않는 것**: 바닐라 클래스를 싣지 않는다(EULA). shim 은 "모양"만 같은 새 코드이고, Mojang·Spigot·CraftBukkit 원문을 복사하지 않는다(H1 의 clean-room 과 같은 원칙, 라이선스 판단은 H1 사용자 결정에 묶임).

## 5. 미지원 호출의 실패 방식

원칙: **조용히 틀리지 않는다.** 값을 지어내거나 호출을 무시하지 않는다. 실패는 (a) 어느 플러그인의 어느 호출인지 알려 주고, (b) 플러그인이 쓰는 **기능 감지(feature detection)** 를 깨지 않는다.

### 5.1 바이트코드의 직접 호출 — 호출 위치에서 던진다

변환기가 상수 풀을 훑어 shim 에 없는(또는 C 등급인) 심볼을 가리키는 `invoke*`·`getfield`·`new` 를 `UnsupportedNmsCall` 던지기로 바꾼다. 그 호출이 **실행될 때만** 던진다 — 로드 때 터지지 않으므로 그 기능을 안 쓰는 플러그인은 멀쩡히 돈다. 메시지:

```
미지원 NMS 호출: 플러그인=Foo, 호출 위치=com.foo.Bar#baz:42, 대상=net.minecraft.world.level.chunk.LevelChunkSection#setBlockState
등급 C — 서버 청크 구조가 다르다. 대체: Furnace 블록 API·Internals#withLevel (docs/feature-parity/compat-h5-2026-11-07.md#2-1)
```

`UnsupportedNmsCall extends UnsupportedFeature`(`UnsupportedOperationException` 의 하위, `furnace-compat-paper` 에 있음). 같은 (플러그인, 대상)은 첫 번째만 `WARN`, 나머지는 `DEBUG`(로그 폭주 방지).

> **H7 구현에서 바뀜(2026-11-08, PR #143 검토):** 바이트코드 덫은 `UnsupportedNmsCall` 대신 JVM 이 냈을 링크 오류의 하위(`UnsupportedNmsLink`: `NoSuchMethodError`·`NoSuchFieldError`·`NoClassDefFoundError`)를 같은 메시지로 던진다. `catch (NoSuchMethodError | LinkageError)` 기능 감지(5장 원칙 b)를 지키기 위해서다. `UnsupportedNmsCall` 은 JVM 대응물이 없는 거절(정의 거부·strict·`connection.send` 거절·shim 의 미지원 의미)에 남는다. 자세한 것은 [compat-h7](compat-h7-2026-11-08.md).

### 5.2 리플렉션 — 진짜처럼 실패한다

`Class.forName(String)`·`ClassLoader.loadClass`·`Class#getDeclaredField/Method/Constructor`·`MethodHandles.Lookup#find*` 호출을 `ReflectionBridge` 로 바꾼다. 다리는 ① 이름을 정규 체계로 변환(`v1_21_R1` 제거, Spigot 이름이면 변환표로), ② shim 에 있으면 그것을 주고, ③ **없으면 자바가 줄 법한 예외를 그대로**(`ClassNotFoundException`·`NoSuchFieldException`·`NoSuchMethodException`) 던진다 — 다만 `WARN` 한 번으로 "플러그인 X 가 NMS 이름 Y 를 찾았으나 없음"을 남긴다. 스텁 클래스를 만들어 "있는 척"하면 `try { Class.forName(새 이름) } catch { Class.forName(옛 이름) }` 같은 플러그인의 기능 감지가 깨지므로 하지 않는다. 클래스 이름·패키지 이름을 읽는 호출(`getName`·`getPackage().getName()`)은 3.4 의 옵션대로 접미사를 붙여 돌려준다.

### 5.3 로드 때 호환 보고

jar 를 처음 열 때 상수 풀 요약을 한 번 남긴다: `플러그인 X: NMS 심볼 N개 중 A 등급 a, B 등급 b(지원 종류 안 m, 밖 k), C 등급 c, 알 수 없음 u. 이름 체계=Spigot, 변환표=있음`. 앞 20개 미지원 심볼을 나열한다. 플러그인을 막지 않는다(경고만 — 못 쓰는 기능만 실패하면 되므로). 옵션 `plugins.compat.nms.strict=true` 면 c+u>0 일 때 플러그인 로드를 거절한다(운영자가 "반쪽 동작보다 안 켜는 편"을 고를 수 있게, 기본 꺼짐).

### 5.4 상속 — 정의 때 던진다

플러그인 클래스가 C 등급 NMS 클래스를 상속(`extends Zombie`)하면 그 플러그인 클래스를 **정의하는 순간** `UnsupportedNmsCall` 을 던진다(바이트코드로는 대체할 수 없다). 그 클래스를 쓰는 기능만 죽는다.

**H7a 요구사항(검토 지적).** ① 리플렉션 호출 치환은 **호출자 민감**이다: `Class.forName(String)` 은 호출한 클래스의 로더로 찾으므로 `ReflectionBridge.forName(name, callerClass)` 처럼 호출자 `Class` 를 넘겨야 한다(`MethodHandles.lookup()` 류도 같다). ② ASM 으로 `invoke*` 를 던지기로 바꿀 때 인자를 `pop`/`pop2` 로 비우고 스택맵 프레임을 다시 계산하되, `COMPUTE_FRAMES` 의 `getCommonSuperClass` 가 병렬 가능 로더에서 클래스를 잘못 로딩하지 않게 재정의한다. ③ 상속 거절(5.4)이 `NoClassDefFoundError` 로 포장돼 보이지 않는지 시험으로 모양을 고정한다. ④ 새 모듈 머리말에 "서버 구현에 의존" 예외 사유를 적는다(`furnace-compat-paper` 원칙의 예외).
**H7c 선행(검토 지적).** 표본이 부르는 패킷은 약 13종인데 래퍼가 있는 것은 4종(SIGN_UPDATE·ADD_ENTITY·REMOVE_ENTITIES·SET_ENTITY_DATA)뿐이다(검토 직접 grep, 근사) — 서명 GUI(열기 패킷)·스코어보드(전부)·파티클이 첫 호출에서 `UnsupportedNmsCall` 이다. H7c 앞에 `furnace-api` 패킷 래퍼 추가 묶음(표본 상위 패킷 우선)이 필요하다. NmsReport 에 패킷 클래스 절을 더하는 것은 후속.
**`getHandle()` 의 "A" 는 이름이 풀린다는 뜻이지 돌려준 shim(`ServerPlayer`·`Entity`·`ServerLevel`)의 멤버를 다 쓸 수 있다는 뜻이 아니다.** 표 상위의 `Advancement(Holder)`·`RecipeHolder`·`LootDataManager`·`WorldDataConfiguration`·`CommandFunction`·`ResourceArgument`·`EntitySelector` 는 2.1 에 등급이 없다 — H7e 가 항목별로 매긴다. 표 14/14 "리플렉션 호출"은 어떤 대상이든 세므로 NMS 와 연결된 리플렉션의 근거는 약하다(리터럴이 있고 리플렉션도 있다 정도로 읽을 것).

**NMS 대조표(H4 방식)**: H7a 가 `ApiIndex` 의 NMS 판을 더해 표의 "있음/없음" 열과 기준표(없는 심볼 수가 늘면 시험 실패)를 만든다. 지금 표는 빈도만 있다.

처음부터 **다 지원**하려 하지 않고, 표의 상위(핸들 얻기 → 아이템 다리 → 좌표·NBT·채팅 → 패킷 보내기)로 실제 플러그인(예: CommandAPI 의 Mojang 변종·signgui·scoreboard-library 가 부르는 범위)이 한 걸음씩 가는 것을 H4 식 기동 시험으로 측정한다.

모델·노력치(참고): H7a·H7d 는 설계·성능 영향이 커서 Opus high(코디네이터가 Fable 대기열로 넣을 후보), H7b·H6b·H7e 는 Sonnet high, H6a·H7c 는 Opus high.

## 7. 위험

- **표본 편향**: 인기 NMS 플러그인이 표에 없다. 순위가 바뀔 수 있으므로 jar 를 받으면 표를 다시 만든다.
- **리플렉션 하한**: 문자열로 조립된 이름은 조각만 보인다. 실제 사용은 더 넓다. H7a 가 `ReflectionBridge` 에 "찾아본 이름" 통계를 남겨(옵션) 실사용 표를 만든다.
- **성능**: 변환은 jar 당 1회(로드), 호출 경로 비용은 `ReflectionBridge` 의 해시 조회와 shim 객체 한 겹. `Class#getName` 바꿔치기는 CraftBukkit·NMS 클래스일 때만 작동해 비용이 일반 플러그인에 닿지 않는다.
- **정직성 대 호환성**: B 등급의 "지원 종류 밖은 던진다"는 일부 플러그인을 켜자마자 죽게 만들 수 있다. 옵션(`strict`)과 보고가 그 균형을 운영자에게 준다.
- **라이선스**: shim 을 CraftBukkit(GPL)·Spigot 원문 없이 쓴다 — H1 의 clean-room 판단과 같은 사용자 결정(GPLv3 관계)에 묶인다. Mojang 매핑 재배포 가능 여부는 확인하지 못했다(저장소에 넣지 않는 설계로 피함).
