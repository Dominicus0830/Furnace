# 연결 자동 추론기 설계 (T-263, 2026-11-23)

> 지시(코디네이터 11-23): 전체 껍데기(T-260)·빠진 멤버(T-261)의 "동작 없음" 멤버를 이미 있는 Furnace 서버·API 기능에 **프로그램이** 잇게 해서, 영역 스레드 12개가 동작 채우기를 대부분 기계로 하게 한다.
> 근거: `docs/roadmap/full-shells-2026-11-23.md` 7~8장, 조사 `faster-shim-and-version-up-research-2026-11-23.md` 5.2(안 2), T-235 차분 틀(`docs/feature-parity/compat-vanilla-diff-t235-2026-11-23.md`), T-262 채움 틀(PR 569, `furnace-compat-paper/src/shimspec/README.md` 마지막 절).
> 이 문서는 구현 전 설계다. 독립 검토를 받은 뒤 구현한다.

## 1. 결론

- **실측해 보니 "이름·형식이 맞는 Furnace 메서드를 찾아 잇기"만으로는 채울 수 있는 몫이 작다**(2장). 플러그인이 부를 수 있는(공개·보호) 동작 없는 NMS 메서드 32,352개 가운데 Bukkit API 에 같은 이름·인자 수의 짝이 있는 것은 647개(2.0%), 바닐라 안에서 이미 살아 있는 멤버로 그냥 넘기는 몸통은 73개다. 나머지는 바닐라 몸통이 진짜 계산(분기·여러 호출)이고, 그 계산은 이식 금지라 **Furnace 쪽 구현에 이어야** 한다.
- 그래서 추론기를 "이름 맞추기 하나"가 아니라 **후보 생성기 다섯 갈래 + 정답기 네 단계 + 채택 규칙 + 영역 스레드 작업 목록**으로 만든다.
  - G0 **값만으로 정해지는 짧은 몸통**(상수 반환·빈 몸통·살아 있는 정적 필드 반환 등, 공개·보호 약 2,250개) — T-262 채움 틀에 종류를 더한다(연결이 아니라 채움).
  - G1 **관용구 목록**: 바닐라에서 자주 반복되는 몸통 모양(엔티티 데이터 읽기·쓰기, 블록 상태 속성 읽기·바꾸기, 속성값 읽기 등)마다 Furnace 쪽 구현을 **한 번** 손으로 쓰고, 추론기가 그 모양의 멤버 전부에 값(어느 칸·어느 속성)만 뽑아 잇는다. 지금 공개·보호 약 780개, 영역 스레드가 관용구를 더할수록 는다.
  - G2 **연결 대상 목록과 짝짓기**: 표지 단 다리(`@LinkTarget`)·Furnace 의 Bukkit 구현과 이름·형식 대응 표로 짝짓는다.
  - G3 **퍼뜨리기**: 한 멤버가 이어지면 바닐라 몸통 지문이 같은 다른 클래스의 멤버(하위 클래스 재정의 등)에 같은 연결을, 같은 클래스 안 별칭에 `this.다른이름` 을 **후보로** 낸다(퍼뜨린 후보도 정답기를 다시 거친다).
  - G4 **"다리 필요" 작업 목록**: Furnace 서버가 이식한 바닐라 클래스(`@VanillaPort`, 974개)의 멤버와 짝을 지어 "이 멤버는 서버의 어느 메서드가 이미 하고 있다"를 적는다. 연결은 만들지 않는다(서버를 부르려면 경계 규칙상 손으로 쓴 다리가 필요). 영역 스레드가 다리를 쓰면 다시 돌려 G2·G3 가 잇는다.
- 채택: 정답기(T-235 차분 틀을 넓힌 것)가 바닐라와 같다고 증명하고 **그 멤버마다 대조가 실제로 차이를 가려냄**(서로 다른 출력 2개 이상 + 그 멤버의 돌연변이가 "다름"으로 떨어짐)이 확인된 **읽기·순수** 줄만 검토 없이 채택(결정 F1). 쓰기는 검토 받은 관용구로 이은 줄만 기계적 묶음(결정 D2, 조건 6장)이고, Bukkit 구현으로 잇는 쓰기와 증명 못 한 줄은 후보 보고서로 가서 영역 스레드가 검토 뒤 넣는다. 후보가 둘 이상 통과하면 채택하지 않는다.
- 출력은 영역별 **연결 파일**(`src/shimspec/links-1.21.1/<영역>.links`, 명세 줄 문법)이고, 전체 껍데기 생성기(`FullShells`·`ShellMerge`)가 던지는 몸통 대신 연결 몸통을 바이트코드로 만든다. 그래서 껍데기 클래스·손 shim 클래스·레코드·열거형 어디든 같은 길로 채워지고, 손 shim 을 명세로 옮기기 전에도 쓸 수 있다.
- **기대치(가정, 4장)**: 도구 단계가 끝나면 추론기와 T-262 를 합쳐 공개·보호 NMS 동작 없음 메서드의 **약 20~25%** 가 기계로 채워진다(멤버 수 균등 비율 — 플러그인 사용 가중 비율은 S5 가 잰다). 로드맵 8장이 "채택률 50% 미만이면 영역 2·5·8 이 늘어난다"고 적은 쪽이다 — 영역 채우기는 보수 쪽(6주) 또는 그 이상으로 잡아야 한다. 나머지 80% 의 가치는 **"찾기"를 기계가 해 준 작업 목록**(G4·후보 보고서)이다.

## 3. 설계

### 3.1 흐름

```
서명표 셋 + 채움 표 + 바닐라 jar(캐시) + 본문 지문표(BodyTable)
            + 컴파일된 호환 jar + 껍데기 jar(build)
                      │
   :furnace-compat-paper:inferLinks  (shimgen 소스셋, 이름 들어간 결과는 build/ 에만)
     ├ 대상 목록 읽기: @LinkTarget·@LinkIdiom·@LinkConvert 표지가 붙은 호환 계층 메서드, Furnace Bukkit 구현
     ├ 동작 없음 멤버 목록(껍데기 jar 의 @NmsShellMember) × 바닐라 몸통
     ├ G1 관용구 맞추기 → G2 대상 짝짓기 → G3 퍼뜨리기 (G0 는 T-262 쪽)
     └ G4 서버 이식 짝(작업 목록만)
                      │ 후보(build/reports/link-infer/candidates.tsv)
                      ▼
   :furnace-compat-paper:vanillaDiffTest -PlinkCandidates=…   (T-235 틀 + 새 형식 꾸러미)
     후보마다 바닐라 ↔ 후보 몸통을 같은 입력으로 견줌 → 같음/다름/증명 없음
                      │
   :furnace-compat-paper:adoptLinks
     채택 규칙(3.4)을 통과한 줄만 src/shimspec/links-<판>/<영역>.links 에 씀(정렬, 같은 입력이면 같은 바이트)
                      │
   generateFullShells: 연결 파일의 멤버는 던지는 몸통 대신 연결 몸통(소유 검사 → 변환 → 대상 → 변환)
```

추론기는 결정적이다: 같은 입력이면 같은 후보·같은 파일. LLM 을 쓰지 않는다. 바닐라 몸통은 **읽어서 분류·값 뽑기에만** 쓰고, 명령을 복사하지 않는다(이식 금지 — 3.6).

### 3.2 후보 생성기

**G0 짧은 값 몸통 (T-262 틀에 종류 추가, 연결 아님)**
`K`(상수 반환), `E`(빈 `void` 몸통), `R`(살아 있는 정적 필드 반환), `A`(인자 반환). T-262 README 의 "네 곳 규칙"(추출기·표 줄·`Fills`·`FillParityTest`)대로 더한다. 채운 멤버는 표지가 없어 "있음"이 된다. 정적 필드 반환은 그 필드가 껍데기가 아닐 때만(아니면 값이 null). PR 569 병합 뒤에 한다(같은 파일). 
제약: 생성자·필드 대입이 섞인 것은 안 한다(T-262 와 같은 "모르면 채우지 않는다").

**G1 관용구 목록 (값만 뽑아 손 구현에 잇기)**
- 관용구 = (바닐라 몸통 모양 틀, 뽑을 값 자리, Furnace 쪽 구현). 구현은 호환 계층의 정적 메서드에 `@LinkIdiom("이름")` 표지와 검사 종류를 단 것이다. 예:
  - `entity-data-get`: `return this.entityData.get(<정적 칸 필드>)` → `NmsEntityData.get(this, <칸>)` (엔티티 데이터 설계 D2~D5 의 다리)
  - `entity-data-set`: `this.entityData.set(<칸>, 인자)` → `NmsEntityData.set(this, <칸>, 인자)` (쓰기)
  - `entity-data-flag-get`: `return (this.entityData.get(<칸>) & <마스크>) != 0`
  - `state-get`: `return <상태 인자>.getValue(<속성 정적 필드>)`, `state-set`, `state-rotate`(`ChestBlock#rotate` 가족 40개), `state-definition`(`builder.add(<속성…>)` — 속성 목록 값만)
  - `attribute-value`: `return this.getAttributeValue(<속성 정적 필드>)`
- 틀 맞추기는 명령 모양이 **정확히** 같을 때만(본문 지문표의 모양 해시 + 값 자리). 값 자리에 오는 것은 리터럴이거나 **살아 있는** 정적 필드뿐(엔티티 데이터 칸 필드가 아직 껍데기면 후보 안 됨 — 엔티티 데이터 설계 D2 단계가 먼저).
- 관용구 하나를 더하는 PR = 구현 + 틀 + 정답기 꾸러미(필요하면). 관용구 구현은 손 코드라 **독립 검토**를 받고, 그 뒤 그 관용구로 이은 줄은 기계적 적용이다(결정 D2 확정, 6장).

**G2 연결 대상 짝짓기**
- 대상 목록(사람이 표지로 정함, 추론기가 짐작하지 않음):
  - `@LinkTarget(check=…, owner=…, receiver=…)` 를 단 호환 계층 정적 메서드(`NmsEntityOps`·`NmsAttributes`·`NmsBlockStates` 같은 다리). 첫 인자가 받는 쪽.
  - Furnace Bukkit 구현의 공개 메서드(받는 쪽 변환 `@LinkConvert` 로 NMS 객체 → Bukkit 객체가 있는 형식만). 검사 종류는 `api`(Bukkit 규칙대로 주인에게 넘김 — 엔티티 명세가 이미 쓰는 판정, 생성 몸통엔 소유 검사 없음). **Bukkit 구현은 읽기 대상으로만 자동 후보가 된다.** Bukkit setter 에는 NMS 에 없는 범위 검사(`Preconditions`)·이벤트가 있어 정답기로 보이지 않으므로, Bukkit 쓰기로 잇는 후보는 늘 후보 보고서로 가고 D2 의 기계적 묶음에도 들지 않는다(검토 R4).
  - Furnace 공개 API 는 대부분 비동기(`CompletableFuture`)라 직접 짝 대상이 아니다. 동기 읽기만 `@LinkTarget` 을 다는 다리로 감싸 쓴다.
- 짝 점수: 이름(get/is/has 떼고 같음 > 낱말 같음), 인자 수·형식이 **형식 대응 표**로 맞음, 반환형이 맞음. 점수는 후보 순서에만 쓰고 채택은 정답기가 정한다.
- **형식 대응 표**: `@LinkConvert` 정적 메서드들(예: NMS `Vec3` ↔ Bukkit `Vector`, `BlockPos` ↔ `Location`(월드는 받는 쪽에서), `ResourceLocation` ↔ `NamespacedKey`, NMS `ItemStack` ↔ Bukkit `ItemStack`, `Component` ↔ adventure `Component`, 같은 이름 열거형). 판과 무관, 몇십 줄. 변환이 없는 형식은 후보에서 빠진다.

**G3 퍼뜨리기**
- 별칭: 같은 클래스(사슬 포함)에서 바닐라 몸통이 살아 있는 멤버로 인자 그대로 넘기면 `this.그멤버`(85개), 넘기는 대상이 나중에 채워지면 다음 실행에서(462개).
- 같은 지문: 이미 이은 멤버(손 shim·명세·연결 파일)와 바닐라 몸통 지문(모양 해시 + 받는 쪽 이름을 지운 참조 해시)이 같은 다른 클래스의 멤버에 같은 대상을, **받는 쪽 형식이 그 대상의 `receiver` 에 맞을 때만**. 하위 클래스가 같은 몸통으로 재정의한 경우가 대부분이다.
- 퍼뜨린 것은 **후보일 뿐**이고 다른 후보와 똑같이 정답기를 거친다. 받는 쪽 이름을 지운 지문은 `Zombie.DATA_BABY_ID` 와 `Piglin.DATA_BABY_ID` 처럼 이름은 같고 칸이 다른 것을 같게 보므로, 지문만으로 잇지 않는다.

**G4 서버 이식 짝 (작업 목록, 연결 아님)**
- `@VanillaPort`(소스 전용 표지)를 읽어 바닐라 클래스 ↔ Furnace 서버 클래스 쌍을 만들고, 쌍 안에서 메서드를 바이트코드 특징(쓰는 실수·정수·문자열 상수, 난수 호출 수, 인자 수·형식 대응, 이름 비슷함)으로 짝짓는다. 점수 높은 짝 하나만, 애매하면 비운다(조사 5.4 의 4a 를 작게).
- 결과는 `build/reports/link-infer/bridge-wanted.md`(영역별, 이름 들어감 — 커밋 안 함): "이 동작 없음 멤버는 서버 `X#y` 가 이미 한다, 필요한 다리 형식은 …". 순서는 플러그인 사용 가중치(덫 계측 T-233·표본 순위 T-234) 높은 것부터. 영역 스레드가 다리(`api.internal` 또는 호환 다리 + `@LinkTarget`)를 쓰고 추론기를 다시 돌리면 G2·G3 가 잇는다.
- 서버를 리플렉션으로 부르는 범용 다리는 만들지 않는다(어댑터 경계 ①③, `docs/ops/adapter-boundary.md`). 다리는 형식이 있는 손 코드다.

### 3.3 검사 종류와 소유 규칙

- 추론기는 소유 규칙을 짐작하지 않는다(조사 5.2). 검사 종류는 **대상의 표지**에서 온다: `pure`·`read=any`·`read=snapshot`·`read=owner`·`write`·`api`(대상이 스스로 Bukkit 규칙대로 넘김).
- `read=owner`·`write` 는 표지의 `owner=` 클래스(`NmsEntityOwner` 등)의 `read/write(Object, String)` 를 연결 몸통 **첫 호출**로 넣는다(명세 생성기와 같은 약속). 빌드 시험이 연결 몸통의 첫 호출을 본다(`ShimSpecBuildTest.ownerCheckProblem` 과 같은 검사를 껍데기 jar 에).
- 대상 표지의 `receiver` 가 받는 쪽 클래스를 정한다. 받는 쪽이 정적 멤버면 `read=owner`·`write` 금지(대상이 스스로 검사 — 명세 규칙과 같음).

### 3.4 정답기와 채택 규칙

| 단계 | 받는 쪽·인자 | 어떻게 | 상태 |
|---|---|---|---|
| O1 값 | 원시값·좌표·NBT·자원 위치 등(T-235 꾸러미) | T-235 그대로 | 있음 |
| O2 레지스트리 객체 | 블록 상태(26,684 전부)·블록·아이템·`ItemStack`(기본 구성 요소+무작위 조합)·`Component`·레지스트리 키, 블록 읽기 인자(`BlockGetter`) | 바닐라는 부트스트랩 뒤 레지스트리 객체, `BlockGetter` 류 인터페이스 인자는 양쪽 로더에 같은 중립 복셀 지도를 보는 `Proxy`. **지도 모형에 없는 메서드가 불리면 Proxy 가 곧바로 던지고**(기본값 0/null 로 답하지 않음), 어느 쪽이든 그 던짐이 나온 입력이 있으면 그 멤버는 "증명 없음" | 새로 |
| O3 월드 밖 객체 | 엔티티·블록 엔티티(월드에 넣지 않은 것) | 바닐라: 생성자를 거치지 않은 `ServerLevel` 에 난수·레지스트리·프로파일러만 채워 만든다(`ExportEntityDataDefaults.fakeLevel` 선례). shim: `EntityType#create` 의 월드 밖 엔티티. 부른 뒤 상태를 내려 견준다 — 동기화 칸 전부, `saveWithoutId` NBT 전부, 경계 상자·치수(칸 훅이 치수를 바꾸므로). 엔티티 난수는 두 쪽에 같은 시드로 넣고(바닐라 `Entity.random` 을 시드 난수로 갈아 끼우고 shim 쪽도 같은 시드), 맞출 수 없으면 바닐라 몸통이 난수에 닿는 멤버는 O3 증명에서 뺀다. 바닐라 몸통이 몇 단계 호출 안에 `Level`·`ServerLevel`·`MinecraftServer` 를 부르는 쓰기 멤버(소리·입자·게임 이벤트·방송·엔티티 추가)는 정적 검사로 **O3 증명에서 빼고 O4 로** 보낸다 — fakeLevel 은 그 부수효과를 못 본다. O3 는 월드 밖 경로만 증명한다(월드 안 다리 경로는 관용구 시험이 본다, 6장 D2 조건) | 새로(가능성 먼저 확인 — S3 첫 일) |
| O4 장면 | 살아 있는 월드·플레이어·서버 | 바닐라 장면 차분기(조사 5.5) | 이 과제 밖. 후보는 "증명 없음" |

채택(`adoptLinks`):
1. 후보마다 정답기 단계를 받는 쪽·인자·반환 형식으로 고른다. 고를 수 없으면 증명 없음.
2. **멤버별 구분력**(검토 R3): 그 멤버의 대조에서 (a) 바닐라 출력(반환값·부른 뒤 상태를 내린 것)이 서로 다른 값으로 2개 이상 나오고, (b) 그 멤버에 대해 만든 돌연변이 후보(관용구 값 자리를 같은 클래스의 다른 칸·다른 속성으로, 인자 순서 바꿈, 불·비교 반환 뒤집음) 가운데 하나 이상이 "다름"으로 떨어져야 한다. 못 하면 "증명 없음"(입력이 분기에 닿지 않아 두 쪽이 같은 기본값을 내는 통과를 막음). 돌연변이를 만들 수 없는 꼴(예: 상수 하나를 돌려주는 대상)은 (a)만으로 보지 않고 증명 없음.
3. **자동 채택**: 검사 종류가 `pure`·`read=*` 이고, 정답기가 "같음"(다름 0, 시간 초과 0, 리플렉션 오류 0, Proxy 던짐 0)이고, 2를 통과했고, 그 멤버에 통과한 후보가 하나뿐일 때.
4. 통과 후보가 둘 이상이면 서로 같은 대상(별칭 정리 뒤)이 아니면 채택하지 않고 "모호함" 목록으로.
5. **쓰기**(`write`·`api` 중 바꾸는 것): O3 가 같음이어도 후보 보고서로. 영역 스레드가 PR 로 넣고 독립 검토(결정 F1). 단 결정 D2(확정)대로 "검토 받은 관용구 + O3 같음 + 2의 구분력 + Level 부수효과 없음" 인 쓰기 줄은 기계적 묶음으로 본다. **G2 의 Bukkit 구현 쓰기는 이 예외에서 빠진다**(늘 검토).
6. 증명 없음: 후보 보고서로(근거·점수와 함께). 영역 스레드가 검토 뒤 `proof=review` 로 넣을 수 있다.
7. 바닐라와 다르지만 Paper 와 같아야 하는 경우는 T-235 의 `paper` 줄 규칙을 그대로 쓴다(연결 파일 줄에 같은 꼴).

**정밀도(오채택) 재기** — 로드맵 완료 기준 "영역 하나에서 채택률·오채택 0":
- **손 멤버 숨기기**: 이미 사람이 채운 멤버(손 shim·명세, 바닐라 짝 있는 것)를 "없다"고 치고 추론기를 돌린다. 후보가 나오면 그 후보 · 손 몸통 · 바닐라를 정답기 입력을 늘려(기본의 10배) 셋이 다 견준다. 후보가 바닐라와는 같다고 나왔는데 손 몸통과 다르면 손 몸통 쪽 차이(버그 후보)이거나 정답기의 사각지대다 — 둘 다 보고서에.
- **돌연변이 카나리**: 관용구의 값 자리를 다른 칸·다른 속성으로 바꾼 후보, 인자 순서를 바꾼 후보, 반환을 뒤집은 후보를 일부러 만들어 정답기가 전부 "다름"으로 거르는지(`HarnessCanaryTest` 와 같은 원리). 하나라도 통과하면 시험 실패. 이것은 틀 전체 점검이고, 멤버마다의 약함은 위 2의 멤버별 구분력이 본다.

### 3.5 연결 파일 형식과 생성

`furnace-compat-paper/src/shimspec/links-1.21.1/<영역 번호>-<이름>.links` (영역은 `fill-areas.txt` 그대로 — 영역 PR 끼리 충돌하지 않게 파일을 나눔). 기계가 쓰고, 사람은 검토 뒤 줄을 옮기거나 지우기만 한다.

```
#furnace-links 1 1.21.1 area=9
# 기계 생성(adoptLinks). 줄: 멤버 -> 대상 검사종류 via=<갈래> proof=<O1|O2|O3|review> body=<바닐라 몸통 지문 12자리> target=<대상 몸통 지문 12자리>
class net.minecraft.core.Holder$Reference
  value()Ljava/lang/Object; -> this.get  read=any  via=G3 proof=O1 body=1a2b3c4d5e6f target=0f1e2d3c4b5a
class net.minecraft.world.entity.monster.Zombie
  isBaby()Z -> @idiom(entity-data-get, #16271d1c1b)  read=owner  via=G1 proof=O3 body=… target=…   # 칸 상수 Zombie.DATA_BABY_ID 는 바닐라 private → 지문
```

- 문법은 명세 줄(`->`)과 같고 서술자는 늘 적는다(판과 무관하지 않음을 받아들임 — 판을 올리면 다시 추론). 대상은 `C.m`(정적 다리), `this.m`(별칭), `@idiom(이름, 값…)`.
- **이름**(결정 D1, 검토 R1): 평문으로 적는 것은 Paper 서버 서명표에서 **공개·보호**인 클래스·멤버·값 이름뿐이다(shim 이 이미 같은 이름으로 내놓는 표면, 명세 파일과 같은 기준). private·패키지 멤버나 값(예: 엔티티 데이터 칸 상수 `DATA_*` 는 바닐라 private)은 `entity_data/ids-<판>.txt` 와 같은 지문 꼴 `#<SHA-256("바닐라 클래스 이름.멤버 이름") 앞 10자리>`(`ExportEntityData.fingerprint` 와 같은 계산) 로 적고, 생성 때 서명표·바닐라 jar 에서 푼다(못 풀면 멈춤). 우리 쪽 이름이 이미 있는 값(`entity_data/ids.spec` 의 `EntityDataIds` 이름)은 그 이름을 써도 된다. 지문은 값을 **선언한** 클래스로 만든다 — 이름은 같고 선언 클래스가 다른 상수(`Zombie.DATA_BABY_ID` 와 `AgeableMob.DATA_BABY_ID`)를 섞지 않도록, 생성 때 지문을 풀어 나온 선언 클래스가 몸통이 실제로 읽는 필드의 소유자와 같은지 검사한다(재검토 비차단 지적). `adoptLinks` 가 쓸 때와 빌드 검사가 읽을 때 **둘 다** "private·패키지 이름 평문 금지"를 검사한다(서명표의 접근 플래그로).
- 생성: `FullShells`(껍데기 클래스)와 `ShellMerge`(손·생성 shim 에 합치는 멤버)가 그 멤버에 던지는 몸통 대신 [소유 검사] → [인자 변환] → 대상 호출 → [반환 변환] → 반환 을 쓰고 `@NmsShellMember` 표지를 달지 않는다(그래서 연결기가 "있음"으로 본다). 리플렉션·`invokedynamic` 없음.
- 빌드 검사(멈춤): 연결 줄의 멤버가 이미 손·명세로 살아 있으면 — 그 클래스뿐 아니라 **상위 사슬·인터페이스에서 찾아져도** — "낡은 줄"(지우라고, 손 shim 바이트를 덮어쓰지 않는다), 대상 메서드가 없거나 형식이 안 맞거나 표지 검사 종류와 줄이 다르면 오류, `body=` 지문이 지금 바닐라 jar 와 다르면 "바닐라 몸통 바뀜"(판 올림 때 T-236 과 같은 신호), `target=` 지문이 지금 대상과 다르면 그 줄만 정답기 다시(CI 선택 실행).
- 표가 없는 빌드(껍데기 없음)는 연결 파일을 안 읽는다 — 지금과 같다. 배포 빌드는 `-PrequireFullShells` 라 늘 들어간다.

### 3.6 지키는 규칙

- **이식 금지**: 바닐라 몸통은 분류(모양 해시)와 값 뽑기(리터럴·정적 필드 이름)에만 쓴다. 연결 몸통의 동작은 Furnace 코드(다리·관용구 구현)다. G0 도 T-262 처럼 리터럴만.
- **Mojang 원문**: 바닐라 jar·서명표·후보 보고서(이름 들어감)는 캐시·build 에만. 커밋하는 것은 연결 파일(공개·보호 이름만 평문, 나머지는 지문 — D1·3.5)과 이름 없는 숫자 기준선뿐. G0 의 정적 필드 반환(`R`)도 필드가 private 이면 T-262 표·기준선에 같은 기준을 적용한다.
- **CraftBukkit GPL**: Craft 클래스는 **서명만** 쓴다(`getHandle()` 반환형으로 NMS ↔ Craft 클래스 짝). Craft 몸통은 읽지 않는다 — "CraftX.b 가 NMS 의 무엇을 부르나"로 짝을 찾는 길은 쓰지 않는다.
- **어댑터 경계**: 대상은 호환 계층 코드와 `furnace-api`(공개·`api.internal` 다리)뿐. 서버 클래스를 바로 부르는 연결 몸통은 만들 수 없다(`AdapterDirectionStaticTest` 가 껍데기 jar 도 보게 넓힌다).
- **소유**: 3.3. **임시 금지**: 증명 없는 줄은 채택하지 않고 던지는 몸통으로 남긴다(조용히 틀린 값을 주지 않음).
