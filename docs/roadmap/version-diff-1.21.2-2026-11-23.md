# 1.21.1 → 1.21.2 차이 지도와 버전업 시간 추정 (2026-11-23)

도미니코 제안(11-23): "Paper 1.21.1·1.21.2 코드와 바닐라 1.21.1·1.21.2 jar 를 놓고 다른 부분을 찾으면 더 빠르지 않을까" — 맞다. 이 문서는 그 일을 **기계로 하는 도구**를 만들고, 첫 홉(1.21.2)에 실제로 돌린 결과와 그걸 근거로 한 시간 추정이다. 버전업 계획(`version-upgrade-plan-2026-11-16.md`)의 **U-03("n-1 ↔ n 차이 → 이 홉의 작업 목록")을 도구로 바꾼 것**이고, 넓은 호환 설계(`broad-support-version-scaling-2026-11-20.md`)의 서명표(T-227)를 그대로 입력으로 쓴다. 두 문서와 겹치거나 어긋나는 곳은 7장.

숫자는 모두 이번에 컨테이너에서 실제로 돌린 결과다(재현 명령 9장). Mojang 이름이 든 전체 목록은 개발자 캐시에만 있고 여기에는 개수만 옮긴다.

## 1. 결론 (먼저 읽을 것)

- **컨테이너에서 전부 됐다.** 바닐라 1.21.1·1.21.2·1.21.3 서버 jar·공식 대응표 내려받기, 이름 풀기, 바닐라 데이터 생성기 실행, Paper 1.21.1·1.21.3 원문(GitHub), paper-api jar(repo.papermc.io) 모두 이 클라우드에서 돌았다. **도미니코 PC 가 필요한 부분은 차이 찾기가 아니라 홉 끝의 실서버 시험·벤치(U-08·U-09)뿐**이다(8장).
- **1.21.2 는 큰 판이다.** 바닐라 클래스 6,148 → 6,381(삭제 108, 추가 341), 메서드 서술자 변경 1,239·삭제 776·추가 1,014, 흐름이 바뀐 메서드 1,727. 패킷 232개 중 번호 바뀜 146·추가 12·삭제 3, 블록 상태 번호는 1,060개 블록 중 1,040개의 첫 번호가 밀린다. 조리법 1,276개 파일이 모두 새 형식, 아이템 1,333개 기본 컴포넌트가 모두 바뀜.
- **1.21.2 → 1.21.3 은 사실상 같은 판이다.** 클래스 1개 추가, 흐름이 바뀐 메서드 2개, 패킷·블록·아이템·레지스트리·명령 변화 0, 프로토콜 번호도 768 로 같다. 그리고 **Paper 는 1.21.2 정식 판이 없다**(1.21.1 다음이 1.21.3). → 두 판을 한 홉으로 묶자고 제안한다(결정 V1, `docs/user-todo/entries/2026-11-23-version-diff-1.21.2.md`).
- **Furnace 영향(대응표 V-06 기준):** 바닐라 대응이 표시된 Furnace 파일 1,125개 중 고칠 가능성이 큰 것(바닐라 쪽 선언이 삭제·서술자 변경) **329개**, 멤버 추가만 35, 흐름만 바뀐 후보 109, 참조만 바뀐 후보 56. 엔티티 패키지(516파일)는 대응표가 아직 없어 이 숫자에 빠져 있다 — 바닐라 쪽 엔티티 변화가 가장 크므로(선언이 바뀐 클래스 212개, 흐름이 바뀐 메서드 537) 실제 일은 더 크다.
- **shim(플러그인용 NMS 대역):** shim 이 맞춘 바닐라 멤버 11,456개 중 그대로 11,159(97.4%), 서술자 변경 64, 사라짐 126, 클래스 사라짐 9, 이름은 같은데 흐름이 바뀜 75(동작 확인 대상). 11-20 설계의 1.21.4 예측(약 180줄)과 같은 크기다.
- **시간(가정, 6장):** 1.21.1 → 1.21.3 한 홉을 스레드 4~6개 병렬로 할 때 **낙관 약 2.5일, 현실 약 5~6일**(작업 시간 기준, 스레드 합계 낙관 약 90시간·현실 약 180시간). 이 도구 덕에 U-03(차이 찾기·작업 목록) 몫은 반나절~하루에서 1시간 안쪽으로 줄었다.

## 2. 만든 도구 (재사용 — 판 두 개만 바꿔 다시 돈다)

| 도구 | 하는 일 | 출력 |
|---|---|---|
| `vanilla-extract -Pmode=body-table` (새 `BodyTable`) | 바닐라 jar(Mojang 이름) 메서드마다 **모양 해시**(명령 코드·상수·분기 구조)와 **참조 해시**(부르는 소유자·이름·서술자), `static final` 상수 값 | 캐시 `body-table.tsv.gz`(커밋 안 함) |
| `vanilla-extract -Pmode=sig-table` (기존 T-227) | 클래스·멤버 선언 | 캐시 `sig-table*.tsv.gz` |
| `vanilla-extract -Pmode=reports` (기존) | 바닐라 데이터 생성기 `--all`: 패킷·레지스트리·블록·아이템·명령 보고서와 데이터팩 파일 | 캐시 `generated/` |
| `tools/compat/version-diff.py` (새) | 위 셋 + jar 자원을 두 판 사이에서 견줘 **영역별 개수**, `--shim-table` 로 shim 영향, `--port-map` 으로 **고칠 Furnace 파일 후보**(등급 A/C/B/D), `--table paper-api` 로 Paper API 선언 차이 | 캐시 `diffs/`(전체, 커밋 안 함) + `--safe` 개수 요약 |
| `tools/compat/paper-patch-diff.py` (새) | Paper 두 판의 패치 묶음을 이름(번호 접두 무시)으로 맞춰 같음/작은 변경/큰 변경/추가/삭제·옮김 | 표 + 목록 |

- 판별 기준: 모양이 다르면 **흐름 변경 후보**(진짜 동작 변경일 가능성이 큼), 모양은 같고 참조만 다르면 **참조만 변경**(부르는 이름이 바뀐 것 — 예: 높이 아래쪽을 묻는 함수 이름이 바뀐 곳이 수십 군데 따라 바뀜). 1.21.2 → 1.21.3 에서 흐름 변경이 2개만 나와(오탐이 적다는 증거) 기준이 쓸 만함을 확인했다.
- 구조물 NBT 파일은 판이 바뀌면 파일마다 DataVersion 숫자만 올라 전부 "바뀜"으로 보인다. 이 값을 가리고 견주면 1,178개 → **78개**만 진짜로 바뀐다.
- 법적 경계: 서명표(T-227)는 "몸통을 읽지 않는다"는 약속을 그대로 둔다. 본문 지문표는 몸통을 읽지만 **해시만 남기고 글자는 어디에도 저장하지 않으며 캐시에만** 둔다. 커밋되는 것은 개수뿐이다. 이 선을 그어도 되는지는 결정 V3 로 확인받는다.
- 시험: `BodyTableTest` 3개(이름만 바뀌면 모양 해시 같음·명령이 늘면 다름, 람다 번호가 달라도 묶음 같음, 같은 입력 같은 바이트). `:vanilla-extract:test` 47개 통과(11-23).

### 4.2 프로토콜
- 번호 146개는 V-03(`PacketIds` 를 번호표에서 생성)로 **자동**이다. 데이터 뽑기의 `protocol-ids` 도구는 1.21.2 에서 고치지 않고 돈다(4.4).
