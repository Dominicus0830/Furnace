# 동적 region(Folia 방식) 설계

## 목표

- 한 region 안의 모든 동작(블록 갱신·예약 틱·플레이어·청크)은 한 스레드에서 바닐라 순서 그대로 → 결과가 바닐라와 같다.
- 서로 떨어진 플레이어 무리는 다른 region 이 되어 작업 스레드 풀에서 병렬로 틱한다.
- 가까워지면 합치고(merge), 멀어지면 나눈다(split). 고정 격자처럼 경계에서 결과가 달라지는 일이 없다.

## 구역(section)과 region

- 구역 = `2^shift × 2^shift` 청크(기본 shift 4 → 16×16 청크). 키 `(cx >> shift, cz >> shift)`.
- 구역은 "있는 청크"(로드됐거나 로드 중이거나 플레이어가 원하는 청크) 수를 센다. 0 이면 죽은 구역.
- region = 구역들의 집합. **불변식: 서로 다른 region 의 구역은 체비셰프 거리로 `merge-radius`(기본 1) 구역보다 멀다.**
  그래서 다른 region 의 청크끼리는 최소 한 구역(16 청크) 떨어져 있고, 블록 갱신·플레이어 시야가 region 을 넘지 않는다.
- 청크 내용은 월드 공용 맵(`ConcurrentHashMap<long, ChunkColumn>`)에 있고, **그 청크 구역을 가진 region 스레드만** 만진다.

## 구역 추가 → 합치기

`claim(청크)` (regionizer 잠금 안):
1. 구역이 있으면 개수 +1, 주인 region 반환.
2. 없으면 반경 안 이웃 region 들을 찾는다.
   - 요청한 region(지금 틱 중인 자기 자신)이 있으면 그 region 이 구역을 갖는다. 아니면 이웃 중 쉬는 region, 아니면 새 region.
   - 주인이 아닌 이웃은 "합칠 대상"으로 서로 기록한다. 실제 합치기는 **틱 사이**에만 한다(틱 도중 자료 구조를 바꾸지 않는다).
3. 틱이 끝날 때(잠금 안) 합칠 대상이 쉬고 있으면 흡수하고, 틱 중이면 자기가 양보한다(다음 틱을 잡지 않고 상대 틱 끝에 흡수됨).

흡수 때 옮기는 것: 구역 주인, 작업 큐(청크 키 붙은 작업), 지연 작업(남은 틱 유지), 플레이어, 있는 청크·저장 대기·퇴출 유예,
블록 레벨 자료(예약 틱 — 각 region 의 지역 틱 시계 차이만큼 보정, 변경 방송 대기, 블록 이벤트, ack 대기).

## 구역 제거 → 나누기

- 청크가 퇴출되면 구역 개수 −1. 틱 끝에 죽은 구역 비율이 문턱(10%)을 넘거나 일정 틱마다 다시 계산:
  죽은 구역을 지우고, 살아 있는 구역을 반경 인접으로 묶어 연결 성분이 둘 이상이면 나눈다(가장 큰 성분은 원래 region).
- 나눌 때 위 자료를 각자 구역(위치)에 따라 나눈다. 구역도 플레이어도 없게 된 region 은 없앤다.

## 작업 보내기

- 모든 월드 작업은 청크 키를 단다: `world.runAt(청크, region -> …)`. 큐에 넣은 뒤 그 region 이 이미 죽었으면(합쳐짐·나뉨)
  넣은 쪽이 죽은 region 의 큐를 비워 지금 주인에게 다시 보낸다 → 합치기·나누기와 경합해도 작업이 사라지지 않는다.
- 플러그인 `scheduler.region(RegionPos)` 의 RegionPos 는 **청크 좌표**다. 그 청크를 가진 region 에서 돈다.

## 틱 스케줄

- 작업 스레드 `region-threads` 개(기본 코어 수). region 마다 다음 틱 시각(50ms 간격, 너무 밀리면 재동기)을 갖고,
  잠금 아래 우선순위 큐에서 가장 이른 region 을 꺼내 돈다. 한 region 은 동시에 한 스레드만.
- 시간·날씨·전역 작업은 지금처럼 전역 스레드.

## 설정

- `region-threads`(작업 스레드 수), `region-section-shift`(기본 4), `region-merge-radius`(기본 1).
- 고정 격자 `region-size` 는 없앤다.
