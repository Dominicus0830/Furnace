# T-235 차분 시험 대상 — 값 클래스(설계 5.5 의 1순위: "전부").
# 줄 꼴:
#   class <Mojang 이름 클래스> [iterations=N] [budget=초] 바닐라와 shim 이 함께 가진 공개 멤버를 전부 같은 입력으로 견준다(멤버마다 입력 N개, 기본 20000)
#     budget=초: 바닐라 쪽이 비싼 느린 클래스만(멤버마다 시간 예산 — 경계값 입력 400개는 다 돌고, 그 뒤 난수 입력에서 예산을 넘으면 멈추고 보고서 머리에 적는다).
#                 없는 클래스는 멈추지 않는다(300초 감시를 넘기면 실패)
#     exclude <열쇠>  # <이유>                 열쇠 = 필드 이름 또는 이름(인자 형식,…) (보고서의 열쇠 그대로). 이유 없는 exclude 는 오류
#     paper <열쇠> [when=<입력 조건>] vanilla=<예외> shim=<예외> [vanilla=… shim=…]…  # <근거>
#                                             바닐라와 다르지만 Paper 와 같게 둔 차이(호환 원칙). 적은 예외 쌍(바닐라가 이것, shim 이 저것)인
#                                             입력만 허용하고, 그 밖의 차이는 같은 멤버여도 다름(실패). 허용한 차이가 한 번도 안 나오면 낡은 줄이라 실패.
#                                             근거 입력은 고정 훑기(DiffRunner.SWEEP)에 넣어 입력 수와 무관하게 늘 나오게 한다
#                                             when= 은 그 차이를 낳는 Paper 패치가 실제로 걸리는 입력으로 더 좁힌다(DiffRunner.CONDITIONS —
#                                             nbt-array-limit: 바이트·정수 배열 길이 1<<24 이상을 다른 오류보다 먼저 만나는 읽기 입력, NbtKit 이 구조만 훑어 판정)
# 여기 적힌 클래스는 관문이다: 차이가 하나라도 있거나, 증명 못 한 멤버(형식 꾸러미에 없는 형식)가 exclude 없이 남으면 실패한다.
# 바닐라에만 있는 멤버(연결 안 됨)는 서명 관문 몫이라 보고만 한다.
# 연결 명세(src/shimspec/*.spec)의 pure·read=any 줄도 자동으로 시도한다: 다름·오류는 실패, 증명 없음(받는 쪽 형식이 꾸러미에 없음)만 보고.
